# Day01 - MCP 概述与核心概念

> 认识 MCP 是什么、解决什么问题，掌握 Host / Client / Server 三大角色以及它与普通 API、Function Calling、Agent 的区别。齐此勘查，即可看懂一个 MCP 会话的骨架。

---

## 1. MCP 是什么

**MCP（Model Context Protocol，模型上下文协议）** 是 Anthropic 于 2024 年 11 月开源并推行的**开放协议**，由官方主导做成了开放标准（包括 Google、OpenAI 等均已纳入支持）。

一句话概括：
> **MCP 是一套让 AI 应用（Host）通过标准化的 Server，安全、统一地连接外部工具、数据源与服务的协议。**

它回答了 AI 落地中最现实的问题：**模型只会"想"，不会"做"** —— 它要读写文件、查数据库、调外部 API、发消息……这些"动作能力"如何以一种统一、可控、可复用的方式暴露给模型？

在没有 MCP 之前，每接入一个新工具就要为它定制一套集成——N 个工具 = N 套代码。MCP 把这个过程**标准化**了：Server 负责把某个外部能力包一层标准接口，任何 MCP 客户端都能即插即用。

---

## 2. 三大核心角色

一个 MCP 交互中，最小需要三方角色：

| 角色 | 英文 | 作用 | 类比 |
|------|------|------|------|
| **宿主** | Host | 面向用户的应用程序，负责加载 Client、对模型上下文做编排 | "前台/指挥部" |
| **客户端** | Client | 宿主体内与 Server 建立 1:1 连接的中介，负责发协议消息 | "对接专员" |
| **服务端** | Server | 暴露能力（工具/资源/提示词），封装某个外部系统 | "能力提供方" |

```
┌─────────── 宿 主 (Host) ───────────┐
│   用户交互  +  LLM 应用逻辑         │
│   ┌───────────────────────┐        │
│   │ Client 客户端          │◄──┼──┐ │    每个 Client 对应一个 Server
│   │ Client 客户端          │  │  │ │
│   └───────────┬───────────┘  │  │ │
└───────────────┼──────────────┼──┼─┘
                ▼              │  │
        ┌──────────────┐       │  │
        │ MCP Server 1 │       │  │  （stdio / HTTP 传输）
        └──────┬───────┘       │  │
               └───────────────┼──┘
```

> 一句话记忆：**Client 多对一关系是反的** —— 一个 Host 里通常有**多个 Client**，每个 Client 连**一个** Server。

## 3. MCP 与普通 API、Function Calling、Agent 的区别

| 方案 | 面向谁 | 特点 |
|------|--------|------|
| **普通 API** | 人/程序直接调 | 无标准，每个服务一套接口，模型不知道"何时调" |
| **Function Calling** | 单个 LLM | 模型"知道要调"，但工具定义与模型强绑定，难以复用 |
| **Agent** | 应用架构 | 让模型自主规划并调用工具，但工具接入仍各自为政 |
| **MCP** | 整个 AI 应用生态 | 标准化工具/资源接入层，Server 与 Host 解耦，可复用 ★ |

关键洞察：**MCP 不是取代 Agent，而是为 Agent 提供统一的外部能力接入层。**

---

## 4. 一个典型会话长什么样

一个 MCP 会话大致如下：

1. **Host 启动** → 为每个要用的 Server 创建 Client
2. **Client 向 Server 发 `initialize`** → 协商协议版本与能力
3. **Client 发 `notifications/initialized`** → 会话就绪
4. **能力发现** → Client 请求 `tools/list`、`resources/list`、`prompts/list`
5. **实际工作** → LLM 需要某个能力时，Client 调用工具 / 读资源 / 取提示模板
6. **会话结束** → 关闭连接

这 6 步贯穿后续所有章节。

---

## 5. 本节小结

- MCP 是连接 AI 应用与外部世界的**开放标准化协议**
- 三角色：**Host（宿主）、Client（客户端）、Server（服务端）**
- 三大能力原语：**工具（Tools）、资源（Resources）、提示词（Prompts）**（Day03 详讲）
- 底层基于 **JSON-RPC 2.0**，传输有 **stdio / HTTP**（Day02 详讲）
- MCP 是 Agent 的外部能力接入层，二者互补不冲突
