# Day09 - 综合实战与生产要点

> 收官实战：从零搭一个「业务 Server + Agent 客户端」的完整案例，并复盘生产环境必须注意的安全、传输、认证与上线要点。

---

## 1. 完整案例：一个「商店」MCP 能力

设定一个业务场景「在线商店」，让 Agent 能查到商品库存、下订单并校验参数。用三层结构呈现：

```
┌──────────────────────────────────────────────┐
│ Agent 客户端 (client_agent.py)                 │
│   收集工具 → 决策 → call_tool → 回填 → 回复    │
├──────────────────────────────────────────────┤
│ MCP Server (server_shop.py)                   │
│   工具: list_items / order_item / divide?     │
│   资源: 商品清单;   提示词: 下单说明            │
├──────────────────────────────────────────────┤
│ 业务数据（内存 mock）                          │
└──────────────────────────────────────────────┘
```

### Server 侧（`server_shop.py`）
- **工具**：`list_items()`（列商品）、`order_item(item, qty)`（下单，带参数校验）
- **资源**：`inventory://items`（商品清单）
- **提示词**：`place_order_guide`（下单流程说明）

### Client 侧（`client_agent.py`）
- 连接 Server → 发现工具 → 规则决策 → 调用 → 输出回复
- 展示了「工具→执行」的完整闭环

---

## 2. 生产要点

### 安全与最小权限
- **只暴露必要能力**：Server 尽量只暴露该场景需要的工具，减少攻击面
- **工具校验参数**：`order_item` 中标定参数范围，异常即拒绝
- **不把密钥写进代码**：环境变量 / 配置注入（前面 Day08 提到 `env`）
- **敏感资源可控**：资源只读，写入类一律走工具

### 传输选择
- 本地单机 → **stdio**（简单、无需暴露端口）
- 远程 / 多客户端 → **Streamable HTTP**（部署为独立服务）

### 认证（远程场景）
- HTTP 传输常配合 **OAuth 2.0** 保护 Server
- Client 带上 access token，Server 校验后再响应

### 性能与超时
- 工具内长耗时操作设超时；返回给模型的结果尽量精简
- 大批量数据优先用资源/一次性读取，避免每轮重复调用

## 3. 上线自检清单

- [ ] 工具只暴露必要能力，参数已校验
- [ ] 无敏感信息硬编码，敏感项走环境变量/secret
- [ ] 资源保持只读；写入一律走工具
- [ ] 传输选择合理（本地 stdio / 远程 HTTP+OAuth）
- [ ] 已用 `mcp dev` 调试过 Server，工具都能正常调用返回
- [ ] 在真实客户端（Claude Desktop / Cline）接入验证通过
- [ ] 超时与错误处理到位，模型拿不到结果时不挂死
- [ ] 日志可用（logging/message）便于排查
