## 二、理论知识

### 2.1 多工具的威力与挑战

能力越多越有用，但也更难：
- 模型要**挑对工具**。
- 参数**可能串场**。
- 工具间**有依赖/冲突**。

### 2.2 工具编排（选择与顺序）

靠每个工具的 `description` 告诉模型「何时用」；模型在 Thought 里决定调用链。示例任务「算一组股票市值」：

```
Thought: 需要查价格, 再乘股数
Action: get_price(symbol=...)
Observation: ...
Action: multiply(a=price, b=shares)
```

### 2.3 工具冲突与优先级

- 多个工具都能满足时，用**规则/优先级**仲裁。
- 写一个 `prioritize(tools_available)` 或让模型显式声明理由。
- 敏感性操作要**白名单 + 人审**（如支付）。

### 2.4 混合工具 ReAct 循环

统一循环只要面对「一组工具 + 一个 llm」，逻辑不变：

```python
tools = reg.openai_tools()
while steps < max_steps:
    resp = llm.chat(messages, tools=tools)
    ...执行每个 tool_calls 并回填...
```

工具数量不影响循环骨架，只影响调度质量。

### 2.5 一个大而全的 Decider（Mock）

演示场景里，用一个大 decider 根据任务关键词分派不同工具链，模拟模型「会选择」。

### 2.6 从工具结果到最终回答

拿到全部 Observation 后让模型**综合**成自然语言回复，而非复述 JSON。

## 三、核心概念解析

### 3.1 工具越多越要清晰描述

工具描述写得越「何时用、怎么用」清晰，模型选中率越高。这是多工具 Agent 的第一杠杆。

### 3.2 涌现行为 vs 失控

多工具下模型可能产生合理组合（涌现），也可能乱调（失控）。要：清晰 schema + 次数上限 + 人工审核高风险操作。

---

## 四、关键知识点总结

- **多工具 = 更大能力 + 更高调度要求**。
- **循环骨架与工具数无关**，同样 while。
- **description 决定选中率**。
- **冲突靠优先级/规则/白名单**。
- **最终回答要综合 Observation 转自然语言**。
