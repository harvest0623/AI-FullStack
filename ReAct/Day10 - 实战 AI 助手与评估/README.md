## 二、理论知识

### 2.1 组装一个完整 Agent

把所有零件拧在一起：

```
System prompt + 工具注册表 + LLM
   ↓
react loop(while): 生成 -> 执行工具 -> 回填 Observation
   ↓ 直到 Final Answer 或 max_steps
返回 (answer, trace, stats)
```

### 2.2 切面：日志与成本统计

记录每次 Agent 运行的元信息，便于审计与优化：

- 轮次 `steps`、调用的工具列表
- 估算 token 与 cost
- 是否成功、失败原因

### 2.3 Agent 类的设计

```python
class Agent:
    def __init__(self, tools, llm, system="", max_steps=8): ...
    def run(self, user_text) -> Result: ...
```

`run` 内部跑循环，返回带 `answer/trace/stats` 的结果对象。

### 2.4 评估指标：正确率 / 轮次 / 失败率

- **正确率**：参考答案是否命中。
- **平均轮次**：任务多省时。
- **失败率 / 超步率**：护栏触发的比例。

### 2.5 编写评估集（Eval Set）

```python
EVALS = [
    {"input": "耳机多少钱", "expect_contains": ["199"]},
    {"input": "请算 3*4 再平方", "expect_contains": ["144"]},
]
```

对每条跑 Agent，检查最终回答是否含期望片段。

### 2.6 从评估到迭代

评估分数低就：改 prompt、加工具描述、调护栏、换 tool schema。**评估集是迭代的标尺**。

---

## 三、核心概念解析

### 3.1 可观测性是工程护栏

日志 + 统计让「黑盒 Agent」变可审计，出问题时能回放轨迹定位。

### 3.2 评估驱动改进

没有指标就没有改进依据。正确率/轮次/失败率三个数字比「感觉好用」靠谱得多。

---

## 四、关键知识点总结

- **Agent 类**封装 ReAct 循环。
- **Result 含 answer/trace/stats**。
- **日志 + 成本 + 轮次** 可观测。
- **Eval Set + 正确率/轮次/失败率** 评估。
- **评估 → 迭代** 是提升闭环。
