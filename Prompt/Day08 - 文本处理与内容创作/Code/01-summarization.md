# 摘要模板合集

> 本文件包含 4 个摘要 Prompt 模板：单文档摘要 / 多文档摘要 / 分块摘要（Map-Reduce）/ 要点摘要。所有模板均围绕客服场景设计，可拓展到任意文本摘要需求。

---

## 模板 1：单文档摘要 - 客服对话摘要

### 模板说明
- 用途：将一段客服对话压缩为简洁摘要
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{conversation}}`、`{{max_words}}`、`{{focus}}`

### 完整模板

```text
你是 SmartCS 智能客服系统的对话摘要引擎。请阅读以下客服对话，生成结构化摘要。

【对话内容】
{{conversation}}

【摘要要求】
1. 字数限制：不超过 {{max_words}} 字
2. 重点聚焦：{{focus}}
3. 必须包含：
   - 用户诉求（一句话）
   - 关键信息（订单号 / 金额 / 日期，若有）
   - 处理结果（已解决 / 待跟进 / 转人工）
   - 情感倾向（正面 / 中性 / 负面）

【输出格式】
{
  "summary": "摘要正文（≤{{max_words}} 字）",
  "user_demand": "用户诉求",
  "key_info": {"order_id": "...", "amount": "...", "date": "..."},
  "status": "resolved | pending | escalated",
  "sentiment": "positive | neutral | negative"
}

约束：
1. 不得编造对话中未出现的信息
2. 若某字段在对话中不存在，填 null
3. 只输出 JSON，不输出任何额外文本
```

### 使用示例

#### 输入
```text
你是 SmartCS 智能客服系统的对话摘要引擎。请阅读以下客服对话，生成结构化摘要。

【对话内容】
用户：我上周三下的订单 20251031-001 还没到，都过了承诺的 3 天了。
客服：您好，抱歉让您久等了。我帮您查一下订单 20251031-001 的物流。
用户：麻烦快点，这单是 299 元的耳机，我等着送人。
客服：查到了，您的订单当前在转运中，预计明天送达。我会加急备注，给您造成不便非常抱歉。
用户：那行吧，明天到就行。

【摘要要求】
1. 字数限制：不超过 80 字
2. 重点聚焦：物流延迟处理
3. 必须包含：用户诉求 / 关键信息 / 处理结果 / 情感倾向

（输出格式同上）
```

#### 预期输出
```json
{
  "summary": "用户投诉订单 20251031-001（299 元耳机）物流延迟超 3 天。客服查询后确认在转运中，承诺次日送达并加急。用户接受。",
  "user_demand": "查询物流延迟订单并要求尽快送达",
  "key_info": {"order_id": "20251031-001", "amount": "299 元", "date": "上周三"},
  "status": "resolved",
  "sentiment": "neutral"
}
```

### 调优建议
- 温度：0.3（摘要需稳定但允许少量措辞变化）
- 若对话极短，可将 max_words 降到 50
- 若需保留原文关键句，追加"在 summary 中保留 1 句原文引用"

## 模板 2：多文档摘要 - 多个用户反馈综合摘要

### 模板说明
- 用途：将多条用户反馈综合为一份摘要，避免简单罗列
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{feedback_list}}`、`{{focus}}`、`{{output_style}}`

### 完整模板

```text
你是用户反馈分析专家。请综合以下多条用户反馈，生成一份综合摘要。

【反馈列表】
{{feedback_list}}

【摘要要求】
1. 重点：{{focus}}
2. 风格：{{output_style}}
3. 必须"综合"而非"罗列"——按主题归类，提炼共性
4. 字数：200-400 字

【输出格式】
{
  "overall_sentiment": "positive | neutral | negative",
  "main_themes": [
    {"theme": "主题名", "frequency": "高/中/低", "summary": "该主题综合描述"}
  ],
  "top_issues": ["问题1", "问题2", "问题3"],
  "improvement_suggestions": ["建议1", "建议2"]
}

约束：
1. 频率按反馈中出现次数判断（>50% 高，20-50% 中，<20% 低）
2. 不得编造未在反馈中出现的问题
3. 只输出 JSON
```

### 使用示例

#### 输入
```text
你是用户反馈分析专家。请综合以下多条用户反馈，生成一份综合摘要。

【反馈列表】
1. 物流太慢了，下单 5 天才到，承诺 3 天。
2. 包装很差，收到时盒子都扁了，耳机还好没坏。
3. 客服回复很慢，等了半小时才有人理。
4. 产品本身不错，音质清晰，但物流真的要改进。
5. 物流是顺丰吗？感觉比上次慢很多。
6. 客服态度还行，就是处理速度太慢。
7. 包装可以再加一层气泡膜，预防暴力分拣。
8. 物流延迟，但客服帮忙加急了，最后还是收到了。

【摘要要求】
1. 重点：物流 / 包装 / 客服三类问题
2. 风格：客观、数据导向
3. 必须"综合"而非"罗列"
4. 字数：200-400 字

（输出格式同上）
```

#### 预期输出
```json
{
  "overall_sentiment": "neutral",
  "main_themes": [
    {
      "theme": "物流延迟",
      "frequency": "高",
      "summary": "多条反馈反映物流速度未达承诺的 3 天，部分用户等待 5 天才收到，是本期最突出的问题。"
    },
    {
      "theme": "客服响应慢",
      "frequency": "中",
      "summary": "用户反映客服回复等待时间过长（半小时级），但态度总体认可，部分客服能主动加急处理。"
    },
    {
      "theme": "包装不足",
      "frequency": "中",
      "summary": "包装被反映偏薄，到货时盒子变形，建议增加气泡膜等缓冲材料。"
    }
  ],
  "top_issues": [
    "物流延迟超过承诺时效",
    "客服响应速度慢",
    "包装缓冲不足"
  ],
  "improvement_suggestions": [
    "与物流方重新对齐时效承诺，或将承诺期从 3 天调整为 5 天",
    "增加客服排班，设置首响 SLA（如 5 分钟内）",
    "包装标准升级，强制增加气泡膜层"
  ]
}
```

### 调优建议
- 温度：0.3
- 反馈条数较多（>20）时，建议先用分类 Prompt 分组，再分别综合
- 若需量化，追加"统计每个主题的反馈条数"

## 模板 3：分块摘要（Map-Reduce） - 长篇退换货政策摘要

### 模板说明
- 用途：对超长文本（超出上下文窗口或质量下降）采用 Map-Reduce 分块摘要
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{chunk}}`（Map 阶段）、`{{chunk_summaries}}`（Reduce 阶段）、`{{final_length}}`

### 完整模板

本模板分两阶段使用：

#### 阶段一：Map（对每块独立摘要）

```text
你是文档摘要助手。请对以下文本块生成块摘要。

【文本块编号】{{chunk_id}}
【文本块内容】
{{chunk}}

【块摘要要求】
1. 字数：不超过 150 字
2. 保留：
   - 政策条款编号（如"第 3 条"）
   - 关键数字（天数 / 金额 / 比例）
   - 适用条件
3. 不保留：举例、铺垫、重复说明
4. 输出格式：{"chunk_id": "...", "summary": "..."}

约束：只输出 JSON，不解释。
```

#### 阶段二：Reduce（合并块摘要）

```text
你是文档摘要助手。请将以下多份块摘要合并为一份最终摘要。

【块摘要列表】
{{chunk_summaries}}

【最终摘要要求】
1. 总字数：约 {{final_length}} 字
2. 必须做到：
   - 去重：相同条款不重复出现
   - 连贯：按政策逻辑顺序组织（适用范围 → 退换货条件 → 流程 → 时效 → 责任）
   - 风格统一：正式、客观
3. 必须保留所有关键数字（天数 / 金额 / 比例）
4. 不得引入块摘要中没有的信息

【输出格式】
{
  "title": "退换货政策摘要",
  "applicable_scope": "适用范围",
  "key_terms": [
    {"term": "条款名", "detail": "条款内容"}
  ],
  "process_summary": "流程简述",
  "important_numbers": ["7 天无理由", "15 天质量问题的"]
}
```

### 使用示例

#### 输入（Map 阶段，对第 1 块）
```text
你是文档摘要助手。请对以下文本块生成块摘要。

【文本块编号】chunk_1
【文本块内容】
第一章 适用范围
第 1 条 本政策适用于在本平台购买的所有实物商品，但不包括以下几类：
（1）定制类商品（已开始生产的）；
（2）鲜活易腐商品（生鲜、鲜花）；
（3）数字内容（充值码、会员服务已激活）；
（4）已拆封的个人卫生用品。
第 2 条 企业用户（B 端）的退换货适用单独协议，本政策不适用。
第 3 条 跨境购商品适用跨境专门政策，7 天无理由不适用。

【块摘要要求】
1. 字数：不超过 150 字
2. 保留条款编号、关键数字、适用条件
3. 输出 JSON
```

#### 预期输出（Map 阶段）
```json
{
  "chunk_id": "chunk_1",
  "summary": "第1-3条规定适用范围：本政策适用于平台实物商品，排除定制类、生鲜、数字内容、已拆封卫生用品；B 端企业用户适用单独协议；跨境购不适用 7 天无理由。"
}
```

#### 输入（Reduce 阶段）
```text
你是文档摘要助手。请将以下多份块摘要合并为一份最终摘要。

【块摘要列表】
[
  {"chunk_id": "chunk_1", "summary": "第1-3条规定适用范围..."},
  {"chunk_id": "chunk_2", "summary": "第4-6条规定退换货条件：7 天无理由、15 天质量问题..."},
  {"chunk_id": "chunk_3", "summary": "第7-10条规定退换货流程：申请 → 审核 → 寄回 → 验收 → 退款..."},
  {"chunk_id": "chunk_4", "summary": "第11-13条规定时效与责任：退款 3 工作日、运费承担规则..."}
]

【最终摘要要求】
1. 总字数：约 300 字
2. 去重、连贯、风格统一
3. 保留所有关键数字

（输出格式同上）
```

#### 预期输出（Reduce 阶段）
```json
{
  "title": "退换货政策摘要",
  "applicable_scope": "适用于平台实物商品；不适用定制类、生鲜、数字内容、已拆封卫生用品、B 端企业用户、跨境购（7 天无理由不适用）。",
  "key_terms": [
    {"term": "7 天无理由", "detail": "自签收起 7 天内可无理由退货，商品需保持原状"},
    {"term": "15 天质量问题", "detail": "自签收起 15 天内出现质量问题可退换，运费由平台承担"},
    {"term": "退款时效", "detail": "验收通过后 3 个工作日内退款到原支付账户"},
    {"term": "运费承担", "detail": "无理由退货运费用户承担；质量问题运费平台承担"}
  ],
  "process_summary": "申请退换货 → 客服审核 → 寄回商品 → 仓库验收 → 退款 / 换货发出。",
  "important_numbers": ["7 天无理由", "15 天质量问题", "3 工作日退款"]
}
```

### 调优建议
- 温度：0.3
- 分块大小建议 1500-2500 字，块太大降质、块太小丢失上下文
- 若块摘要仍有重复，可在 Reduce 阶段追加"识别并合并重复条款"
- 工程实现：用 Python 切分文本，循环调用 LLM 完成 Map，最后一次性 Reduce

## 模板 4：要点摘要 - 提取关键信息列表

### 模板说明
- 用途：从文本中提取关键要点，以列表形式输出
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{text}}`、`{{point_count}}`、`{{point_focus}}`

### 完整模板

```text
你是信息提取专家。请从以下文本中提取关键要点。

【文本】
{{text}}

【提取要求】
1. 提取 {{point_count}} 个要点
2. 聚焦维度：{{point_focus}}
3. 每个要点 ≤ 30 字
4. 按重要性从高到低排序
5. 要点之间不重复

【输出格式】
{
  "points": [
    {"rank": 1, "point": "要点内容", "evidence": "原文依据（≤20 字）"}
  ]
}

约束：
1. evidence 必须是原文中的原句或关键词
2. 不得编造文本中没有的要点
3. 只输出 JSON
```

### 使用示例

#### 输入
```text
你是信息提取专家。请从以下文本中提取关键要点。

【文本】
2025 年 Q4 客服运营月报：本月共接入咨询 12,450 单，环比上升 8.3%。其中订单查询类占 42%，退换货类占 23%，物流咨询占 18%。平均首响时长 1 分 23 秒，环比缩短 12 秒。一次性解决率 78%，环比提升 3 个百分点。客户满意度 4.6/5.0。本月投诉 156 单，主要集中在物流延迟（68 单）和包装破损（42 单）。已推动物流方升级分拣流程，包装增加气泡膜。

【提取要求】
1. 提取 5 个要点
2. 聚焦维度：关键数据 + 问题与改进
3. 每个要点 ≤ 30 字
4. 按重要性排序

（输出格式同上）
```

#### 预期输出
```json
{
  "points": [
    {"rank": 1, "point": "Q4 咨询量 12,450 单，环比上升 8.3%", "evidence": "本月共接入咨询 12,450 单，环比上升 8.3%"},
    {"rank": 2, "point": "一次性解决率 78%，环比提升 3 个百分点", "evidence": "一次性解决率 78%，环比提升 3 个百分点"},
    {"rank": 3, "point": "首响时长 1 分 23 秒，环比缩短 12 秒", "evidence": "平均首响时长 1 分 23 秒，环比缩短 12 秒"},
    {"rank": 4, "point": "投诉 156 单，物流延迟 68 单为主因", "evidence": "本月投诉 156 单，主要集中在物流延迟（68 单）"},
    {"rank": 5, "point": "已升级分拣流程并增加气泡膜包装", "evidence": "已推动物流方升级分拣流程，包装增加气泡膜"}
  ]
}
```

### 调优建议
- 温度：0.2
- evidence 字段可有效降低幻觉，便于人工核对
- 若要点之间易重复，追加"每个要点必须包含独特信息"
