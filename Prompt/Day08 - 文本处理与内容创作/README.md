# Day08 - 文本处理与内容创作

> 文本处理和内容创作是 LLM 最广泛的应用场景，从数据处理到营销文案全覆盖。本章系统讲解摘要、分类、抽取、翻译、改写、创作、风格迁移、格式转换、数据清洗、问答系统等十大类任务的 Prompt 设计，所有模板均可直接用于主流 LLM。

---

## 本章简介

如果说 Day07 的代码生成让 LLM 成为了"工程师的搭档"，那么 Day08 的文本处理与内容创作则让 LLM 化身为"数据分析师 + 文案策划 + 翻译 + 编辑"的复合型助手。在真实业务中，文本类任务的体量远超代码——电商平台每天产生数万条客服对话、商品评价、用户反馈，靠人力逐条处理既慢又贵，而结构良好的 Prompt 可以让 LLM 稳定完成摘要、分类、抽取、翻译、改写、创作等任务。

本章延续 SmartCS 智能客服助手场景：客服对话摘要、用户反馈情感分类、订单实体抽取、退换货政策翻译、客服回复润色、营销文案与周报生成等模板覆盖了客服系统的全链路文本需求；同时所有模板可拓展到任意文本处理与内容创作场景。本章最后给出 RAG 问答系统的 Prompt 预览，为 Day09 的 Agent 学习埋下伏笔。

## 理论知识讲解

### 1. 文本摘要（Summarization）

文本摘要是 LLM 最经典的任务之一。根据输入文档数量与长度，分为四种模式：

| 模式 | 输入 | 适用场景 | Prompt 要点 |
|------|------|---------|------------|
| 单文档摘要 | 一篇文章 / 一段对话 | 新闻摘要、对话摘要 | 指定长度 / 重点 / 视角 |
| 多文档摘要 | 多个来源文本 | 综合多用户反馈 | 强调"综合"，避免罗列 |
| 分块摘要（Map-Reduce） | 超长文本 | 政策文档、长报告 | 先分块摘要，再合并 |
| 要点摘要 | 任意文本 | 提取关键信息列表 | 指定要点条数与格式 |

**摘要质量控制维度**：
- 字数 / 要点数：硬性约束
- 风格：正式 / 口语 / 商务
- 读者画像：管理层 / 一线客服 / 用户
- 是否包含原文引用

**摘要 Prompt 要点**：
- 指定长度（"不超过 100 字"）
- 指定重点（"聚焦退换货原因"）
- 指定视角（"从客服视角"）
- 是否引用原文（"保留关键数字"）

**分块摘要 Map-Reduce 流程**：

```text
超长文本
    │
    ▼
[分块] 按字数 / 段落切分为 N 块
    │
    ▼
[Map]  对每块独立摘要 ──→ N 份块摘要
    │
    ▼
[Reduce] 合并 N 份块摘要 ──→ 综合摘要
    │
    ▼
[润色] 去重 + 连贯 + 风格统一 ──→ 最终摘要
```

### 2. 文本分类（Classification）

文本分类是结构化文本的核心手段。常见子任务：

| 子任务 | 类别 | 应用 |
|--------|------|------|
| 情感分类 | 正面 / 负面 / 中性 | 评价分析、舆情监控 |
| 主题分类 | 给定主题列表 | 内容路由、工单分派 |
| 意图分类 | 客服意图 | 智能客服路由 |

**分类 Prompt 要点**：
- 给定类别列表（封闭集合）
- Few-Shot 示例（每类至少 1 个）
- 置信度输出（便于人工复核低置信样本）
- 处理边界（"其他"类、多意图情况）

模板骨架：

```text
将以下文本分类到给定类别之一。

类别：
- positive：正面情感
- negative：负面情感
- neutral：中性

示例：
输入：质量很好，物流也快
输出：{"label": "positive", "confidence": 0.95}

输入：包装破损，但客服处理很快
输出：{"label": "neutral", "confidence": 0.7, "reason": "正负情感并存"}

输入：{{text}}
输出 JSON：{"label": "...", "confidence": 0.0-1.0, "reason": "..."}
```

### 3. 信息抽取（Extraction）

信息抽取把非结构化文本转为结构化数据。三类子任务：

| 子任务 | 抽取内容 | 示例 |
|--------|---------|------|
| 实体抽取 | 人名 / 地名 / 组织 / 产品 / 金额 / 日期 | "张三买了 299 元耳机" → {person, money, product} |
| 关系抽取 | 实体间关系 | "张三 → 购买 → 耳机" |
| 事件抽取 | 时间 + 地点 + 人物 + 事件 | "10月1日北京张三退货" |

**抽取 Prompt 要点**：
- Schema 定义（明确字段名、类型、是否必填）
- JSON 输出（便于下游解析）
- 置信度（每个抽取值附带）
- 多值处理（一个字段可能有多个值，用数组）

### 4. 文本翻译（Translation）

LLM 翻译质量已接近专业译员，关键是控制一致性与风格。

| 子任务 | 说明 |
|------|------|
| 多语言翻译 | 中英 / 中日 / 中韩等 |
| 风格化翻译 | 正式 / 口语 / 商务 / 文学 |
| 术语表翻译 | 提供领域术语表保证一致性 |

**翻译 Prompt 要点**：
- 源语言 / 目标语言（明确指定）
- 风格（正式 / 口语）
- 术语表（key-value 列表）
- 上下文（前后文、领域）

### 5. 文本改写（Rewriting）

改写不改变原意，只调整表达。四类子任务：

| 子任务 | 目标 | 典型场景 |
|--------|------|---------|
| 润色 | 提升表达质量 | 客服回复、文章打磨 |
| 简化 | 降低阅读难度 | 政策转用户语言 |
| 扩写 | 增加细节深度 | 短文扩展为长文 |
| 续写 | 按风格方向继续 | 故事 / 文章续写 |

**改写 Prompt 要点**：
- 保持原意（明确约束）
- 指定变化方向（更专业 / 更通俗 / 更长 / 更短）
- 风格约束（语气、字数）

### 6. 内容创作（Content Creation）

内容创作是 LLM 最具创造力的应用。常见类型：

| 类型 | 子任务 | 关键要素 |
|------|--------|---------|
| 文章写作 | 选题 / 大纲 / 正文 / SEO | 主题、字数、结构 |
| 营销文案 | 标题 / 广告语 / 产品描述 / 落地页 | 卖点、受众、CTA |
| 邮件写作 | 商务 / 客户关怀 / 营销 | 收件人、目的、语气 |
| 报告生成 | 数据分析 / 周报 / 月报 | 数据、维度、结论 |
| 故事创作 | 设定 / 角色 / 情节 / 风格 | 题材、风格、长度 |

**创作 Prompt 要点**：
- 目标受众（决定用词与深度）
- 语气风格（品牌调性）
- 长度（字数 / 段落数）
- 关键信息（必须包含的卖点 / 数据）
- 品牌调性（一致性与差异化）

### 7. 风格迁移（Style Transfer）

风格迁移把文本从一种风格转为另一种，原意不变：

| 输入风格 | 输出风格 | 场景 |
|---------|---------|------|
| 口语 | 正式 | 客服记录转报告 |
| 技术 | 通俗 | 技术文档转用户说明 |
| 消极 | 积极 | 投诉回复润色 |

Prompt 要点：明确"原意不变 + 风格维度变化"。

### 8. 格式转换（Format Conversion）

格式转换是非结构化 ↔ 结构化的桥梁：

| 转换方向 | 输入 | 输出 |
|---------|------|------|
| 文本 → 表格 | 描述性文本 | Markdown 表格 |
| 文本 → JSON | 非结构化记录 | 结构化数据 |
| 文本 → 大纲 | 长文 | 层级大纲 |
| 表格 → 文本 | 数据表 | 叙述性描述 |

### 9. 数据清洗与标准化

| 子任务 | 说明 |
|--------|------|
| 统一格式 | 日期 / 电话 / 地址标准化 |
| 去重合并 | 重复信息合并 |
| 缺失值处理 | 推断填充 |

### 10. 关键词提取与主题建模

| 子任务 | 说明 |
|--------|------|
| 关键词提取 | TF-IDF 思路用 Prompt 实现 |
| 主题识别 | 给定文本 → 识别讨论主题 |

### 11. 问答系统 Prompt 设计

| 子任务 | 说明 |
|--------|------|
| FAQ 问答 | 给定 FAQ 库 → 匹配问题 → 生成答案 |
| 问答对生成 | 从文档生成 Q&A 对 |
| RAG 预览 | 检索增强生成的 Prompt 模板预览 |

RAG Prompt 骨架（Day09 详解）：

```text
你是客服助手。根据以下检索到的知识库片段回答用户问题。

【知识库片段】
{{retrieved_chunks}}

【用户问题】
{{user_question}}

约束：
1. 只能基于知识库片段回答，不得编造
2. 若知识库无法回答，回复"暂无法回答，转人工"
3. 引用片段编号 [1] [2]
```

### 分块摘要 Map-Reduce 流程图

```text
┌──────────────────────────────────────────────┐
│  超长文本（如 50000 字退换货政策）           │
└──────────────────┬───────────────────────────┘
                   │
                   ▼
          ┌────────────────┐
          │  分块（Chunk） │
          │  按 2000 字/块 │
          └────────┬───────┘
                   │
        ┌──────────┼──────────┐
        ▼          ▼          ▼
   ┌─────────┐┌─────────┐┌─────────┐
   │ 块1摘要 ││ 块2摘要 ││ 块N摘要 │   ← Map 阶段
   └────┬────┘└────┬────┘└────┬────┘
        │          │          │
        └──────────┼──────────┘
                   ▼
          ┌────────────────┐
          │ 合并 + 去重     │
          │ 风格统一        │              ← Reduce 阶段
          └────────┬───────┘
                   ▼
          ┌────────────────┐
          │  最终摘要       │
          └────────────────┘
```

## 实战练习

### 练习 1：客服对话全链路文本处理

**任务**：
1. 收集 5 条真实客服对话（可模拟）
2. 使用 `Code/01-summarization.md` 中的"单文档摘要"模板，为每条对话生成摘要
3. 使用 `Code/02-classification-extraction.md` 中的"情感分类"和"实体抽取"模板，对每条对话分析情感并抽取订单号 / 金额 / 日期
4. 汇总成一张 Markdown 表格：对话 / 摘要 / 情感 / 实体

**验收标准**：
- 摘要不超过 50 字
- 情感分类带置信度
- 实体抽取输出 JSON

### 练习 2：电商退换货政策多语言翻译

**任务**：
1. 选一段 300 字左右的电商退换货政策
2. 使用 `Code/03-translation-rewrite.md` 中的"多语言翻译"模板，提供 5 个术语（如"7天无理由退货"），翻译为英文
3. 使用"风格化翻译"模板，分别生成商务正式版和口语化版
4. 对比三版（直译 / 正式 / 口语）的差异

**验收标准**：
- 术语表中的术语在译文中保持一致
- 三版风格差异明显

### 练习 3：客服周报自动化生成

**任务**：
1. 模拟一周客服数据（10 条对话 + 5 条评价 + 3 条投诉）
2. 使用 `Code/04-content-creation.md` 中的"报告生成"模板，生成客服周报
3. 周报需包含：本周概况 / 关键数据 / 典型案例 / 问题与改进建议
4. 使用 `Code/05-format-conversion.md` 中的"表格转文本"模板，把数据表转为叙述性描述

**验收标准**：
- 周报结构完整，含 4 个章节
- 数据准确，无编造
- 改进建议可执行
