# 输出格式控制

> 本文件展示六种输出格式的 Prompt 模板：纯文本 / Markdown 表格 / 列表 / JSON / Markdown 大纲 / 自定义模板。重点演示 JSON Schema 约束输出结构，所有模板围绕 SmartCS 客服场景。

---

## 格式一：纯文本

### 模板说明
- 用途：生成自然语言客服回复
- 适用模型：通用
- 变量：`{{user_message}}`、`{{order_info}}`

### 完整模板
```
你是 SmartCS 客服。请用纯文本回复用户，语气专业温和，不超过 100 字，不要使用 Markdown 格式符号。

用户消息：{{user_message}}
订单信息：{{order_info}}
```

### 使用示例
#### 输入
```
你是 SmartCS 客服。请用纯文本回复用户，语气专业温和，不超过 100 字，不要使用 Markdown 格式符号。

用户消息：耳机有杂音怎么办？
订单信息：订单 SO20240501，无线蓝牙耳机
```

#### 预期输出
```
您好，很抱歉耳机出现杂音问题。建议您先尝试更换设备连接排查，若仍有杂音，可为订单 SO20240501 申请退换货。请问您希望退款还是换新？
```

### 调优建议
- 明确"不要使用 Markdown 符号"，否则模型可能输出 `**`、`#` 等
- 温度建议：0.5

## 格式二：Markdown 表格

### 模板说明
- 用途：商品对比、订单明细等多维度信息展示
- 适用模型：通用
- 变量：`{{products}}`

### 完整模板
```
你是 SmartCS 导购助手。请将以下商品信息整理为 Markdown 表格，列名：型号 | 价格 | 降噪 | 续航 | 推荐指数(1-5★)。

商品数据：
{{products}}

要求：表格后附 1 句总结推荐，不超过 30 字。
```

### 使用示例
#### 输入
```
你是 SmartCS 导购助手。请将以下商品信息整理为 Markdown 表格，列名：型号 | 价格 | 降噪 | 续航 | 推荐指数(1-5★)。

商品数据：
- EarA 199元 无降噪 8小时 三星
- EarB 299元 有降噪 12小时 五星
- EarC 399元 有降噪 10小时 四星

要求：表格后附 1 句总结推荐，不超过 30 字。
```

#### 预期输出
```
| 型号 | 价格 | 降噪 | 续航 | 推荐指数 |
|------|------|------|------|---------|
| EarA | 199元 | 无 | 8小时 | ★★★ |
| EarB | 299元 | 有 | 12小时 | ★★★★★ |
| EarC | 399元 | 有 | 10小时 | ★★★★ |

综合推荐 EarB，降噪与续航均衡且性价比最高。
```

### 调优建议
- 明确列名与数据类型，避免模型自由发挥列结构
- 星级等需统一格式，可在模板中给定示例

---

## 格式三：列表

### 模板说明
- 用途：退货流程、操作步骤等条目化输出
- 适用模型：通用
- 变量：`{{task}}`

### 完整模板
```
你是 SmartCS 客服。请以 Markdown 有序列表输出 {{task}} 的操作步骤，每步标题加粗，说明不超过 30 字，共 4 步。
```

### 使用示例
#### 输入
```
你是 SmartCS 客服。请以 Markdown 有序列表输出"退货申请"的操作步骤，每步标题加粗，说明不超过 30 字，共 4 步。
```

#### 预期输出
```
1. **提交申请**：在订单页选择"申请退货"并填写原因
2. **等待审核**：客服 1 小时内审核通过
3. **寄回商品**：按提供的地址寄回并保留物流单号
4. **退款到账**：签收后 1-3 工作日原路退回
```

### 调优建议
- 指定有序/无序、步数、每步字数，输出才稳定
- 需要子步骤时可要求"每步下可含 2 个子要点"

## 格式四：JSON（重点）

### 模板说明
- 用途：意图识别、信息抽取等需程序解析的场景
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_message}}`

### 完整模板
```
你是 SmartCS 意图识别模块。对用户消息分类，类别仅限：faq / order_query / refund / complaint / ticket。

用户消息：{{user_message}}

输出要求：
- 以 JSON 输出，schema 如下：
{
  "intent": "string，上述 5 类之一",
  "confidence": "number，0.0-1.0 保留两位小数",
  "keywords": "array，关键词列表，最多 5 个",
  "need_human": "boolean，是否需转人工"
}
- 只输出 JSON，不要 markdown 代码块标记，不要解释
- 不要编造未列出的类别
```

### 使用示例
#### 输入
```
你是 SmartCS 意图识别模块。对用户消息分类，类别仅限：faq / order_query / refund / complaint / ticket。

用户消息：我买的耳机有杂音，订单 SO20240501，要求退款！

输出要求：
- 以 JSON 输出，schema 如下：
{
  "intent": "string，上述 5 类之一",
  "confidence": "number，0.0-1.0 保留两位小数",
  "keywords": "array，关键词列表，最多 5 个",
  "need_human": "boolean，是否需转人工"
}
- 只输出 JSON，不要 markdown 代码块标记，不要解释
- 不要编造未列出的类别
```

#### 预期输出
```json
{"intent": "refund", "confidence": 0.95, "keywords": ["耳机", "杂音", "退款", "SO20240501"], "need_human": false}
```

### JSON Schema 严格约束（进阶）

当需要更严格的结构控制时，可直接给出 JSON Schema：

```
请按以下 JSON Schema 输出，不要包含任何其他内容：

{
  "type": "object",
  "properties": {
    "intent": {"type": "string", "enum": ["faq", "order_query", "refund", "complaint", "ticket"]},
    "confidence": {"type": "number", "minimum": 0, "maximum": 1},
    "keywords": {"type": "array", "items": {"type": "string"}, "maxItems": 5},
    "need_human": {"type": "boolean"}
  },
  "required": ["intent", "confidence", "keywords", "need_human"]
}

用户消息：{{user_message}}
```

### 调优建议
- 明确"不要 markdown 代码块标记"，否则模型常输出 ` ```json ` 包裹
- 温度建议：0（结构化输出需确定性）
- OpenAI 支持 `response_format: {"type": "json_object"}` 强制 JSON 输出
- 复杂结构建议给出完整示例 JSON，模型模仿更准确

## 格式五：Markdown 大纲

### 模板说明
- 用途：退换货政策、售后指南等层级化文档生成
- 适用模型：通用
- 变量：`{{topic}}`

### 完整模板
```
你是 SmartCS 文档助手。请为"{{topic}}"生成 Markdown 大纲，要求：
- 一级标题 1 个（#）
- 二级标题 3-4 个（##）
- 每个二级标题下 2-3 个要点（- ）
- 每个要点后附 1 句说明
```

### 使用示例
#### 输入
```
你是 SmartCS 文档助手。请为"SmartCS 退换货政策"生成 Markdown 大纲，要求：
- 一级标题 1 个（#）
- 二级标题 3-4 个（##）
- 每个二级标题下 2-3 个要点（- ）
- 每个要点后附 1 句说明
```

#### 预期输出
```
# SmartCS 退换货政策

## 退货时效
- 7 天无理由：签收 7 天内可无理由退货
- 15 天质量：质量问题 15 天内可退

## 退货条件
- 原包装完好：需保留完整包装与配件
- 非人为损坏：人为损坏不在退货范围

## 退款时效
- 原路退回：退款原路返回支付账户
- 1-3 工作日：签收后 1-3 个工作日到账

## 特殊说明
- 定制商品：定制类商品不支持无理由退货
- 生鲜商品：生鲜品类一经签收不退换
```

### 调优建议
- 明确标题层级数量与要点数，避免模型自由发挥层级深度
- 大纲生成后可分段展开，用 Prompt 链式调用逐节扩写

## 格式六：自定义模板

### 模板说明
- 用途：工单生成等需固定格式的场景
- 适用模型：通用
- 变量：`{{user_message}}`、`{{order_info}}`

### 完整模板
```
你是 SmartCS 工单生成模块。请按以下模板格式输出工单，不要增删字段：

【工单编号】TK-{{自动生成}}
【提交时间】{{当前时间}}
【订单信息】{{order_info}}
【用户诉求】{{user_message}}
【工单类型】[退款/换货/维修/咨询]（选一）
【优先级】[高/中/低]
【处理建议】（不超过 50 字）
【 assigned_to】客服组-售后组

请根据用户消息与订单信息填充各字段。
```

### 使用示例
#### 输入
```
你是 SmartCS 工单生成模块。请按以下模板格式输出工单，不要增删字段：

【工单编号】TK-20240501-007
【提交时间】2024-05-04 10:30
【订单信息】订单 SO20240501，无线蓝牙耳机，299 元
【用户诉求】耳机左耳有杂音，使用 3 天后出现问题，要求退款
【工单类型】[退款/换货/维修/咨询]（选一）
【优先级】[高/中/低]
【处理建议】（不超过 50 字）
【assigned_to】客服组-售后组

请根据用户消息与订单信息填充各字段。
```

#### 预期输出
```
【工单编号】TK-20240501-007
【提交时间】2024-05-04 10:30
【订单信息】订单 SO20240501，无线蓝牙耳机，299 元
【用户诉求】耳机左耳有杂音，使用 3 天后出现问题，要求退款
【工单类型】退款
【优先级】中
【处理建议】建议先引导用户提供杂音视频证据，确认质量问题后走退款流程，1-3 工作日到账。
【assigned_to】客服组-售后组
```

### 调优建议
- 自定义模板适合对接固定业务系统的场景
- 模板字段用 `【】` 或 `<>` 包裹，模型识别更稳定
- 可与 JSON 格式二选一：JSON 适合程序解析，自定义模板适合人工阅读

---

## 六种格式对比

| 格式 | 适用场景 | 程序可解析 | 实现难度 |
|------|---------|-----------|---------|
| 纯文本 | 客服对话回复 | 弱 | 易 |
| Markdown 表格 | 商品对比、明细 | 中 | 易 |
| 列表 | 流程步骤 | 中 | 易 |
| JSON | 意图识别、抽取 | 强 | 中 |
| Markdown 大纲 | 文档生成 | 中 | 易 |
| 自定义模板 | 工单、固定格式 | 中 | 中 |

---

## 总结

> 核心心法：选格式的依据是"下游如何消费输出"。
> - 人看 → 纯文本 / 表格 / 列表 / 大纲
> - 程序解析 → JSON（首选）/ 自定义模板
> - 对接业务系统 → JSON Schema 严格约束

格式控制的核心是**给示例 + 给 schema + 禁止多余内容**三件套，缺一不可。
