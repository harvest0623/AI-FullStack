# 基础 Prompt 模板合集

> 本文件围绕 SmartCS 智能客服场景，展示从"差 Prompt"到"好 Prompt"的改进过程。每个示例包含改进前、改进后、改进点说明，帮助理解 Prompt 四要素（指令 / 上下文 / 输入 / 输出格式）的实际作用。

---

## 示例 1：客服问候

### 模板说明
- 用途：为新进店用户生成一段欢迎语
- 适用模型：通用
- 变量：`{{user_name}}`、`{{shop_name}}`

### 改进前（差 Prompt）
```
你好
```

**预期输出**：
```
你好！有什么可以帮您的吗？
```
> 问题：无身份、无业务感、无格式约束，输出泛泛。

### 改进后（好 Prompt）

#### 完整模板
```
你是电商平台 {{shop_name}} 的智能客服助手 SmartCS。
请为新进店用户生成一段欢迎语，要求：
- 语气：专业、热情、简洁
- 长度：不超过 30 字
- 内容：包含店铺名称与一句引导提问
- 称呼用户：{{user_name}}

直接输出欢迎语，不要解释。
```

#### 使用示例
##### 输入
```
你是电商平台 "SmartCS 数码旗舰店" 的智能客服助手 SmartCS。
请为新进店用户生成一段欢迎语，要求：
- 语气：专业、热情、简洁
- 长度：不超过 30 字
- 内容：包含店铺名称与一句引导提问
- 称呼用户：小李

直接输出欢迎语，不要解释。
```

##### 预期输出
```
小李你好，欢迎来到 SmartCS 数码旗舰店！选购中遇到商品、订单或售后问题，随时问我哦～
```

### 改进点
| 维度 | 改进前 | 改进后 |
|------|--------|--------|
| 上下文 | 无身份 | 明确店铺名 + 客服身份 |
| 指令 | "你好" | 明确"生成欢迎语" |
| 约束 | 无 | 字数、语气、内容要素 |
| 输出格式 | 无 | "直接输出，不要解释" |

### 调优建议
- 温度建议：0.7（欢迎语需要一点温度，但不至于跑偏）
- 若希望每次问候略有不同，可加"准备 3 条不同风格的欢迎语"让模型给出候选

## 示例 2：商品推荐

### 模板说明
- 用途：根据用户画像从在售机型中推荐商品
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{budget}}`、`{{preferences}}`、`{{candidate_products}}`

### 改进前（差 Prompt）
```
推荐个手机
```

**预期输出**：
```
为您推荐以下手机：iPhone 15、华为 Mate 60、小米 14……（通用清单，与用户需求无关）
```
> 问题：无用户画像、无候选范围、无输出格式，结果不可被业务系统消费。

### 改进后（好 Prompt）

#### 完整模板
```
你是 SmartCS 电商平台的导购助手。请根据用户画像，从候选机型中推荐 2 款最合适的手机。

用户画像：
- 预算：{{budget}}
- 偏好：{{preferences}}

候选机型：
{{candidate_products}}

输出要求：
- 以 JSON 数组输出，每项包含字段：name（机型名）、price（价格）、reason（推荐理由，不超过 30 字）
- 只从候选机型中选择，不要编造不存在的机型
- 不要输出 JSON 以外的任何内容
```

#### 使用示例
##### 输入
```
你是 SmartCS 电商平台的导购助手。请根据用户画像，从候选机型中推荐 2 款最合适的手机。

用户画像：
- 预算：3000 元
- 偏好：拍照好、续航久

候选机型：
- PhoneA 2999 元 拍照旗舰，续航一般
- PhoneB 3199 元 大电池长续航，拍照中等
- PhoneC 2599 元 性价比之选，拍照续航均衡

输出要求：
- 以 JSON 数组输出，每项包含字段：name（机型名）、price（价格）、reason（推荐理由，不超过 30 字）
- 只从候选机型中选择，不要编造不存在的机型
- 不要输出 JSON 以外的任何内容
```

##### 预期输出
```json
[
  {"name": "PhoneA", "price": "2999元", "reason": "拍照旗舰契合用户拍照需求，预算内"},
  {"name": "PhoneC", "price": "2599元", "reason": "拍照续航均衡，性价比高，预算充裕"}
]
```

### 改进点
| 维度 | 改进前 | 改进后 |
|------|--------|--------|
| 上下文 | 无 | 用户画像 + 候选机型 |
| 指令 | "推荐个手机" | "推荐 2 款最合适的" |
| 约束 | 无 | 只能从候选选、不编造 |
| 输出格式 | 无 | JSON 数组 + 字段约束 |

### 调优建议
- 温度建议：0.3（推荐需要稳定，避免每次结果差异大）
- 候选机型列表较长时，可先用检索筛选 Top 5 再送入 Prompt，避免上下文过长

## 示例 3：问题解答（FAQ）

### 模板说明
- 用途：根据 FAQ 知识库回答用户售后问题
- 适用模型：通用
- 变量：`{{faq_content}}`、`{{user_question}}`

### 改进前（差 Prompt）
```
退货怎么弄？
```

**预期输出**：
```
您好，退货流程如下：请联系客服……（凭模型记忆编造，可能与实际政策不符，产生幻觉）
```
> 问题：未提供真实 FAQ，模型靠预训练记忆编造，容易出错。

### 改进后（好 Prompt）

#### 完整模板
```
你是 SmartCS 电商客服。请仅根据下方提供的 FAQ 知识库回答用户问题。

FAQ 知识库：
"""
{{faq_content}}
"""

用户问题：{{user_question}}

回答要求：
- 只能依据 FAQ 知识库作答，不要编造未提及的政策
- 若 FAQ 中没有相关内容，回复："抱歉，该问题暂未收录，已为您转接人工客服。"
- 回答简洁，不超过 100 字，语气专业礼貌
```

#### 使用示例
##### 输入
```
你是 SmartCS 电商客服。请仅根据下方提供的 FAQ 知识库回答用户问题。

FAQ 知识库：
"""
Q: 退货时效是多久？
A: 签收后 7 天内可申请无理由退货，15 天内可申请质量问题退货。

Q: 退货运费谁承担？
A: 非质量问题退货由买家承担运费；质量问题退货运费由卖家承担。
"""

用户问题：我收货 10 天了还能退货吗？

回答要求：
- 只能依据 FAQ 知识库作答，不要编造未提及的政策
- 若 FAQ 中没有相关内容，回复："抱歉，该问题暂未收录，已为您转接人工客服。"
- 回答简洁，不超过 100 字，语气专业礼貌
```

##### 预期输出
```
您好，签收后 7 天内可申请无理由退货，15 天内可申请质量问题退货。您已收货 10 天，若属于质量问题仍可在 15 天内申请退货；若为无理由退货则已超过时效，建议联系人工客服进一步协助。
```

### 改进点
| 维度 | 改进前 | 改进后 |
|------|--------|--------|
| 上下文 | 无 | 注入真实 FAQ 知识库 |
| 指令 | "退货怎么弄" | "依据 FAQ 回答" |
| 约束 | 无 | 不编造、无答案时转人工 |
| 输出格式 | 无 | 字数限制 + 语气要求 |

### 调优建议
- 温度建议：0（FAQ 回答需准确，避免发挥）
- FAQ 较长时，先用向量检索召回 Top 3 相关条目，再注入 Prompt（RAG 思路）

## 示例 4：意图识别（结构化输出进阶）

### 模板说明
- 用途：识别用户消息的意图，为后续路由提供依据
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_message}}`

### 改进前（差 Prompt）
```
看看这条消息是什么意思：我想退钱
```

**预期输出**：
```
这条消息的意思是用户想要退款。（自然语言，无法被程序解析）
```
> 问题：输出非结构化，无法被业务系统消费。

### 改进后（好 Prompt）

#### 完整模板
```
你是 SmartCS 客服系统的意图识别模块。请对用户消息进行意图分类。

意图类别（仅限以下 5 类）：
- faq：常见问题咨询
- order_query：订单查询
- refund：退款/退货
- complaint：投诉
- ticket：需转人工工单

用户消息：{{user_message}}

输出要求：
- 以 JSON 输出，格式：{"intent": "类别", "confidence": 0.0-1.0, "reason": "判断理由(不超过20字)"}
- 只能从上述 5 类中选择，不要编造新类别
- 不要输出 JSON 以外的任何内容
```

#### 使用示例
##### 输入
```
你是 SmartCS 客服系统的意图识别模块。请对用户消息进行意图分类。

意图类别（仅限以下 5 类）：
- faq：常见问题咨询
- order_query：订单查询
- refund：退款/退货
- complaint：投诉
- ticket：需转人工工单

用户消息：我买的耳机有杂音，要求退款！

输出要求：
- 以 JSON 输出，格式：{"intent": "类别", "confidence": 0.0-1.0, "reason": "判断理由(不超过20字)"}
- 只能从上述 5 类中选择，不要编造新类别
- 不要输出 JSON 以外的任何内容
```

##### 预期输出
```json
{"intent": "refund", "confidence": 0.9, "reason": "明确提到退款且伴随商品问题"}
```

### 改进点
| 维度 | 改进前 | 改进后 |
|------|--------|--------|
| 上下文 | 无 | 明确意图分类体系 |
| 指令 | "看看是什么意思" | "进行意图分类" |
| 约束 | 无 | 限定 5 类、不编造 |
| 输出格式 | 自然语言 | JSON + 字段约束 |

### 调优建议
- 温度建议：0（分类任务需确定性输出）
- 若用户消息可能跨多个意图，可在 JSON 中改 `intent` 为 `intents` 数组

## 示例 5：退换货引导（多步骤指令）

### 模板说明
- 用途：引导用户完成退换货流程
- 适用模型：通用
- 变量：`{{order_info}}`、`{{return_reason}}`

### 改进前（差 Prompt）
```
用户要退货，你看着办
```

**预期输出**：
```
好的，请提供订单号……（无流程、无信息收集，效率低）
```
> 问题：无流程、无步骤、无信息约束。

### 改进后（好 Prompt）

#### 完整模板
```
你是 SmartCS 退换货专员。请按以下流程引导用户完成退货：

订单信息：{{order_info}}
退货原因：{{return_reason}}

引导步骤（逐步输出，每步等用户确认后再进入下一步）：
1. 确认退货商品与原因
2. 提供退货地址与物流要求
3. 告知预计退款时效
4. 生成退货工单编号

输出要求：
- 当前只输出第 1 步内容
- 语气专业、简洁，每步不超过 80 字
- 若订单信息缺失关键字段（如订单号），先向用户询问
```

#### 使用示例
##### 输入
```
你是 SmartCS 退换货专员。请按以下流程引导用户完成退货：

订单信息：订单号 SO20240501-001，商品"无线蓝牙耳机"，金额 299 元
退货原因：商品有杂音

引导步骤（逐步输出，每步等用户确认后再进入下一步）：
1. 确认退货商品与原因
2. 提供退货地址与物流要求
3. 告知预计退款时效
4. 生成退货工单编号

输出要求：
- 当前只输出第 1 步内容
- 语气专业、简洁，每步不超过 80 字
- 若订单信息缺失关键字段（如订单号），先向用户询问
```

##### 预期输出
```
您好，已收到您的退货申请。请确认以下信息：
- 订单号：SO20240501-001
- 商品：无线蓝牙耳机（299 元）
- 退货原因：商品有杂音
信息无误吗？确认后我将提供退货地址。
```

### 改进点
| 维度 | 改进前 | 改进后 |
|------|--------|--------|
| 上下文 | 无 | 订单信息 + 退货原因 |
| 指令 | "你看着办" | 明确 4 步流程 |
| 约束 | 无 | 逐步输出、字数限制 |
| 输出格式 | 无 | 结构化分步引导 |

### 调优建议
- 温度建议：0.3（流程引导需稳定，避免跳步）
- 多步骤场景可结合 Prompt 链式调用：第一步输出确认后，再用第二步 Prompt 继续

---

## 总结：从差到好的改进路径

| 改进方向 | 差 Prompt 表现 | 好 Prompt 做法 |
|---------|---------------|---------------|
| 加上下文 | 无身份/背景 | 明确角色 + 业务背景 + 知识 |
| 明指令 | 模糊动词（看看/处理） | 具体动词（分类/推荐/引导） |
| 限约束 | 无边界 | 范围、字数、禁止项 |
| 定格式 | 自然语言 | JSON / 分步 / 字段约束 |

> 核心心法：把 Prompt 当作"写给新员工的任务说明书"——越具体、越可执行，结果越好。
