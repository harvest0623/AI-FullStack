# LLM 自动评估模板（LLM-as-a-Judge）

用更强的 LLM（如 GPT-4）评估其他 LLM 的输出。本模板提供通用评估 Prompt 与 3 个具体评估示例：意图识别准确性评估、客服回复质量评估、格式合规性评估。

---

## 模板说明

- 用途：用 GPT-4 自动评估其他 LLM 在 SmartCS 客服任务上的输出质量
- 适用模型：GPT-4（作为评估器）/ Claude（作为评估器）
- 变量：`{{evaluation_criteria}}`、`{{original_input}}`、`{{output_to_evaluate}}`、`{{reference_answer}}`

---

## 完整模板（通用评估 Prompt）

```
你是 Prompt 输出质量评估专家，负责评估 LLM 在客服任务上的输出质量。请严格按评估标准打分。

评估标准：
{{evaluation_criteria}}

原始输入：
{{original_input}}

待评估输出：
{{output_to_evaluate}}

参考答案（如有）：
{{reference_answer}}

请按以下格式输出评估结果：

维度评分：
- 准确性：X/5（理由：...）
- 相关性：X/5（理由：...）
- 流畅性：X/5（理由：...）
- 安全性：X/5（理由：...）
- 格式合规：X/5（理由：...）

总分：X/25

总评：
[2-3 句话总结输出质量]

改进建议：
[1-3 条具体可执行的改进建议]
```

## 评估示例 1：意图识别准确性评估

### 评估标准

```
评估意图识别输出的准确性：
- 5 分：意图类别完全正确，置信度合理，实体提取完整
- 4 分：意图正确，实体有小瑕疵
- 3 分：意图正确但置信度过高或过低
- 2 分：意图错误但方向接近
- 1 分：意图完全错误
```

### 输入

```
你是 Prompt 输出质量评估专家，负责评估 LLM 在客服任务上的输出质量。请严格按评估标准打分。

评估标准：
评估意图识别输出的准确性：
- 5 分：意图类别完全正确，置信度合理，实体提取完整
- 4 分：意图正确，实体有小瑕疵
- 3 分：意图正确但置信度过高或过低
- 2 分：意图错误但方向接近
- 1 分：意图完全错误

原始输入：
我 10 天前买的电饭煲按键失灵了，想换货，订单号 20240518。

待评估输出：
{"intent": "退换货", "confidence": 0.95, "entities": {"order_id": "20240518", "product": "电饭煲", "issue": "按键失灵", "purchase_days": 10}}

参考答案：
intent=退换货，confidence 应在 0.9 以上；entities 应包含 order_id、product、issue、purchase_days

请按以下格式输出评估结果：

维度评分：
- 准确性：X/5（理由：...）
- 相关性：X/5（理由：...）
- 流畅性：X/5（理由：...）
- 安全性：X/5（理由：...）
- 格式合规：X/5（理由：...）

总分：X/25

总评：
[2-3 句话总结输出质量]

改进建议：
[1-3 条具体可执行的改进建议]
```

### 预期输出

```
维度评分：
- 准确性：5/5（理由：意图"退换货"完全正确，置信度 0.95 合理，实体提取完整且准确）
- 相关性：5/5（理由：输出直接回应输入，无冗余）
- 流畅性：5/5（理由：JSON 结构清晰，字段命名规范）
- 安全性：5/5（理由：未泄露任何敏感信息，未编造事实）
- 格式合规：5/5（理由：JSON 可解析，字段齐全，类型正确）

总分：25/25

总评：
意图识别输出质量优秀，意图类别、置信度、实体提取均符合参考答案，是一次高质量的识别结果。

改进建议：
1. 可考虑增加 issue_type 字段（如"质量问题"/"物流问题"），便于下游任务路由
2. purchase_days 字段建议增加时间单位（如"purchase_days": "10天"），避免歧义
```

## 评估示例 2：客服回复质量评估

### 评估标准

```
评估客服回复质量：
- 准确性（5 分）：政策适用无误、金额计算精确
- 同理心（5 分）：是否先共情再处理、语气是否有温度
- 专业性（5 分）：用词是否专业、是否避免模板化套话
- 简洁性（5 分）：是否在 200 字以内、是否有冗余
- 安全性（5 分）：是否未泄露内部规则、是否未超政策承诺
```

### 输入

```
你是 Prompt 输出质量评估专家，负责评估 LLM 在客服任务上的输出质量。请严格按评估标准打分。

评估标准：
评估客服回复质量：
- 准确性（5 分）：政策适用无误、金额计算精确
- 同理心（5 分）：是否先共情再处理、语气是否有温度
- 专业性（5 分）：用词是否专业、是否避免模板化套话
- 简洁性（5 分）：是否在 200 字以内、是否有冗余
- 安全性（5 分）：是否未泄露内部规则、是否未超政策承诺

原始输入：
我 5 天前下的订单 #20240518，物流一直不动，到底怎么回事？还没收到货呢！（用户为 VIP）

待评估输出：
您好，关于订单 #20240518 物流停滞的问题，我们已为您核查。包裹在上海转运中心滞留，原因为疑似破损待复核。这是物流方原因，非您的责任。我们已为您创建高优先级工单 T20240518001，VIP 专属客服将在 1 小时内联系您。您可选择：1) 等待复核后派送；2) 立即补发新包裹；3) 全额退款 2890 元。额外赠送 100 元优惠券作为补偿。

参考答案：
应包含：共情、原因说明、解决方案、补偿、VIP 专属通道

请按以下格式输出评估结果：

维度评分：
- 准确性：X/5（理由：...）
- 相关性：X/5（理由：...）
- 流畅性：X/5（理由：...）
- 安全性：X/5（理由：...）
- 格式合规：X/5（理由：...）

总分：X/25

总评：
[2-3 句话总结输出质量]

改进建议：
[1-3 条具体可执行的改进建议]
```

### 预期输出

```
维度评分：
- 准确性：5/5（理由：物流异常原因说明准确，工单号与金额 2890 元正确，方案三选一合理）
- 相关性：5/5（理由：直接回应用户"物流停滞"的诉求，提供明确方案）
- 流畅性：5/5（理由：语言通顺专业，结构清晰）
- 安全性：5/5（理由：未泄露内部规则，补偿在 VIP 权限范围内（100 元 < 200 元上限））
- 格式合规：5/5（理由：回复长度适中，结构化呈现方案）

总分：23/25

总评：

改进建议：
1. 开头增加一句共情："我们完全理解您等待 5 天的焦急心情"
2. 方案可按推荐顺序排列，并标注推荐项（如"推荐方案：立即补发"）
3. 金额 2890 元可加粗或单独成行，便于用户快速识别
```

## 评估示例 3：格式合规性评估

### 评估标准

```
评估 JSON 输出的格式合规性：
- 5 分：JSON 可解析、字段齐全、类型正确、无多余文本
- 4 分：JSON 可解析，1 处小问题
- 3 分：JSON 可解析但缺少非关键字段
- 2 分：JSON 难以解析或缺少关键字段
- 1 分：未输出 JSON 或无法解析
```

### 输入

```
你是 Prompt 输出质量评估专家，负责评估 LLM 在客服任务上的输出质量。请严格按评估标准打分。

评估标准：
评估 JSON 输出的格式合规性：
- 5 分：JSON 可解析、字段齐全、类型正确、无多余文本
- 4 分：JSON 可解析，1 处小问题
- 3 分：JSON 可解析但缺少非关键字段
- 2 分：JSON 难以解析或缺少关键字段
- 1 分：未输出 JSON 或无法解析

原始输入：
判断用户输入的意图，输出 JSON {"intent": "...", "confidence": 0.0~1.0}
用户输入：我想退货

待评估输出：
根据用户输入"我想退货"，可以判断为退换货意图。以下是 JSON 输出：

{"intent": "退换货", "confidence": 0.9}

希望以上回答对您有帮助！

参考答案：
{"intent": "退换货", "confidence": 0.9}

请按以下格式输出评估结果：

维度评分：
- 准确性：X/5（理由：...）
- 相关性：X/5（理由：...）
- 流畅性：X/5（理由：...）
- 安全性：X/5（理由：...）
- 格式合规：X/5（理由：...）

总分：X/25

总评：
[2-3 句话总结输出质量]

改进建议：
[1-3 条具体可执行的改进建议]
```

### 预期输出

```
维度评分：
- 准确性：5/5（理由：意图识别正确，置信度合理）
- 相关性：5/5（理由：直接回应用户输入）
- 流畅性：4/5（理由：自然语言部分通顺，但 JSON 前后有多余文本）
- 安全性：5/5（理由：无安全问题）
- 格式合规：2/5（理由：JSON 前有"根据用户输入..."、后有"希望以上回答..."，多余文本会影响程序解析）

总评：
意图识别准确，但格式合规性差——JSON 前后有多余自然语言文本，会导致 `json.loads()` 解析失败。需要强化"仅输出 JSON"的约束。

改进建议：
1. 在 Prompt 中明确"不要输出 JSON 以外的任何内容"
2. 增加 Few-Shot 示例，示范"只有 JSON、无其他文本"的正确输出
3. 可在 Prompt 末尾加"直接输出 JSON，不要解释"，强化约束
```

## 调优建议

- 评估器选择：用比被评估模型更强的 LLM 作为评估器（如用 GPT-4 评估 GPT-3.5 的输出），评估结果更可信
- 温度建议：0.0，评估需要稳定性与一致性
- 评估器校准：先用人工标注 20-30 个样本，对比 LLM 评估器与人工评分的一致性，一致性低于 80% 时需调整评估 Prompt
- 避免偏见：LLM 评估器容易被表面流畅性误导，对"流畅但错误"的输出可能给高分。需在评估标准中强调"先判准确性，再判流畅性"
- 批量评估：可将多个样本打包成一次 Prompt 调用，降低成本（但单次不超过 10 个样本，避免评估质量下降）
- 局限认知：LLM-as-a-Judge 难以评估事实准确性（需对照知识库），对微妙差异不敏感，关键场景仍需人工复核
