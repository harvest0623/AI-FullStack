## 四、完整 A/B 测试案例

### 测试计划

| 字段 | 内容 |
|------|------|
| 测试名称 | SmartCS 退换货判断 Prompt - Zero-Shot CoT vs Few-Shot CoT |
| 测试假设 | Few-Shot CoT（B 版）在困难场景下的准确性优于 Zero-Shot CoT（A 版） |
| A 版（基线） | v1.0 - Zero-Shot CoT，末尾加"让我们一步一步思考" |
| B 版（候选） | v1.1 - Few-Shot CoT，提供 2 个"Step 1/2/3"格式示例 |
| 修改变量 | 仅修改 CoT 形式（Zero-Shot → Few-Shot） |
| 控制变量 | 模型 GPT-4 / 温度 0.0 / 同一输入集 / 每版运行 3 次取平均 |

| 评估维度 | 准确性 / 格式合规 / 一致性 |
| 评估方式 | 人工盲评 + 程序化 JSON 校验 |
| 通过标准 | B 版在困难场景准确性上超过 A 版 ≥ 0.5 分（5 分制） |
| 测试时间 | 2024-05-20 至 2024-05-22 |
| 负责人 | 张三 |

### A 版 Prompt（v1.0 - Zero-Shot CoT）

```
你是 SmartCS 客服助手，负责判断用户退换货请求是否符合政策。

退换货政策：
- 7 天无理由退货（商品完好）
- 15 天质量问题退货（需照片凭证）
- 30 天质量问题换货
- 定制商品不支持无理由退货（质量问题除外）

用户请求：{{user_request}}

让我们一步一步思考。

输出 JSON：{"conclusion": "符合/不符合/需补充信息", "reason": "...", "next_step": "..."}
```

### B 版 Prompt（v1.1 - Few-Shot CoT）

```
你是 SmartCS 客服助手，负责判断用户退换货请求是否符合政策。

退换货政策：
- 7 天无理由退货（商品完好）
- 15 天质量问题退货（需照片凭证）
- 30 天质量问题换货
- 定制商品不支持无理由退货（质量问题除外）

示例 1：
用户请求：3 天前买的外套，标签没拆，码数不合适
推理：
Step 1：时间 3 天 < 7 天，符合无理由退货时间
Step 2：标签未拆，商品完好
Step 3：外套非定制商品
结论：符合 7 天无理由退货
输出：{"conclusion": "符合", "reason": "3 天 < 7 天，商品完好，非定制", "next_step": "请提供订单号办理退货"}

示例 2：
用户请求：20 天前买的定制刻字钢笔，笔尖有毛刺，想换货，有照片
推理：
Step 1：时间 20 天，过 7 天无理由期，但 < 30 天质量问题换货期
Step 2：定制商品不支持无理由退货，但质量问题除外
Step 3：笔尖毛刺属质量问题，有照片凭证
结论：符合 30 天质量问题换货
输出：{"conclusion": "符合", "reason": "20 天 < 30 天，质量问题，定制商品质量问题不豁免", "next_step": "请上传照片，审核后安排换货"}

用户请求：{{user_request}}

推理：

输出 JSON：{"conclusion": "符合/不符合/需补充信息", "reason": "...", "next_step": "..."}
```

### 结果分析

#### 总体对比

| 维度 | A 版平均分 | B 版平均分 | 差值 | 显著性 |
|------|-----------|-----------|------|--------|
| 准确性 | 4.2 | 4.8 | +0.6 | 是 |
| 格式合规 | 4.5 | 5.0 | +0.5 | 是 |
| 一致性 | 4.0 | 4.8 | +0.8 | 是 |
| 总分 | 12.7 | 14.6 | +1.9 | 是 |

#### 分场景对比

| 场景类型 | A 版准确性 | B 版准确性 | B 版是否更优 |
|---------|-----------|-----------|------------|
| 简单场景（8 例） | 5.0 | 5.0 | 否（持平） |
| 中等场景（7 例） | 4.6 | 4.9 | 是（+0.3） |
| 困难场景（5 例） | 2.8 | 4.6 | 是（+1.8） |

#### 结论与建议

- **是否采用 B 版**：是
- **关键发现**：
  1. B 版在困难场景下准确性提升显著（+1.8 分），主要因为 Few-Shot 示例示范了"定制商品+质量问题"的复杂判断逻辑
  2. B 版格式合规性提升（+0.5 分），因为示例统一了"Step 1/2/3"推理格式
  3. B 版一致性提升（+0.8 分），示例约束了推理路径，减少随机性
  4. 简单场景下两版持平，B 版未引入退化
- **后续优化方向**：
  1. 增加更多困难场景示例（如"已激活电子产品+质量问题"）
  2. 测试示例数量从 2 个增加到 3 个的边际收益
  3. 在中等场景下进一步优化，缩小与简单场景的差距

## 调优建议

- 严格控制变量：每次 A/B 测试只修改一个变量，否则无法归因
- 样本量充足：至少 20 个用例，困难场景至少 5 个，否则统计不显著
- 多次运行取平均：每个用例运行 3 次取平均，减少随机性影响
- 盲评减少偏见：评估者不知哪个是 A 哪个是 B
- 关注退化：B 版在提升某维度的同时是否导致其他维度下降（如准确性提升但延迟增加）
- 渐进发布：B 版通过测试后，先灰度发布 10% 流量，观察线上指标后再全量
