# 高级 CoT 模式模板合集

本文件收录 3 个高级 CoT 模板，覆盖推理过程可见与隐藏对比（`<reasoning>` + `<answer>`）、多步条件嵌套推理、推理与结论分离，适用于复杂退换货流程判断与多商品退款金额计算场景。

---

## 模板 1：推理过程可见与隐藏对比模板

### 模板说明
- 用途：通过 XML 标签控制推理过程是否对用户可见，便于调试与生产环境切换
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_request}}`、`{{policy}}`、`{{show_reasoning}}`

### 完整模板

```
你是 SmartCS 智能客服助手，负责处理复杂退换货流程判断。请先进行内部推理，再给出最终回复。

退换货政策：
{{policy}}

用户请求：
{{user_request}}

请按以下格式输出：
<reasoning>
在这里展示你的完整推理过程：
1. 分析用户请求类型与商品信息
2. 逐条对照退换货政策
3. 判断是否符合条件并说明依据
</reasoning>
<answer>
在这里给出最终给用户的回复。
注意：当 {{show_reasoning}} 为 false 时，本标签内容不应提及推理细节，只给出结论与下一步操作建议；为 true 时，可向用户简要说明判断依据。
</answer>
```

### 使用示例

#### 输入
```
你是 SmartCS 智能客服助手，负责处理复杂退换货流程判断。请先进行内部推理，再给出最终回复。

退换货政策：
- 7 天无理由退货（商品完好）
- 15 天质量问题退货（需照片凭证）
- 30 天质量问题换货
- 定制商品不支持退换货
- 已激活的电子产品不支持无理由退货（质量问题除外）

用户请求：
我 6 天前买了一台定制刻字的平板，今天发现屏幕有坏点，想退货。

请按以下格式输出：
<reasoning>
在这里展示你的完整推理过程：
1. 分析用户请求类型与商品信息
2. 逐条对照退换货政策
3. 判断是否符合条件并说明依据
</reasoning>
<answer>
在这里给出最终给用户的回复。
注意：当 false 时，本标签内容不应提及推理细节，只给出结论与下一步操作建议；为 true 时，可向用户简要说明判断依据。
</answer>
```

#### 预期输出
```
<reasoning>
1. 分析用户请求类型与商品信息
- 请求类型：退货
- 商品：平板（电子产品，定制刻字）
- 购买时间：6 天前
- 问题描述：屏幕坏点（质量问题）
- 是否激活：未明确说明

2. 逐条对照退换货政策
- 7 天无理由退货：6 天 < 7 天，时间符合。但商品是"定制刻字"，触发"定制商品不支持退换货"。
- 15 天质量问题退货：6 天 < 15 天，屏幕坏点属于质量问题，时间与问题性质均符合。需照片凭证。
- 定制商品不支持退换货：商品为定制刻字，触发本条款。但本条款未明确"质量问题是否豁免"。
- 已激活电子产品不支持无理由退货：用户主张的是质量问题而非无理由，本条款不适用。

3. 判断是否符合条件并说明依据
- 关键冲突：定制商品不支持退换货 vs 质量问题退货
- 通常质量问题属于法定三包范围，应优先于商家自定义的"定制商品不退"条款
- 结论：建议按质量问题退货流程处理，但需补充屏幕坏点照片凭证，并交由高级客服复核定制商品的特殊处理规则
</reasoning>
<answer>
您好，关于您平板屏幕坏点的问题，我们已收到您的退货申请。

由于您的商品为定制刻字版本，情况较为特殊，需要您配合：
1. 请拍摄屏幕坏点照片（建议亮屏状态下清晰展示坏点位置）
2. 上传至本对话或工单系统

我们将在收到照片后 24 小时内由高级客服为您复核处理。质量问题属于法定三包范围，我们会依法保障您的权益。
</answer>
```

### 调优建议
- 温度建议：0.0~0.2
- 生产环境通常设置 `{{show_reasoning}}=false`，只取 `<answer>` 返回给用户
- 调试环境可设置 `{{show_reasoning}}=true`，便于审计推理链
- 注意：当政策存在冲突时（如本例定制 vs 质量问题），建议明确兜底规则，避免模型自行裁定

## 模板 2：多步条件嵌套推理模板

### 模板说明
- 用途：处理复杂退换货流程判断，含多层条件嵌套（时间→商品类型→问题类型→凭证）
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_request}}`、`{{policy}}`

### 完整模板

```
你是 SmartCS 智能客服助手，负责处理复杂的退换货流程判断。请按嵌套条件结构进行推理。

退换货政策：
{{policy}}

用户请求：
{{user_request}}

推理结构（请严格按此嵌套展开）：

Layer 1 - 时间维度判定
  ├─ 购买时间 ≤ 7 天 → 进入 Layer 2
  ├─ 7 天 < 购买时间 ≤ 15 天 → 进入 Layer 2（仅质量问题）
  ├─ 15 天 < 购买时间 ≤ 30 天 → 进入 Layer 2（仅换货/维修）
  └─ 购买时间 > 90 天 → 不支持售后

Layer 2 - 商品类型判定
  ├─ 普通商品 → 进入 Layer 3
  ├─ 定制商品 → 标记"定制特殊处理"
  ├─ 贴身衣物 → 标记"不支持无理由"
  └─ 已拆封食品 → 标记"不支持退货"

Layer 3 - 问题类型判定
  ├─ 无理由（不喜欢/码数不合适）→ 检查商品是否完好
  ├─ 质量问题 → 检查凭证完整性
  └─ 物流损坏 → 检查签收记录

Layer 4 - 凭证与状态判定
  ├─ 凭证完整 → 给出结论
  └─ 凭证缺失 → 要求补充

请逐层展开推理，每层都明确写出"判定结果"与"进入下一层的依据"，最后给出综合结论。
```

### 使用示例

#### 输入
```
你是 SmartCS 智能客服助手，负责处理复杂的退换货流程判断。请按嵌套条件结构进行推理。

退换货政策：
- 7 天无理由退货（商品完好）
- 15 天质量问题退货（需照片凭证）
- 30 天质量问题换货（需照片凭证）
- 90 天免费维修
- 定制商品不支持无理由退货（质量问题除外）
- 贴身衣物不支持退货
- 已拆封食品不支持退货

用户请求：
我 12 天前定制了一款刻字钢笔，昨天收到后发现笔尖有毛刺，写字刮纸，想换货，已经拍了照片。

请逐层展开推理，每层都明确写出"判定结果"与"进入下一层的依据"，最后给出综合结论。
```

#### 预期输出
```
Layer 1 - 时间维度判定
- 购买时间：12 天前
- 判定结果：7 天 < 12 天 ≤ 15 天，进入"仅质量问题"路径
- 进入 Layer 2 依据：时间已过 7 天无理由期，但仍在 15 天质量问题退货期内

Layer 2 - 商品类型判定
- 商品类型：定制刻字钢笔
- 判定结果：标记"定制特殊处理"。但政策明确"定制商品不支持无理由退货（质量问题除外）"，用户主张质量问题，可继续。
- 进入 Layer 3 依据：定制商品在质量问题场景下不豁免

Layer 3 - 问题类型判定
- 问题类型：笔尖毛刺、写字刮纸（质量问题）
- 判定结果：属于质量问题，需检查凭证完整性
- 进入 Layer 4 依据：质量问题路径，需照片凭证

Layer 4 - 凭证与状态判定
- 凭证：已拍照片
- 判定结果：凭证完整
- 综合结论：符合换货条件

综合结论：
- 时间：12 天，在 30 天质量问题换货期内
- 商品：定制钢笔，但质量问题不豁免
- 问题：笔尖毛刺属质量问题
- 凭证：照片已提供
- 处理方案：可办理换货。请将照片上传至工单，客服将在 24 小时内审核并安排换货。定制刻字内容将在新笔上保留。
```

### 调优建议
- 温度建议：0.0
- 嵌套层数不宜过深（建议 ≤ 4 层），否则推理链易断裂
- 当某层判定存在歧义时，建议在政策中预先明确优先级（如"质量问题优先于定制商品限制"）

## 模板 3：推理与结论分离模板

### 模板说明
- 用途：将推理过程与最终结论物理分离，便于程序化提取结论（如多商品退款金额计算）
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{order_items}}`、`{{refund_policy}}`

### 完整模板

```
你是 SmartCS 智能客服助手，负责核算多商品订单的退款金额。请先逐商品推理，再汇总输出最终退款金额。

退款政策：
{{refund_policy}}

订单商品明细：
{{order_items}}

请按以下格式输出（严格遵循标签结构，便于程序解析）：

<reasoning>
对每个商品逐一推理：
商品1：[名称]
- 实付金额：...
- 退款规则：...（说明适用的政策条款）
- 退款金额：...

商品2：[名称]
- 实付金额：...
- 退款规则：...
- 退款金额：...

汇总：
- 商品退款小计：...
- 优惠券分摊扣除：...（如适用）
- 实际退款总额：...
</reasoning>

<conclusion>
退款总额：X 元
明细：
- 商品1 [名称]：退款 Y 元（理由：...）
- 商品2 [名称]：退款 Z 元（理由：...）
</conclusion>
```

### 使用示例

#### 输入
```
你是 SmartCS 智能客服助手，负责核算多商品订单的退款金额。请先逐商品推理，再汇总输出最终退款金额。

退款政策：
- 7 天无理由退货：按实付金额全额退款
- 质量问题退货：按实付金额全额退款 + 补偿 10 元运费
- 优惠券分摊：退货商品的优惠券分摊金额需从退款中扣除
- 满减订单部分退货：按商品原价比例重新计算未退货商品实付金额

订单商品明细：
订单总价：500 元（含满 300 减 30 优惠券，实际支付 470 元）
商品A：原价 200 元，质量问题退货，已提供照片
商品B：原价 300 元，无理由退货，商品完好

请按以下格式输出（严格遵循标签结构，便于程序解析）：

<reasoning>
对每个商品逐一推理：
商品1：[名称]
- 实付金额：...
- 退款规则：...（说明适用的政策条款）
- 退款金额：...

商品2：[名称]
- 实付金额：...
- 退款规则：...
- 退款金额：...

汇总：
- 商品退款小计：...
- 优惠券分摊扣除：...（如适用）
- 实际退款总额：...
</reasoning>

<conclusion>
退款总额：X 元
明细：
- 商品1 [名称]：退款 Y 元（理由：...）
- 商品2 [名称]：退款 Z 元（理由：...）
</conclusion>
```

#### 预期输出
```
<reasoning>
对每个商品逐一推理：
商品1：商品A
- 原价：200 元
- 实付金额计算：订单实际支付 470 元，按原价比例分摊：470 × (200/500) = 188 元
- 退款规则：质量问题退货，按实付金额全额退款 + 补偿 10 元运费
- 退款金额：188 + 10 = 198 元

商品2：商品B
- 原价：300 元
- 实付金额计算：470 × (300/500) = 282 元
- 退款规则：7 天无理由退货，商品完好，按实付金额全额退款
- 退款金额：282 元

汇总：
- 商品退款小计：198 + 282 = 480 元
- 优惠券分摊扣除：满 300 减 30 优惠券，两商品均退货，优惠券无需扣除（已按比例分摊到实付金额中）
- 运费补偿：+10 元（商品A 质量问题）
- 实际退款总额：480 元
</reasoning>

<conclusion>
退款总额：480 元
明细：
- 商品1 商品A：退款 198 元（理由：质量问题退货，实付 188 元 + 运费补偿 10 元）
- 商品2 商品B：退款 282 元（理由：7 天无理由退货，实付金额全额退还）
</conclusion>
```

### 调优建议
- 温度建议：0.0，金额计算严禁随机性
- 程序解析时只读取 `<conclusion>` 标签，`<reasoning>` 留作审计日志
- 注意：满减订单部分退货的退款计算易出错，建议在政策中明确"按原价比例分摊实付金额"的算法
- 若商品数量超过 5 个，建议拆分为多次调用，避免推理链过长导致遗漏
