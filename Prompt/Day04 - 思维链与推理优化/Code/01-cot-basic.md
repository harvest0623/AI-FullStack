# CoT 基础模板合集

本文件收录 4 个思维链（Chain-of-Thought）基础模板，覆盖 Zero-Shot CoT 触发词对比、Few-Shot CoT 推理示例、分步推理结构化模板、条件判断推理模板，全部围绕 SmartCS 智能客服的真实场景。

---

## 模板 1：Zero-Shot CoT 触发词对比

### 模板说明
- 用途：对比不同 Zero-Shot CoT 触发措辞在退换货资格判断上的效果差异
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_request}}`、`{{policy}}`、`{{trigger_phrase}}`

### 完整模板

```
你是 SmartCS 智能客服助手，负责处理用户的退换货请求。

退换货政策：
{{policy}}

用户请求：
{{user_request}}

{{trigger_phrase}}
```

### 使用示例

#### 输入
```
你是 SmartCS 智能客服助手，负责处理用户的退换货请求。

退换货政策：
- 7 天内无理由退货（商品完好、不影响二次销售）
- 15 天内质量问题退货（需提供照片凭证）
- 以下情况不支持退货：定制商品、贴身衣物、已拆封的食品
- 退货时优惠券不予退还，按实际支付金额退款

用户请求：
我 5 天前买了一件外套，标签没拆，但是码数不合适，想退货。

让我们一步一步思考。
```

#### 预期输出
```
Step 1：识别商品类型与时间
- 商品：外套（非定制、非贴身衣物、非食品，属于可退货品类）
- 购买时间：5 天前

Step 2：匹配退换货政策
- 5 天 < 7 天，符合"7 天内无理由退货"政策
- 标签未拆，符合"商品完好、不影响二次销售"条件

Step 3：检查是否触发不支持退货的情形
- 外套不在不支持退货的清单内

Step 4：得出结论
- 符合 7 天无理由退货条件，可办理退货
- 退款金额按实际支付金额退还（优惠券不退还）

结论：您的退货申请符合政策，可立即办理。请提供订单号以便后续处理。
```

### 调优建议
- 推荐测试的触发措辞对照：
  - A 组：`让我们一步一步思考。`
  - B 组：`请先分析，再给出答案。`
  - C 组：`请展示你的推理过程。`
  - D 组（无触发，对照组）：留空
- 温度建议：0.0~0.3，保证政策判断的稳定性
- 注意：对照组（无触发）在复杂条件下准确率明显低于有触发的版本

## 模板 2：Few-Shot CoT 推理示例

### 模板说明
- 用途：用 Few-Shot CoT 进行折扣金额计算，统一推理格式为 "Step 1/2/3"
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{order_info}}`

### 完整模板

```
你是 SmartCS 智能客服助手，负责核算订单折扣金额。请按照示例的推理格式处理用户订单。

示例 1：
订单：商品原价 200 元，满 100 减 20 优惠券，会员 95 折
推理：
Step 1：计算优惠券抵扣。满 100 减 20，原价 200 满足条件，抵扣 20 元。
Step 2：计算优惠券后金额。200 - 20 = 180 元。
Step 3：应用会员折扣。180 × 0.95 = 171 元。
答案：应付金额 171 元。

示例 2：
订单：商品原价 80 元，满 100 减 20 优惠券（不满足），会员 95 折
推理：
Step 1：检查优惠券是否可用。原价 80 < 100，不满足满减条件，优惠券不可用。
Step 2：优惠券后金额仍为 80 元。
Step 3：应用会员折扣。80 × 0.95 = 76 元。
答案：应付金额 76 元。

订单：{{order_info}}
推理：
```

## 模板 3：分步推理结构化模板

### 模板说明
- 用途：用结构化步骤进行运费计算，含基础运费、重量附加费、偏远地区附加费
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{order_detail}}`、`{{shipping_policy}}`

### 完整模板

```
你是 SmartCS 智能客服助手，负责计算订单运费。请严格按以下步骤处理：

1. 解析订单信息：从订单中提取收货地区、商品总重量、是否保价
2. 计算基础运费：根据地区类型查表
3. 计算重量附加费：超出首重部分按每公斤加收
4. 计算保价费：如选择保价，按商品价值 5‰ 收取（最低 1 元）
5. 汇总运费：基础运费 + 重量附加费 + 保价费

运费政策：
{{shipping_policy}}

订单信息：
{{order_detail}}

请按上述步骤输出推理过程，并在最后给出"运费总计：X 元"。
```

### 使用示例

#### 输入
```
你是 SmartCS 智能客服助手，负责计算订单运费。请严格按以下步骤处理：

1. 解析订单信息：从订单中提取收货地区、商品总重量、是否保价
2. 计算基础运费：根据地区类型查表
3. 计算重量附加费：超出首重部分按每公斤加收
4. 计算保价费：如选择保价，按商品价值 5‰ 收取（最低 1 元）
5. 汇总运费：基础运费 + 重量附加费 + 保价费

运费政策：
- 首重 1kg：华东 10 元 / 华南 12 元 / 西北 20 元 / 港澳 50 元
- 续重每公斤：华东 2 元 / 华南 3 元 / 西北 6 元 / 港澳 15 元
- 保价费：商品价值 × 5‰，最低 1 元

订单信息：
收货地区：西北
商品总重量：3.5kg
是否保价：是
商品价值：800 元

请按上述步骤输出推理过程，并在最后给出"运费总计：X 元"。
```

#### 预期输出
```
Step 1 解析订单信息：
- 收货地区：西北
- 商品总重量：3.5kg
- 是否保价：是
- 商品价值：800 元

Step 2 计算基础运费：
- 西北地区首重 1kg 基础运费 20 元

Step 3 计算重量附加费：
- 超出首重重量：3.5 - 1 = 2.5kg
- 续重按 3kg 计（不足 1kg 按 1kg 计）
- 附加费：3 × 6 = 18 元

Step 4 计算保价费：
- 800 × 5‰ = 4 元（高于最低 1 元，取 4 元）

Step 5 汇总运费：
- 基础运费 20 + 附加费 18 + 保价费 4 = 42 元

运费总计：42 元
```

### 调优建议
- 温度建议：0.0
- 注意：续重不足 1kg 的进位规则需在政策中明确，否则模型可能直接按小数计算
- 若经常出现进位错误，可在示例中明确演示"2.5kg 按 3kg 计"的进位规则

## 模板 4：条件判断推理模板

### 模板说明
- 用途：多条件决策，根据退换货政策的多条规则综合判断用户是否符合退换条件
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_request}}`、`{{policy}}`

### 完整模板

```
你是 SmartCS 智能客服助手。请按"先理解问题，再分析条件，最后得出结论"的方式处理用户的退换货请求。

处理流程：
1. 理解问题：提取用户请求类型（退货/换货/维修）、商品信息、购买时间、问题描述
2. 分析条件：逐条对照退换货政策，标注每条政策是"符合 / 不符合 / 不适用"
3. 得出结论：基于条件分析判断是否符合退换货条件，并说明依据条款

退换货政策：
{{policy}}

用户请求：
{{user_request}}

请按上述流程输出，最后给出明确结论（符合 / 不符合 / 需补充信息）。
```

### 使用示例

#### 输入
```
你是 SmartCS 智能客服助手。请按"先理解问题，再分析条件，最后得出结论"的方式处理用户的退换货请求。

处理流程：
1. 理解问题：提取用户请求类型（退货/换货/维修）、商品信息、购买时间、问题描述
2. 分析条件：逐条对照退换货政策，标注每条政策是"符合 / 不符合 / 不适用"
3. 得出结论：基于条件分析判断是否符合退换货条件，并说明依据条款

退换货政策：
- 7 天无理由退货（商品完好）
- 15 天质量问题退货（需照片凭证）
- 30 天质量问题换货（需照片凭证）
- 90 天免费维修
- 定制商品不支持退换货
- 已使用商品不支持无理由退货

用户请求：
我是 10 天前买的电饭煲，今天使用时发现按键失灵，想要换货，已经拍了视频。

请按上述流程输出，最后给出明确结论（符合 / 不符合 / 需补充信息）。
```

#### 预期输出
```
1. 理解问题：
- 请求类型：换货
- 商品：电饭煲
- 购买时间：10 天前
- 问题描述：按键失灵（质量问题）
- 凭证：已拍视频

2. 分析条件：
- 7 天无理由退货：不符合（已过 7 天，且非无理由场景）
- 15 天质量问题退货：符合（10 天 < 15 天，且为质量问题，但用户要求换货而非退货）
- 30 天质量问题换货：符合（10 天 < 30 天，质量问题，有视频凭证）
- 90 天免费维修：不适用（用户要求换货而非维修）
- 定制商品不支持退换货：不适用（电饭煲非定制商品）
- 已使用商品不支持无理由退货：不适用（用户主张的是质量问题换货，非无理由退货）

3. 得出结论：
符合换货条件。依据"30 天质量问题换货"条款：购买 10 天在 30 天内，按键失灵属于质量问题，已提供视频凭证。
建议：可办理换货，请将视频凭证上传至工单，客服将在 24 小时内审核。
```

### 调优建议
- 温度建议：0.0~0.2
- 注意：当用户描述模糊时，模型可能误判"质量问题"还是"使用不当"，可在政策中增加质量问题的判定标准
- 若需要更严格的判定，可在政策中明确"视频凭证需清晰展示故障现象"
