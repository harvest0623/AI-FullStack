# 自洽性策略模板

Self-Consistency（自洽性）通过对同一问题用高温度采样生成多条 CoT 推理路径，再对最终答案投票取多数，提升高精度推理任务的准确率。本模板演示 SmartCS 客服场景下复杂退款金额计算的 3 路径投票过程。

---

## 模板说明

- 用途：对复杂退款金额计算生成多条推理路径并投票，确保结论自洽
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{order_info}}`、`{{refund_policy}}`、`{{num_paths}}`

---

## 完整模板

```
你是 SmartCS 智能客服助手，负责核算复杂订单的退款金额。为提升准确性，请使用 Self-Consistency 策略：对同一订单生成 {{num_paths}} 条独立的推理路径，再对最终答案投票取多数。

退款政策：
{{refund_policy}}

订单信息：
{{order_info}}

执行步骤：

Step 1 生成 {{num_paths}} 条独立推理路径
- 每条路径独立推理，中间步骤可不同
- 每条路径必须给出明确的"最终退款金额：X 元"

Step 2 提取每条路径的最终答案
- 列出路径1/路径2/...的最终退款金额

Step 3 投票
- 统计每个金额出现的次数
- 取出现次数最多的金额作为最终答案
- 若所有路径答案一致，置信度最高
- 若出现分歧，标注分歧原因并给出建议（如需人工复核）

请按上述步骤输出。
```

## 使用示例

### 输入

```
你是 SmartCS 智能客服助手，负责核算复杂订单的退款金额。为提升准确性，请使用 Self-Consistency 策略：对同一订单生成 3 条独立的推理路径，再对最终答案投票取多数。

退款政策：
- 7 天无理由退货：按实付金额全额退款
- 质量问题退货：按实付金额全额退款 + 补偿 10 元运费
- 优惠券分摊：退货商品的优惠券分摊金额需从退款中扣除
- 满减订单部分退货：按商品原价比例重新计算未退货商品实付金额
- 会员折扣：退款金额按实际支付金额计算，不退会员折扣差价

订单信息：
订单原价合计：599 元
优惠券：满 300 减 50（实际抵扣 50 元）
会员折扣：9 折（作用于优惠券后金额）
实际支付：(599 - 50) × 0.9 = 494.1 元
退货商品：订单内全部商品退货，其中 1 件为质量问题，其余为无理由退货

请按上述步骤输出。
```

### 预期输出

```
Step 1 生成 3 条独立推理路径

路径 1（按"质量问题主导"路径推理）：
- 退货包含质量问题商品，按政策可获运费补偿 10 元
- 订单实际支付金额 494.1 元
- 全部商品退货，按实付金额全额退款
- 优惠券分摊：全部商品退货，优惠券无需单独扣除（已体现在实付金额中）
- 退款金额 = 494.1 + 10 = 504.1 元
最终退款金额：504.1 元

路径 2（按"分项核算"路径推理）：
- 订单实际支付 494.1 元，包含 1 件质量问题商品与若干无理由退货商品
- 全部商品退货，无理由部分按实付金额全额退款
- 质量问题部分额外补偿 10 元运费
- 优惠券满 300 减 50 已使用，全部退货时优惠券不退还（用户实际未支付这 50 元），退款仍以实付金额为准
- 退款金额 = 494.1 + 10 = 504.1 元
最终退款金额：504.1 元

路径 3（按"政策优先级"路径推理）：
- 先判断退货类型：质量问题退货优先于无理由退货
- 既然订单内含质量问题商品，整单可按质量问题退货处理
- 退款 = 实付金额 + 运费补偿 = 494.1 + 10 = 504.1 元
- 验证：若按无理由退货处理（无运费补偿），退款应为 494.1 元；但质量问题补偿 10 元应叠加
最终退款金额：504.1 元

Step 2 提取每条路径的最终答案
- 路径 1：504.1 元
- 路径 2：504.1 元
- 路径 3：504.1 元

Step 3 投票
- 504.1 元：出现 3 次
- 其他金额：0 次
- 多数答案：504.1 元（3/3 一致）

置信度：高（3 条路径完全一致）

最终退款金额：504.1 元
说明：订单实付 494.1 元 + 质量问题运费补偿 10 元。建议在退款备注中注明"含质量问题运费补偿 10 元"，便于财务对账。
```

## 调优建议

- 温度建议：0.7~1.0（生成路径阶段）。高温度才能让多条路径产生差异化推理，否则只是相同推理的复述，失去投票意义
- 路径数量建议：3~5 条即可，更多路径边际收益递减而成本线性上升
- 实际工程实现：
  - 不要在一个 Prompt 里让模型"模拟"多条路径（如本示例所示），这只是一个教学演示
  - 真实生产中应：用同一 Prompt + 高温度，调用 LLM N 次，得到 N 条独立输出，再由程序提取答案并投票
- 答案提取：从每条路径中提取最终答案时，建议在 Prompt 中强制使用"最终退款金额：X 元"这样的固定格式，便于正则解析
- 分歧处理：当 N 条路径答案不一致时，应标注分歧并触发人工复核，而非简单取多数
- 成本提示：Self-Consistency 的 Token 消耗是单次 CoT 的 N 倍，建议仅在大额退款、高精度要求场景启用
