# Prompt 链式调用模板

Prompt Chaining 将复杂任务分解为多个 Prompt 步骤，前一步输出作为后一步输入。本模板演示 SmartCS 客服系统的 4 步链式调用管道：意图识别 → 路由分发 → 任务执行 → 回复生成。

---

## 模板说明

- 用途：展示 Prompt 链式调用的完整管道，包含 4 个步骤的 Prompt 与连接方式
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_message}}`、`{{faq_kb}}`、`{{policy}}`、`{{order_info}}`

---

## 管道总览

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  步骤 1       │     │  步骤 2       │     │  步骤 3       │     │  步骤 4       │
│  意图识别     │────►│  路由分发     │────►│  任务执行     │────►│  回复生成     │
│  (Prompt)    │     │  (代码逻辑)  │     │  (子 Prompt) │     │  (Prompt)    │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
     输入: user_message   输入: intent          输入: 任务数据        输入: 结构化结果
     输出: intent          输出: 子 Prompt 选择  输出: 结构化结果      输出: 用户可见回复
```

---

## 步骤 1：意图识别 Prompt

### 完整模板

```
# Role
你是 SmartCS 意图识别模块。

# Task
判断用户输入属于哪个意图：FAQ咨询 / 订单查询 / 退换货 / 投诉 / 闲聊

用户输入：{{user_message}}

# Format
输出 JSON：
{"intent": "...", "confidence": 0.0~1.0, "entities": {"order_id": "...", "product": "..."}}
仅输出 JSON，不要其他内容。
```

### 输入示例

```
用户输入：我 10 天前买的电饭煲按键失灵了，想换货，订单号 20240518。
```

### 预期输出

```json
{
  "intent": "退换货",
  "confidence": 0.95,
  "entities": {
    "order_id": "20240518",
    "product": "电饭煲",
    "issue": "按键失灵",
    "purchase_days": 10
  }
}
```

---

## 步骤 2：路由分发（代码逻辑）

本步骤为代码逻辑，不调用 LLM，根据步骤 1 输出的 `intent` 选择对应的子 Prompt：

```python
# 伪代码示例
def route(intent: str) -> str:
    routing_map = {
        "FAQ咨询": "faq_answer_prompt",
        "订单查询": "order_query_prompt",
        "退换货": "refund_guide_prompt",
        "投诉": "complaint_handle_prompt",
        "闲聊": "small_talk_prompt"
    }
    return routing_map.get(intent, "fallback_prompt")
```

本例 `intent = "退换货"`，路由到 `refund_guide_prompt`（退换货任务执行 Prompt）。

## 完整管道执行流程示例

```
输入：我 10 天前买的电饭煲按键失灵了，想换货，订单号 20240518。

[步骤 1] 意图识别 Prompt
输出：{"intent": "退换货", "confidence": 0.95, "entities": {...}}

[步骤 2] 路由分发（代码）
输入：intent=退换货
输出：选择 refund_guide_prompt

[步骤 3] 退换货任务执行 Prompt
输入：用户信息 + 退换货政策
输出：{"conclusion": "需补充信息", "next_step": "请用户上传照片凭证..."}

[步骤 4] 回复生成 Prompt
输入：步骤 3 的结构化输出
输出：您好，关于您订单 20240518 电饭煲按键失灵的问题...（自然语言回复）
```

## 调优建议

- 温度建议：
  - 步骤 1（意图识别）：0.0，需确定性
  - 步骤 3（任务执行）：0.0~0.2，需准确判断
  - 步骤 4（回复生成）：0.6~0.8，需一定创意但保持专业
- 每步独立测试：链式调用的优势在于每步可单独测试与优化，出现问题时能快速定位
- 错误传播：上游错误会向下游传播，建议在每步之间增加校验（如步骤 1 的 confidence < 0.5 时直接转人工）
- 并行化机会：若步骤 3 需要查询多个数据源（订单、物流、库存），可并行调用，再合并结果
- 缓存：步骤 1 的意图识别结果可按用户输入哈希缓存，避免重复调用
- 工程实现：推荐使用 LangChain 的 LLMChain 或 LangGraph 编排链式调用
