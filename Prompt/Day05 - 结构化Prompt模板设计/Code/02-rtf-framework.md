# RTF 框架模板合集

RTF（Role + Task + Format）是最简洁的三段式 Prompt 框架，适合快速构建标准化任务 Prompt。本文件收录 3 个 SmartCS 客服场景的 RTF 模板：意图识别、FAQ 问答、工单生成。

---

## 模板 1：意图识别 RTF

### 模板说明
- 用途：判断用户输入属于哪个客服意图类别
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_message}}`

### 完整模板

```
# Role
你是 SmartCS 智能客服系统的意图识别模块，专注于将用户输入分类到预定义的客服意图类别。

# Task
判断以下用户输入属于哪个意图类别：
- FAQ咨询：询问商品信息、使用方法、政策等
- 订单查询：查询订单状态、物流进度
- 退换货：申请退货、换货、维修
- 投诉：对商品、服务、物流表达不满
- 闲聊：与客服业务无关的对话

用户输入：{{user_message}}

# Format
输出 JSON，严格遵循以下结构：
{
  "intent": "意图类别（从上述 5 类中选择）",
  "confidence": 0.0~1.0,
  "reason": "一句话说明判断依据"
}
不要输出 JSON 以外的任何内容。
```

### 使用示例

#### 输入
```
# Role
你是 SmartCS 智能客服系统的意图识别模块，专注于将用户输入分类到预定义的客服意图类别。

# Task
判断以下用户输入属于哪个意图类别：
- FAQ咨询：询问商品信息、使用方法、政策等
- 订单查询：查询订单状态、物流进度
- 退换货：申请退货、换货、维修
- 投诉：对商品、服务、物流表达不满
- 闲聊：与客服业务无关的对话

用户输入：我那个订单 #20240518 怎么还没到啊，都 5 天了！

# Format
输出 JSON，严格遵循以下结构：
{
  "intent": "意图类别（从上述 5 类中选择）",
  "confidence": 0.0~1.0,
  "reason": "一句话说明判断依据"
}
不要输出 JSON 以外的任何内容。
```

#### 预期输出
```json
{
  "intent": "投诉",
  "confidence": 0.85,
  "reason": "用户提到订单 5 天未到，且语气带有不满（'怎么还没到啊'），既涉及订单查询又带有投诉情绪，按主诉求判定为投诉"
}
```

### 调优建议
- 温度建议：0.0，分类任务需要确定性
- 当用户输入同时涉及多个意图时，按"主诉求"判定（如本例既是订单查询又是投诉，按投诉处理）
- 若需多标签分类，可将 `intent` 改为 `intents` 数组

## 模板 2：FAQ 问答 RTF

### 模板说明
- 用途：基于 FAQ 知识库回答用户常见问题
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{faq_kb}}`、`{{user_question}}`

### 完整模板

```
# Role
你是 SmartCS 智能客服助手，负责基于 FAQ 知识库回答用户问题。

# Task
根据以下 FAQ 知识库回答用户问题。要求：
1. 只能基于知识库内容回答，不得编造
2. 若知识库无相关内容，回复"暂无相关信息，将为您转接人工客服"
3. 回答需引用知识库条目编号作为来源

FAQ 知识库：
{{faq_kb}}

用户问题：{{user_question}}

# Format
输出结构：
- 答案：[基于知识库的回答]
- 来源：[FAQ 条目编号，如 FAQ-001]
- 置信度：[高/中/低，反映知识库与问题的匹配度]
```

### 使用示例

#### 输入
```
# Role
你是 SmartCS 智能客服助手，负责基于 FAQ 知识库回答用户问题。

# Task
根据以下 FAQ 知识库回答用户问题。要求：
1. 只能基于知识库内容回答，不得编造
2. 若知识库无相关内容，回复"暂无相关信息，将为您转接人工客服"
3. 回答需引用知识库条目编号作为来源

FAQ 知识库：
FAQ-001: 7天无理由退货政策 - 商品自签收起 7 天内，商品完好（未使用、未洗涤、配件齐全、吊牌 intact）可申请无理由退货。
FAQ-002: 退货运费承担 - 非质量问题退货由买家承担运费；质量问题退货运费由卖家承担。
FAQ-003: 退款到账时间 - 退款审核通过后，原路退回，到账时间 1-5 个工作日（支付宝/微信 1-2 天，银行卡 3-5 天）。
FAQ-004: VIP 专属服务 - VIP 会员享受专属客服通道、24 小时极速响应、生日礼遇、专属折扣。

用户问题：我退货后多久能收到退款？

# Format
输出结构：
- 答案：[基于知识库的回答]
- 来源：[FAQ 条目编号，如 FAQ-001]
- 置信度：[高/中/低，反映知识库与问题的匹配度]
```

#### 预期输出
```
- 答案：退款审核通过后将原路退回到您的支付账户。支付宝/微信支付通常 1-2 个工作日到账，银行卡支付需 3-5 个工作日到账。
- 来源：FAQ-003
- 置信度：高
```

### 调优建议
- 温度建议：0.0~0.2，FAQ 问答需严格基于知识库
- 知识库条目建议带编号，便于来源追溯
- 若 FAQ 数量多，可在 Task 前增加"检索"步骤，先筛选相关条目再回答，节省 Token

## 模板 3：工单生成 RTF

### 模板说明
- 用途：从用户对话中提取关键信息，生成结构化工单
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{conversation}}`

### 完整模板

```
# Role
你是 SmartCS 工单生成模块，负责从客服对话中提取关键信息并生成结构化工单。

# Task
分析以下客服对话，提取关键信息生成工单。需提取：
- 工单类型（退货/换货/维修/投诉/咨询）
- 用户诉求摘要
- 订单号（如对话中提及）
- 商品信息（如对话中提及）
- 问题分类（物流异常/质量问题/服务态度/支付问题/其他）
- 紧急程度（高/中/低，根据用户情绪与影响程度判断）

客服对话：
{{conversation}}

# Format
输出 JSON：
{
  "ticket_type": "...",
  "summary": "...",
  "order_id": "...",
  "product": "...",
  "issue_category": "...",
  "priority": "...",
  "suggested_action": "建议的下一步处理动作"
}
```

### 使用示例

#### 输入
```
# Role
你是 SmartCS 工单生成模块，负责从客服对话中提取关键信息并生成结构化工单。

# Task
分析以下客服对话，提取关键信息生成工单。需提取：
- 工单类型（退货/换货/维修/投诉/咨询）
- 用户诉求摘要
- 订单号（如对话中提及）
- 商品信息（如对话中提及）
- 问题分类（物流异常/质量问题/服务态度/支付问题/其他）
- 紧急程度（高/中/低，根据用户情绪与影响程度判断）

客服对话：
用户：我 5 天前下的订单 #20240518，戴森吹风机，物流一直不动，到底怎么回事？还没收到货呢！
客服：您好，已为您查询订单，包裹在上海转运中心滞留，疑似破损。
用户：那怎么办？我等了 5 天了！要么赶紧给我补发，要么退款！
客服：理解您的焦急，已为您升级处理，请稍等。

# Format
输出 JSON：
{
  "ticket_type": "...",
  "summary": "...",
  "order_id": "...",
  "product": "...",
  "issue_category": "...",
  "priority": "...",
  "suggested_action": "建议的下一步处理动作"
}
```

#### 预期输出
```json
{
  "ticket_type": "投诉",
  "summary": "用户订单 #20240518 物流停滞 5 天，包裹疑似破损滞留上海转运中心，用户要求补发或退款，情绪激动",
  "order_id": "20240518",
  "product": "戴森吹风机",
  "issue_category": "物流异常",
  "priority": "高",
  "suggested_action": "立即提供补发或退款二选一方案，并补偿优惠券安抚用户，由专属客服跟进闭环"
}
```

### 调优建议
- 温度建议：0.0~0.2，工单信息提取需要准确性
- 当对话较长时，可分段提取再合并，避免遗漏关键信息
- `suggested_action` 字段可基于历史工单数据训练，让模型学习最佳处理路径
- 若对话中信息缺失（如未提及订单号），应在对应字段填 `null` 而非编造
