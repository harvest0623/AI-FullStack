# 示例选择策略对比

> 本文件以 SmartCS 客服意图分类为场景，展示不同示例选择策略的效果差异：数量对比（1 vs 3 vs 5）/ 顺序对比 / 多样性对比 / 代表性对比。每个策略给出正反两组示例对比，帮助你理解"示例怎么选"比"示例多少"更重要。

---

## 测试任务

统一任务：将用户消息分类为 `faq / order_query / refund / complaint` 四类，输出 JSON `{"intent": "..."}`。

测试输入（贯穿全文）：
```
买的耳机有杂音，订单 SO20240501，赶紧退钱
```
正确答案：`{"intent": "refund"}`

---

## 策略一：数量对比（1 vs 3 vs 5）

### 1.1 一个示例（One-Shot）

```
你是 SmartCS 意图识别模块。类别：faq / order_query / refund / complaint。

输入：耳机坏了要退钱
输出：{"intent": "refund"}

输入：买的耳机有杂音，订单 SO20240501，赶紧退钱
输出：
```

**预期输出**：`{"intent": "refund"}` ✅

**评价**：一个示例主要示范了格式，对当前输入恰好够用。但如果输入是其他类别（如投诉），单一样例无法覆盖，模型可能套用 refund。

---

### 1.2 三个示例（推荐）

```
你是 SmartCS 意图识别模块。类别：faq / order_query / refund / complaint。

输入：退货流程是什么？
输出：{"intent": "faq"}

输入：我的单子到哪了
输出：{"intent": "order_query"}

输入：耳机坏了要退钱
输出：{"intent": "refund"}

输入：买的耳机有杂音，订单 SO20240501，赶紧退钱
输出：
```

**预期输出**：`{"intent": "refund"}` ✅

**评价**：3 个示例覆盖 3 类，格式清晰，token 成本适中。**这是性价比最高的数量。**

---

### 1.3 五个示例（过多）

```
你是 SmartCS 意图识别模块。类别：faq / order_query / refund / complaint。

输入：退货流程是什么？
输出：{"intent": "faq"}

输入：保修期多久？
输出：{"intent": "faq"}

输入：我的单子到哪了
输出：{"intent": "order_query"}

输入：查下订单 SO123
输出：{"intent": "order_query"}

输入：耳机坏了要退钱
输出：{"intent": "refund"}

输入：买的耳机有杂音，订单 SO20240501，赶紧退钱
输出：
```

**预期输出**：`{"intent": "refund"}` ✅（但与 3 个示例结果相同）

**评价**：结果未提升，但 token 成本增加约 60%，且 complaint 类别未覆盖。**边际收益递减，不推荐。**

### 数量对比结论

| 数量 | 效果 | Token 成本 | 推荐 |
|------|------|-----------|------|
| 1 | 格式示范为主，类别覆盖差 | 低 | 简单任务 |
| 3 | 类别覆盖好，性价比最高 | 中 | ✅ 推荐 |
| 5 | 效果与 3 相当甚至更差 | 高 | 不推荐 |

> 关键：**覆盖所有类别比堆数量重要**。4 类任务用 4 个示例（每类 1 个）通常最优。

## 策略二：顺序对比

同样的 3 个示例，不同顺序对输出的影响。

### 2.1 差顺序：相似示例不在最后

```
你是 SmartCS 意图识别模块。类别：faq / order_query / refund / complaint。

输入：退货流程是什么？
输出：{"intent": "faq"}

输入：我的单子到哪了
输出：{"intent": "order_query"}

输入：耳机坏了要退钱
输出：{"intent": "refund"}

输入：我要投诉你们客服态度差
输出：{"intent": "complaint"}

输入：买的耳机有杂音，赶紧退钱
输出：
```

**预期输出**：`{"intent": "complaint"}` ❌（被最后的 complaint 示例带偏）

**问题**：近因效应使模型受最后一个示例影响大。当前输入是 refund，但最后示例是 complaint，可能误判。

---

### 2.2 好顺序：与当前输入相似的示例放最后

```
你是 SmartCS 意图识别模块。类别：faq / order_query / refund / complaint。

输入：退货流程是什么？
输出：{"intent": "faq"}

输入：我要投诉你们客服态度差
输出：{"intent": "complaint"}

输入：我的单子到哪了
输出：{"intent": "order_query"}

输入：耳机坏了要退钱
输出：{"intent": "refund"}

输入：买的耳机有杂音，赶紧退钱
输出：
```

**预期输出**：`{"intent": "refund"}` ✅

**改进点**：把与当前输入最相似的 refund 示例放在最后（近因效应），模型更易正确归纳。

### 顺序对比结论

| 顺序策略 | 效果 |
|---------|------|
| 相似示例在中间/开头 | 易被后续示例覆盖，误判率高 |
| 相似示例在最后（近因） | 模型聚焦正确模式，准确率高 |

> 关键：**利用近因效应**，把与当前输入最相似的示例放最后。动态场景下可用检索找最相似示例放末尾。

## 策略三：多样性对比

### 3.1 差：示例缺乏多样性（全 refund）

```
你是 SmartCS 意图识别模块。类别：faq / order_query / refund / complaint。

输入：耳机坏了要退款
输出：{"intent": "refund"}

输入：要求退钱
输出：{"intent": "refund"}

输入：给我退货
输出：{"intent": "refund"}

输入：买的耳机有杂音，订单 SO20240501
输出：
```

**预期输出**：`{"intent": "refund"}` ❌（无论输入是什么，模型都会倾向 refund）

**问题**：示例全是 refund，模型归纳出"输出永远是 refund"的错误模式，产生类别偏差。

---

### 3.2 好：示例覆盖多类别

```
你是 SmartCS 意图识别模块。类别：faq / order_query / refund / complaint。

输入：退货流程是什么？
输出：{"intent": "faq"}

输入：我的单子到哪了
输出：{"intent": "order_query"}

输入：耳机坏了要退钱
输出：{"intent": "refund"}

输入：你们客服态度太差，投诉！
输出：{"intent": "complaint"}

输入：买的耳机有杂音，订单 SO20240501
输出：
```

**预期输出**：`{"intent": "refund"}` ✅（正确，因输入含"杂音"暗示质量问题）

**改进点**：4 个示例覆盖 4 个类别，模型学会了"按内容区分"而非"无脑输出某一类"。

### 多样性对比结论

| 多样性 | 效果 |
|--------|------|
| 低（全同类） | 严重类别偏差，输出单一 |
| 高（覆盖各类别） | 模型学会区分，准确率高 |

> 关键：**示例必须覆盖所有候选类别**，否则模型会偏向数量最多的那一类。

## 策略四：代表性对比

### 4.1 差：选了非典型特殊案例

```
你是 SmartCS 意图识别模块。类别：faq / order_query / refund / complaint。

输入：我是小明，昨天下午 3 点用手机下单的蓝牙耳机，型号 XX-001，黑色，想问问这个能不能退货
输出：{"intent": "faq"}

输入：SO20240501-001 这个单子走顺丰还是圆通，我下周一不在家
输出：{"intent": "order_query"}

输入：买的耳机有杂音，订单 SO20240501
输出：
```

**预期输出**：可能 `{"intent": "faq"}` 或 `{"intent": "order_query"}` ❌

**问题**：示例输入过长且含大量无关信息（姓名、时间、颜色），模型难以归纳"什么特征对应什么类别"，特殊案例误导了模式学习。

---

### 4.2 好：选了典型代表案例

```
你是 SmartCS 意图识别模块。类别：faq / order_query / refund / complaint。

输入：退货流程是什么？
输出：{"intent": "faq"}

输入：我的订单到哪了？
输出：{"intent": "order_query"}

输入：耳机坏了要退款
输出：{"intent": "refund"}

输入：投诉客服态度差
输出：{"intent": "complaint"}

输入：买的耳机有杂音，订单 SO20240501
输出：
```

**预期输出**：`{"intent": "refund"}` ✅

**改进点**：示例简短典型，每条直击一个类别的核心特征，模型易归纳"提到退款→refund，提到订单状态→order_query"。

### 代表性对比结论

| 代表性 | 效果 |
|--------|------|
| 低（特殊/冗长案例） | 模型抓不住特征，泛化差 |
| 高（简短典型案例） | 模型易归纳核心特征，泛化好 |

> 关键：**示例应选最能体现类别特征的典型表述**，避免冗长、含噪的特殊案例。

## 策略五：一致性对比（附赠）

### 5.1 差：格式不一致

```
输入：退货流程是什么？
输出：faq

输入：我的单子到哪了
分类：order_query

输入：耳机坏了要退钱
输出：{"intent": "refund"}

输入：买的耳机有杂音
输出：
```

**问题**：三个示例用了三种格式（纯文本 / "分类：" / JSON），模型困惑，输出格式不可预测。

### 5.2 好：格式统一

```
输入：退货流程是什么？
输出：{"intent": "faq"}

输入：我的单子到哪了
输出：{"intent": "order_query"}

输入：耳机坏了要退钱
输出：{"intent": "refund"}

输入：买的耳机有杂音
输出：
```

**改进点**：所有示例统一 JSON 格式，输出 100% 一致。

> 关键：**示例格式必须完全统一**，这是 Few-Shot 格式控制的基础。

## 示例选择策略总结表

| 策略 | 差的做法 | 好的做法 |
|------|---------|---------|
| 数量 | 堆 5 个以上 | 3-4 个，覆盖所有类别 |
| 顺序 | 相似示例在中间 | 相似示例放最后 |
| 多样性 | 全是同一类 | 覆盖每个类别至少 1 个 |
| 代表性 | 冗长特殊案例 | 简短典型案例 |
| 一致性 | 格式五花八门 | 格式完全统一 |
| 质量 | 含错误标注 | 示例正确无误 |

## 最佳实践：动态示例选择（进阶）

生产环境中，可结合向量检索动态选择示例：

```python
def build_few_shot_prompt(user_input, example_pool, embed_model):
    """根据当前输入动态检索最相似的 3 个示例"""
    # 1. 对 example_pool 中每个示例的输入做 embedding
    # 2. 对 user_input 做 embedding
    # 3. 检索最相似的 3 个，按相似度升序排列（最相似放最后）
    # 4. 拼接成 few-shot prompt
    similar_examples = retrieve_top_k(user_input, example_pool, k=3, embed_model=embed_model)
    examples = "\n\n".join([f"输入：{e.input}\n输出：{e.output}" for e in similar_examples[:-1]])
    last = similar_examples[-1]
    prompt = f"""你是 SmartCS 意图识别模块。类别：faq / order_query / refund / complaint。

{examples}

输入：{last.input}
输出：{last.output}

输入：{user_input}
输出："""
    return prompt
```

> 动态选择能让每个输入都获得最相关的示例，显著提升准确率，是 Few-Shot 在生产环境的进阶用法。

---

## 总结

> 核心心法：**示例选择 > 示例数量**。3 个精心选择的典型示例，胜过 10 个随意堆砌的示例。
>
> 选择口诀：**覆盖全类别、选典型案例、相似放最后、格式必统一**。
