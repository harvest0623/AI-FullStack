# 少样本 Prompt 模板合集

> 本文件提供 5 个少样本（Few-Shot）Prompt 模板，与 `01-zero-shot.md` 一一对应：情感分类 / 意图识别 / 商品推荐 / FAQ 问答 / 工单摘要。每个模板加入 Few-Shot 示例，并与零样本版本对比输出质量差异，直观展示 In-Context Learning 的价值。

---

## 模板 1：情感分类少样本

### 模板说明
- 用途：判断用户消息情感倾向，含反讽等复杂情况
- 适用模型：通用
- 变量：`{{user_message}}`

### 完整模板
```
你是 SmartCS 客服的情感分析模块。请判断用户消息的情感倾向，输出"正面/负面/中性"。

示例：
输入：耳机音质超棒，爱了！
输出：正面

输入：用了一天就坏，什么垃圾质量
输出：负面

输入：音质不错但续航短，整体还行
输出：中性

输入：好得很，用一次就坏了，真"优秀"
输出：负面

输入：{{user_message}}
输出：
```

### 使用示例
#### 输入
```
你是 SmartCS 客服的情感分析模块。请判断用户消息的情感倾向，输出"正面/负面/中性"。

示例：
输入：耳机音质超棒，爱了！
输出：正面

输入：用了一天就坏，什么垃圾质量
输出：负面

输入：音质不错但续航短，整体还行
输出：中性

输入：好得很，用一次就坏了，真"优秀"
输出：负面

输入：客服态度挺好的，就是问题没解决，再看看吧
输出：
```

#### 预期输出
```
中性
```

### 与零样本对比
| 输入 | 零样本输出 | 少样本输出 |
|------|-----------|-----------|
| 好得很，用一次就坏了 | 正面（误判反讽） | 负面（正确） |
| 客服态度好但问题没解决 | 正面（只看前半句） | 中性（正确） |

**质量差异**：少样本通过反签示例教会模型识别反讽，准确率显著提升。

### 调优建议
- 温度建议：0
- 示例覆盖正面/负面/中性/反讽四类，多样性好
- 反签示例是 Few-Shot 的关键价值，零样本几乎无法处理

## 模板 2：意图识别少样本

### 模板说明
- 用途：识别用户意图，含跨意图与口语化输入
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_message}}`

### 完整模板
```
你是 SmartCS 意图识别模块。请对用户消息分类，类别：faq / order_query / refund / complaint。

示例：
输入：退货流程是什么？
输出：{"intent": "faq", "confidence": 0.95}

输入：我的单子到哪了
输出：{"intent": "order_query", "confidence": 0.9}

输入：耳机坏了必须退钱！
输出：{"intent": "refund", "confidence": 0.9}

输入：你们客服什么态度，我要投诉！
输出：{"intent": "complaint", "confidence": 0.95}

输入：{{user_message}}
输出：
```

### 使用示例
#### 输入
```
你是 SmartCS 意图识别模块。请对用户消息分类，类别：faq / order_query / refund / complaint。

示例：
输入：退货流程是什么？
输出：{"intent": "faq", "confidence": 0.95}

输入：我的单子到哪了
输出：{"intent": "order_query", "confidence": 0.9}

输入：耳机坏了必须退钱！
输出：{"intent": "refund", "confidence": 0.9}

输入：你们客服什么态度，我要投诉！
输出：{"intent": "complaint", "confidence": 0.95}

输入：买的耳机有杂音，订单 SO20240501，赶紧给我退钱，不然投诉你们
输出：
```

#### 预期输出
```json
{"intent": "refund", "confidence": 0.85}
```

### 与零样本对比
| 输入 | 零样本输出 | 少样本输出 |
|------|-----------|-----------|
| 买的耳机有杂音...退钱...投诉你们 | complaint（被"投诉"误导） | refund（识别核心诉求是退款） |
| 我的单子到哪了 | faq（误判为咨询） | order_query（正确） |

**质量差异**：少样本教会模型区分"核心诉求"与"附带情绪"，跨意图输入更稳定；且输出 JSON 格式 100% 一致。

### 调优建议
- 温度建议：0
- 示例覆盖 4 类意图，且包含口语化表述，代表性好
- 跨意图输入建议在示例中标注"以核心诉求为准"

## 模板 3：商品推荐少样本

### 模板说明
- 用途：根据用户需求推荐商品，输出格式严格统一
- 适用模型：通用
- 变量：`{{user_need}}`、`{{candidates}}`

### 完整模板
```
你是 SmartCS 导购助手。根据用户需求从候选商品中推荐 1 款，按指定格式输出。

示例：
需求：预算 500 内，跑步用耳机
候选：EarA 199 无降噪 / EarB 399 有降噪 / EarC 499 防水
输出：
商品名：EarC
理由：499 元符合预算，防水特性适合跑步场景。

需求：预算 200 内，通勤降噪
候选：EarA 199 无降噪 / EarB 299 有降噪
输出：
商品名：EarA
理由：预算内唯一选项，虽无降噪但价格最低，满足预算约束。

需求：{{user_need}}
候选：{{candidates}}
输出：
```

### 使用示例
#### 输入
```
你是 SmartCS 导购助手。根据用户需求从候选商品中推荐 1 款，按指定格式输出。

示例：
需求：预算 500 内，跑步用耳机
候选：EarA 199 无降噪 / EarB 399 有降噪 / EarC 499 防水
输出：
商品名：EarC
理由：499 元符合预算，防水特性适合跑步场景。

需求：预算 200 内，通勤降噪
候选：EarA 199 无降噪 / EarB 299 有降噪
输出：
商品名：EarA
理由：预算内唯一选项，虽无降噪但价格最低，满足预算约束。

需求：预算 300 内，想要降噪，续航久
候选：EarA 199 无降噪 8h / EarB 299 有降噪 12h / EarC 399 有降噪 10h
输出：
```

#### 预期输出
```
商品名：EarB
理由：299 元符合预算，有降噪且续航 12h 最长，两项需求均满足。
```

### 与零样本对比
| 维度 | 零样本 | 少样本 |
|------|--------|--------|
| 格式一致性 | 偶尔输出多余解释 | 100% 遵循"商品名+理由"格式 |
| 约束遵循 | 有时推荐超预算机型 | 严格遵循预算约束 |
| 推理逻辑 | 较随意 | 模仿示例的"逐项需求匹配"逻辑 |

**质量差异**：少样本通过示例示范了"逐需求匹配"的推理方式，且格式完全统一，便于程序解析。

### 调优建议
- 温度建议：0.3
- 示例展示了"预算冲突时如何取舍"的边界情况，提升泛化能力
- 可增加 1 个"无合适商品"的示例教模型拒绝推荐

## 模板 4：FAQ 问答少样本

### 模板说明
- 用途：依据 FAQ 回答，处理多跳问题与无答案情况
- 适用模型：通用
- 变量：`{{faq_content}}`、`{{user_question}}`

### 完整模板
```
你是 SmartCS 客服。仅根据 FAQ 知识库回答，不编造，无答案时转人工。

FAQ 知识库：
"""
{{faq_content}}
"""

示例：
问题：退货要钱吗？
回答：非质量问题退货由买家承担运费；质量问题由卖家承担。

问题：保修期多久，电池算吗？
回答：主机保修 1 年，电池保修 6 个月，人为损坏不保修。

问题：你们支持货到付款吗？
回答：该问题暂未收录，已转人工。

问题：{{user_question}}
回答：
```

### 使用示例
#### 输入
```
你是 SmartCS 客服。仅根据 FAQ 知识库回答，不编造，无答案时转人工。

FAQ 知识库：
"""
Q: 退货时效？ A: 7 天无理由，15 天质量问题。
Q: 运费谁付？ A: 质量问题卖家付，非质量问题买家付。
"""

示例：
问题：退货要钱吗？
回答：非质量问题退货由买家承担运费；质量问题由卖家承担。

问题：保修期多久，电池算吗？
回答：该问题暂未收录，已转人工。

问题：我收货 10 天了，耳机有杂音能退吗？运费谁出？
回答：
```

#### 预期输出
```
耳机杂音属质量问题，15 天内可退货。质量问题退货运费由卖家承担。
```

### 与零样本对比
| 维度 | 零样本 | 少样本 |
|------|--------|--------|
| 多跳问题 | 可能只回答一半 | 综合多条 FAQ 完整回答 |
| 无答案处理 | 有时编造答案 | 严格按示例转人工 |
| 回答风格 | 不稳定 | 与示例风格一致 |

**质量差异**：少样本示范了"多跳问题合并回答"与"无答案转人工"两种模式，幻觉率显著降低。

### 调优建议
- 温度建议：0.2
- 示例包含"无答案"情况，教会模型拒绝编造
- FAQ 条目多时，示例应覆盖不同类型的问题

## 模板 5：工单摘要少样本

### 模板说明
- 用途：将客服对话压缩为结构化工单摘要
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{conversation}}`

### 完整模板
```
你是 SmartCS 工单生成模块。请将客服对话压缩为工单摘要，保留订单号、诉求、进度、待办。

示例：
对话：
用户：订单 SO20240500 没收到货。
客服：已查询，物流延迟，预计明天到。
摘要：
- 订单：SO20240500
- 诉求：催发货/物流查询
- 进度：物流延迟，预计明日送达
- 待办：明日跟踪送达情况

对话：
用户：耳机右耳没声音，SO20240502，要换货。
客服：请提供照片。用户：[照片]
客服：已登记换货，3 天内寄出新机。
摘要：
- 订单：SO20240502
- 诉求：右耳无声音，申请换货
- 进度：已登记换货，3 天内寄出
- 待办：跟进新机寄出与签收

对话：
{{conversation}}
摘要：
```

### 使用示例
#### 输入
```
你是 SmartCS 工单生成模块。请将客服对话压缩为工单摘要，保留订单号、诉求、进度、待办。

示例：
对话：
用户：订单 SO20240500 没收到货。
客服：已查询，物流延迟，预计明天到。
摘要：
- 订单：SO20240500
- 诉求：催发货/物流查询
- 进度：物流延迟，预计明日送达
- 待办：明日跟踪送达情况

对话：
用户：耳机右耳没声音，SO20240502，要换货。
客服：请提供照片。用户：[照片]
客服：已登记换货，3 天内寄出新机。
摘要：
- 订单：SO20240502
- 诉求：右耳无声音，申请换货
- 进度：已登记换货，3 天内寄出
- 待办：跟进新机寄出与签收

对话：
用户：耳机左耳有杂音，订单 SO20240501，要求退款。
客服：请提供商品照片。
用户：[发送照片] 左耳明显杂音。
客服：照片已收到，提交退款工单，1-3 工作日到账。
用户：好的，请尽快。
摘要：
```

#### 预期输出
```
- 订单：SO20240501
- 诉求：左耳杂音，申请退款
- 进度：已提交退款工单，照片已上传
- 待办：跟进 1-3 工作日退款到账情况
```

### 与零样本对比
| 维度 | 零样本 | 少样本 |
|------|--------|--------|
| 字段完整性 | 偶尔遗漏"待办" | 4 个字段齐全 |
| 信息提取 | 长对话易遗漏照片等细节 | 关键细节均保留 |
| 格式一致性 | 有时输出段落式摘要 | 严格按列表格式 |

**质量差异**：少样本示范了统一的四字段格式与"待办"提取逻辑，输出可直接对接工单系统。

### 调优建议
- 温度建议：0.2
- 示例覆盖"物流查询"与"换货"两种场景，多样性好
- 若需程序解析，可将输出改为 JSON 格式

## 零样本 vs 少样本总览对比

| 模板 | 零样本表现 | 少样本提升点 |
|------|-----------|-------------|
| 情感分类 | 反讽误判 | 学会识别反讽 |
| 意图识别 | 跨意图不稳 | 区分核心诉求与情绪 |
| 商品推荐 | 格式不统一 | 格式 100% 一致 |
| FAQ 问答 | 多跳遗漏 | 完整合并回答 |
| 工单摘要 | 字段缺失 | 四字段齐全 |

> 核心结论：**简单任务零样本够用，复杂/格式敏感/领域特定任务必须用少样本**。Few-Shot 的核心价值是格式控制与模式归纳，而非"教模型新知识"。
