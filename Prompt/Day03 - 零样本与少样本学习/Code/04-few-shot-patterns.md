# 少样本常见模式合集

> 本文件提供 Few-Shot 四大常见模式的完整模板：分类模式（客服工单分类）/ 抽取模式（提取订单信息）/ 转换模式（用户消息转 JSON）/ 生成模式（根据工单生成回复话术）。每种模式含 3 个示例与可复用的完整模板。

---

## 模式一：分类模式

### 模板说明
- 用途：将用户消息分类到固定类别（文本 → 类别）
- 适用模型：通用
- 变量：`{{user_message}}`

### 完整模板
```
你是 SmartCS 工单分类模块。请将用户消息分类到以下类别之一：
- after_sale：售后退换货
- logistics：物流咨询
- product：商品咨询
- complaint：投诉建议
- other：其他（非售后话题）

示例：
输入：耳机用了三天就有杂音，要退货
输出：after_sale

输入：我的快递到哪了
输出：logistics

输入：这款手机支持 5G 吗
输出：product

输入：你们客服回复太慢了，投诉！
输出：complaint

输入：今天天气真好
输出：other

输入：{{user_message}}
输出：
```

## 模式二：抽取模式

### 模板说明
- 用途：从用户消息中提取结构化信息（文本 → 结构化数据）
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_message}}`

### 完整模板
```
你是 SmartCS 订单信息抽取模块。请从用户消息中提取订单相关信息，以 JSON 输出。

字段说明：
- order_id：订单号（无则填 null）
- product：商品名称（无则填 null）
- issue：问题描述（无则填 null）
- action：用户期望动作（退款/换货/维修/咨询/其他）

示例：
输入：我买的无线蓝牙耳机，订单 SO20240501，左耳有杂音，要退款
输出：{"order_id": "SO20240501", "product": "无线蓝牙耳机", "issue": "左耳有杂音", "action": "退款"}

输入：订单 SO20240502 的手机壳什么时候发货
输出：{"order_id": "SO20240502", "product": "手机壳", "issue": null, "action": "咨询"}

输入：买的充电宝充不进电，要换货
输出：{"order_id": null, "product": "充电宝", "issue": "充不进电", "action": "换货"}

输入：{{user_message}}
输出：
```

### 使用示例
#### 输入
```

字段说明：
- order_id：订单号（无则填 null）
- product：商品名称（无则填 null）
- issue：问题描述（无则填 null）
- action：用户期望动作（退款/换货/维修/咨询/其他）

输入：我买的无线蓝牙耳机，订单 SO20240501，左耳有杂音，要退款
```

```json
{"order_id": "SO20240503", "product": "智能手表", "issue": "屏幕有划痕", "action": "换货"}
```

- 字段较多时建议用 JSON Schema 严格约束

## 模式三：转换模式

### 模板说明
- 用途：将用户自然语言消息转换为结构化 JSON 工单（A 格式 → B 格式）
- 适用模型：GPT-4 / Claude / 通用
- 变量：`{{user_message}}`

### 完整模板
```
你是 SmartCS 工单生成模块。请将用户自然语言消息转换为结构化 JSON 工单。

输出 JSON Schema：
{
  "ticket_type": "退款/换货/维修/咨询",
  "priority": "高/中/低",
  "order_id": "string 或 null",
  "description": "问题描述，不超过 50 字",
  "suggested_action": "建议处理动作，不超过 30 字"
}

示例：
输入：耳机左耳没声音，订单 SO20240501，赶紧给我处理
输出：{"ticket_type": "维修", "priority": "高", "order_id": "SO20240501", "description": "左耳无声音，影响使用", "suggested_action": "引导提供视频证据后走换货"}

输入：买的手机壳颜色发错了，要换对的
输出：{"ticket_type": "换货", "priority": "中", "order_id": null, "description": "手机壳颜色发错", "suggested_action": "核实订单颜色后重新寄出"}

输入：退货流程是什么
输出：{"ticket_type": "咨询", "priority": "低", "order_id": null, "description": "咨询退货流程", "suggested_action": "发送退货流程说明"}

输入：{{user_message}}
输出：
```

### 使用示例
#### 输入
```
你是 SmartCS 工单生成模块。请将用户自然语言消息转换为结构化 JSON 工单。

输出 JSON Schema：
{
  "ticket_type": "退款/换货/维修/咨询",
  "priority": "高/中/低",
  "order_id": "string 或 null",
  "description": "问题描述，不超过 50 字",
  "suggested_action": "建议处理动作，不超过 30 字"
}

示例：
输入：耳机左耳没声音，订单 SO20240501，赶紧给我处理
输出：{"ticket_type": "维修", "priority": "高", "order_id": "SO20240501", "description": "左耳无声音，影响使用", "suggested_action": "引导提供视频证据后走换货"}

输入：买的手机壳颜色发错了，要换对的
输出：{"ticket_type": "换货", "priority": "中", "order_id": null, "description": "手机壳颜色发错", "suggested_action": "核实订单颜色后重新寄出"}

输入：退货流程是什么
输出：{"ticket_type": "咨询", "priority": "低", "order_id": null, "description": "咨询退货流程", "suggested_action": "发送退货流程说明"}

输入：充电宝用了半个月充不进电，订单 SO20240510，必须退款
输出：
```

#### 预期输出
```json
{"ticket_type": "退款", "priority": "高", "order_id": "SO20240510", "description": "充电宝充不进电，使用半月故障", "suggested_action": "确认质量问题后走退款流程"}
```

### 调优建议
- 温度建议：0
- 示例覆盖 4 种 ticket_type，且包含 order_id 缺失的情况
- 转换模式核心：给明确的目标 Schema + 多种类型的完整示例
- 输出必须为合法 JSON，可配合 `response_format` 强制

## 模式四：生成模式

### 模板说明
- 用途：根据工单信息生成客服回复话术（描述 → 内容）
- 适用模型：通用
- 变量：`{{ticket_info}}`

### 完整模板
```
你是 SmartCS 客服话术生成模块。请根据工单信息生成一段专业、有同理心的回复话术。

要求：
- 先共情，再说明处理方案，最后给时间节点
- 不超过 100 字
- 语气专业温和，不使用"亲亲""宝宝"

示例：
工单：{"type": "退款", "order_id": "SO20240501", "issue": "耳机杂音", "priority": "高"}
回复：很抱歉耳机出现杂音给您带来困扰。已为您加急处理订单 SO20240501 的退款，1-3 个工作日原路退回，请您留意到账通知。

工单：{"type": "换货", "order_id": "SO20240502", "issue": "颜色发错", "priority": "中"}
回复：非常抱歉商品颜色发错。订单 SO20240502 的换货已登记，正确颜色商品将于 3 天内寄出，到时我会同步物流单号给您。

工单：{"type": "咨询", "order_id": null, "issue": "退货流程", "priority": "低"}
回复：您好，退货流程如下：在订单页点击"申请退货"→填写原因→客服审核→寄回商品→退款到账，一般 1-3 个工作日完成。

工单：{{ticket_info}}
回复：
```

### 使用示例
#### 输入
```
你是 SmartCS 客服话术生成模块。请根据工单信息生成一段专业、有同理心的回复话术。

要求：
- 先共情，再说明处理方案，最后给时间节点
- 不超过 100 字
- 语气专业温和，不使用"亲亲""宝宝"

示例：
工单：{"type": "退款", "order_id": "SO20240501", "issue": "耳机杂音", "priority": "高"}
回复：很抱歉耳机出现杂音给您带来困扰。已为您加急处理订单 SO20240501 的退款，1-3 个工作日原路退回，请您留意到账通知。

工单：{"type": "换货", "order_id": "SO20240502", "issue": "颜色发错", "priority": "中"}
回复：非常抱歉商品颜色发错。订单 SO20240502 的换货已登记，正确颜色商品将于 3 天内寄出，到时我会同步物流单号给您。

工单：{"type": "咨询", "order_id": null, "issue": "退货流程", "priority": "低"}
回复：您好，退货流程如下：在订单页点击"申请退货"→填写原因→客服审核→寄回商品→退款到账，一般 1-3 个工作日完成。

工单：{"type": "维修", "order_id": "SO20240510", "issue": "充电宝充不进电", "priority": "高"}
回复：
```

#### 预期输出
```
很抱歉充电宝出现充电问题给您带来不便。已为您加急登记订单 SO20240510 的维修申请，专员将在 1 小时内联系您确认处理方式，最迟今日给出方案。
```

### 调优建议
- 温度建议：0.5（需一点温度让话术自然，但不能跑偏）
- 示例覆盖退款/换货/咨询三种类型，结构统一为"共情+方案+时间"
- 生成模式核心：示例示范风格与结构，模型模仿并泛化到新工单
- 可用"禁止使用亲亲"等负面指令约束用语（此处因属安全约束，可用负面表述）

## 四大模式对比总结

| 模式 | 输入 → 输出 | 核心要点 | SmartCS 应用 | 温度 |
|------|------------|---------|-------------|------|
| 分类 | 文本 → 类别 | 每类至少 1 示例 | 工单分类 | 0 |
| 抽取 | 文本 → 结构化 | 明确字段+缺失处理 | 订单信息提取 | 0 |
| 转换 | A格式 → B格式 | 给目标 Schema | 消息转 JSON 工单 | 0 |
| 生成 | 描述 → 内容 | 示范风格与结构 | 回复话术生成 | 0.5 |

## 通用 Few-Shot 模板骨架

无论哪种模式，都可套用以下骨架：

```
[角色设定 + 任务说明]

[输出格式说明 / Schema]

示例：
输入：[示例1输入]
输出：[示例1输出]

输入：[示例2输入]
输出：[示例2输出]

输入：[示例3输入]
输出：[示例3输出]

输入：{{实际输入}}
输出：
```

**编写要点**：
1. 示例覆盖所有类别 / 字段缺失情况 / 边界案例
2. 示例格式完全统一
3. 相似示例放最后
4. 示例简短典型，避免冗长
5. 示例标注必须正确

## 总结

> 核心心法：**Few-Shot 四大模式覆盖了绝大多数业务场景**——分类、抽取、转换、生成。选对模式 + 选好示例，就能用最低成本让 LLM 听懂"业务语言"。
>
> 模式选择口诀：
> - 要分门别类 → 分类模式
> - 要拎出信息 → 抽取模式
> - 要换格式 → 转换模式
> - 要写内容 → 生成模式
