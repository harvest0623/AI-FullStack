# Day05 - 错误处理与重试

> 本节目标：工具调用会失败（异常/坏参数/未知函数）。关键设计是：**出错别崩**，
> 把错误当作 `tool` 结果喂回模型，让它能**重试、修正参数、或妥协**。

---

## 1. 错误从哪来

| 错误类型 | 示例 | 可恢复? |
|----------|------|--------|
| 参数校验失败 | 缺必填参数 | 是 → 模型补参数重试 |
| 函数内部异常 | 除零、网络失败 | 是 → 模型换参数/换工具 |
| 未知函数名 | 模型幻觉出不存在函数 | 是 → 反馈给模型 |
| 致命错误 | 框架层崩溃 | 否 → 应结束 |

---

## 2. 核心设计：把错误"喂回模型"

不要直接把异常抛给用户，而把它包成一条 `tool` 消息：

```
denominator=0 -> 函数抛 ValueError
  -> 框架捕获, 生成 tool 结果:  {content: "[error] 除数不能为 0"}
  -> 模型看到错误, 决定: 改用 b=2 再调一次
  -> 得到 5.0, 完成
```

框架的 `execute` 现在会捕获 `TypeError/ValueError/其他异常` 并包装成
`FunctionCallError(recoverable=True)`，循环主函数再把 `[error] ...` 喂回给模型。

---

## 3. 模型侧的"重试策略"

规则 planner 里写清楚：

```python
last = [m for m in messages if m["role"]=="tool"][-1]
if last["content"].startswith("[error]"):
    return ("call", [{"name":"divide", "args":{"a":10, "b":2}}])  # 修正重试
return ("text", f"最终: {last['content']}")
```

> 真实模型会"自己"做这件事——给足 `description` 和错误信息后，它一般会修正参数
> 再试。你的工作是**别把错误吞掉或崩溃**，而是把它规范地回传。

---

## 4. 未知函数的兜底

模型偶尔会幻觉出**不存在的函数**。框架检测到 `registry.has(name)==False` 就回一
条 `[error] 未知函数`，模型下次就会改选真实工具或直接回答，而不是硬闯。

## 6. 你要记住的三句话

1. 工具会错；**把错误喂回模型**，而不是崩溃或吞掉。
2. 框架负责捕获 + 包成 `[error]` 结果；模型负责重试/修正/妥协。
3. 未知函数要有兜底反馈，防止模型幻觉裸奔。
