# Day06 - 参数校验与类型

> 本节目标：在**函数执行之前**先校验参数，把缺参、类型不对的调用挡在门外，
> 而不是等函数内部报错。校验是"宁可早失败、别晚爆炸"的工程思维。

---

## 1. 为什么校验

模型传参**不总是可靠**：可能漏了必填、传错类型（把数字传成字符串、"二十"
当整数）。如果不校验直接执行：

- 函数 `a + b` 遇到 `"x"` → TypeError
- 函数期望 `integer` 收到 `1.5` → 结果错误但难察觉

**执行前校验**能给出清晰、可恢复的错误，让模型有机会修正重试。

---

## 2. 框架内置校验（本 Day 已增强）

`registry.execute()` 在执行前自动检查 `parameters`：

| 校验项 | 规则 |
|--------|------|
| 必填缺失 | `required` 里列出的参数没传 → 报错 |
| 类型 | `type=string` 需为 str；`number`/`integer` 需为数字；`integer` 不能是小数/布尔 |

```python
reg.execute("add", {"a": 1})        # 缺 b       -> 拦截
reg.execute("add", {"a": 1.5, "b": 3})  # integer 收到小数 -> 拦截
reg.execute("get_weather", {"city": 123})  # city 应为字符串 -> 拦截
```

---

## 3. 校验失败后怎么办

校验失败抛出 `FunctionCallError(recoverable=True)`，被循环捕获后作为
`[error]` 结果喂回模型。模型（planner）检测到错误就**修正参数重试**：

```python
if last["content"].startswith("[error]") and 还可重试:
    return ("call", [{"name":"add", "args":{"a":20, "b":7}}])  # 修正后重试
```

于是"二十 加 7"流程是：传错(`"二十"`) → 拦截 → 改传 `(20,7)` → 得 27。

---

## 4. 双保险

| 防线 | 时机 | 兜住什么 |
|------|------|----------|
| schema 校验 | 执行**前** | 缺参、类型、枚举 |
| 函数内部 try | 执行**时** | 业务异常（除零、网络） |

校验 + 函数自身防御一起用，最稳。

## 6. 你要记住的三句话

1. **执行前校验**，别等函数内部爆炸——早失败好过晚爆炸。
2. 校验两类：必填缺失 + 类型不符。
3. 校验失败反馈给模型，它能修正参数重试。
