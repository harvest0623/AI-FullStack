# Day08 - 并行工具调用

> 本节目标：模型在**同一次决策(single turn)**里发出多个独立的函数调用，框架一次
> 全部执行并把所有结果一起喂回。相比 Day07 的"多轮串行"，并行更高效——一次往返办多件事。

---

## 1. 串行 vs 并行

| | 串行(多轮) | 并行(本 Day) |
|--|------------|--------------|
| 形态 | 每轮一个 call | 一次决策返回 **多个 call**（列表） |
| 依赖 | 下一步可能依赖上一步结果 | 多个调用**互相独立** |
| 效率 | 慢（一调用一一往返） | 快（一次全部发出） |

> 前提是并行调用之间**彼此没有依赖**。有依赖的必须串行（Day07 那种）。

---

## 2. 一次决策返回多个 call

模型把 `tool_calls` 返回成一个**数组**：

```python
calls = [
    {"name": "get_weather", "args": {"city": "上海"}},
    {"name": "get_weather", "args": {"city": "北京"}},
    {"name": "get_weather", "args": {"city": "广州"}},
]
return ("call", calls)           # 并行发起
```

框架对同一个 `("call", [...])` 里的多个调用逐个执行，产物是多个 `role=tool`
结果，一起追加回历史。

---

## 3. 综合结果

一次性拿到多个 `tool` 结果后，模型（planner）把它们**综合**成最终回答：

```python
lines = [m["content"] for m in tool_msgs]
return ("text", "并行拿到: " + " | ".join(lines))
```

---

## 4. 并行 vs 并发的提示

- **并行调用**是"模型一次返回多个调用"——语义层面并行。
- 真要**并发执行**（多线程加速），可在执行层用线程池；本模块聚焦调用形态，
  执行仍是顺序的，结果一致。

## 6. 你要记住的三句话

1. 并行 = 一次决策返回**多个 call**，没有依赖就并行省时间。
2. 框架自动逐个执行并把结果一起喂回，模型综合作答。
3. 有依赖的任务不要并行，要串行（多轮）。
