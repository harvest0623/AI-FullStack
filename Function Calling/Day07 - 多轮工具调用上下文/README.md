# Day07 - 多轮工具调用上下文

> 本节目标：让多个工具调用"接力"成一段**有状态**的多步流程。核心是：每轮工具
> 结果都保留在对话历史里，后续模型决策可以参考前面拿到的中间结果，一步步推进。

---

## 1. 单轮 vs 多轮

| | 单轮 | 多轮(本 Day) |
|--|------|--------------|
| 调用数 | 模型一次决策发一次调用 | 多次调用串成流程 |
| 状态 | 每次独立 | 历史结果驱动下一步 |
| 典型 | 查天气 | 查菜单 → 下单 → 汇总 |

---

## 2. 上下文从哪来

框架的 `chat_with_tools` 维护 `conv`（对话历史）。每次工具执行后，`role=tool`
的结果都**追加**进去。模型（planner）通过查看"历史里已经调过哪些、得到什么"做决策：

```python
tool_msgs = [m for m in messages if m["role"] == "tool"]
if not any(m["name"] == "get_menu" for m in tool_msgs):
    return ("call", ...get_menu...)      # 第1步: 先查菜单
if not any(m["name"] == "place_order" for m in tool_msgs):
    return ("call", ...place_order...)   # 第2步: 有菜单后下单
return ("text", ...汇总)                 # 第3步: 都做完了, 汇总回答
```

这就把多步任务串成了"条件驱动的流程图"。

---

## 3. 为什么要"历史"

- **数据依赖**：下一步的参数/决策取决于上一步结果（先知道菜单价格才能下单）。
- **避免重复**：看历史"已调用过"，不会反复查菜单。
- **可解释**：整段历史就是执行轨迹，可审计、可回溯。

---

## 4. 真实模型的差别

真实 LLM 因为能"看"到整段包含 tool 结果的消息，天然会基于前面结果决定下一步；
你只需按「先发 tools → 收 tool_calls → 执行 → 追加结果 → 再发」循环做事，
上下文自动累积。

## 6. 你要记住的三句话

1. 多轮 = 多次工具调用串成流程，靠对话历史累积**上下文**。

3. 对话历史就是执行轨迹，可读可审计。
