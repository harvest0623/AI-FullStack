## 为什么需要嵌入与向量

传统关键词搜索靠"字面匹配"：搜"退款"找不到"我想把钱要回来"。语义检索靠**嵌入向量**把含义变成坐标，用**余弦相似度**找"意思相近"的内容。

| 场景 | 传统 | 嵌入向量 |
|------|------|---------|
| 匹配方式 | 字面 token | 语义坐标 |
| 同义词 | 匹配不到 | 自动相关 |
| 语法变化 | 易漏 | 语义不变即相近 |
| 用于 RAG | — | 检索来源材料 ★ |

Ollama 可跑嵌入模型（如 `nomic-embed-text`、`bge-m3`），`/api/embed` 一步出向量，**数据全程本地**。

---

## 核心概念

- **Embedding**：文本 → 浮点向量（如 384/768/1024 维），语义相近则向量方向相近。
- **余弦相似度**：两向量夹角的 cos 值，∈[-1,1]，越大越相似。
- **嵌入模型**：`nomic-embed-text`（轻量通用）、`bge-m3`（中英多语言）、`mxbai-embed-large`（大模型）。
- **文档切块**：长文本按段落/固定长度切块，逐块入库供检索。
- **入库**：把切块 `文本→向量` 存进向量库（VectorDB 板块）。
- **检索**：查询转向量，取 top-k 最相似的块。

## 每日内容详解

### 01 - 嵌入与相似度
展示"文本→向量"的由来，手写余弦相似度，对比关键词 vs 语义的匹配差异。

### 02 - 本地语义搜索
用一个 FAQ 库做 top-k 检索：查询转向量，与每条候选算相似度，按分排序返回。

### 03 - 文档切块与入库
把一篇长文档按段落/固定长度切块，批量生成向量，形成"检索池"。

### 04 - 嵌入驱动的检索
完整链路：切块 → 入库 → 查询 embed → 取最相似块 → 拼接回答，为 RAG 模块打底。

## 练习与挑战

1. **读一读向量**：打印某向量前 8 个维度的浮点值，感受"坐标"。
2. **换模型对比**：有环境时对比 `nomic-embed-text` 与 `bge-m3` 的检索效果。
3. **换切块策略**：固定长度 vs 按句子切块，看检索差异。
4. **自建问答库**：用你自己的 10 条 FAQ 跑通 `02` 的检索。
