## 一、DataIQ 项目目标与架构

> **目标**：员工用自然语言查询制度文档，得到带依据、准、快的回答；支持按部门/密级权限隔离；可观测、可评估、可增量更新。

```
src/
├── config.py        # 配置（模型/切块/检索参数）
├── loaders.py       # 数据加载
├── chunker.py       # 切块（递归/父子）
├── embedder.py      # 嵌入（可降级）
├── store.py         # 向量库封装（Chroma）
├── retriever.py     # 混合检索 + 重排
├── router.py        # 查询路由（按部门/类型）
├── generator.py     # 生成 + Prompt
├── cache.py         # 检索/生成缓存
├── evaluate.py      # 指标（Recall/忠实性）
└── api.py           # FastAPI 服务
```

分层原则：**每层只依赖下层、可单独替换、方便测试**。

## 三、完整查询链路

```
请求 ─▶ 路由(按部门/密级选过滤条件)
        ▼
查询改写（可选）─▶ 混合检索(BM25+向量, RRF融合) ─▶ 重排 ─▶ 取Top-3
                                                       ▼
                                            缓存命中？→是→返回
                                                       ↓ 否
                                           注入Prompt ─▶ LLM生成 ─▶ 记录观测 ─▶ 返回
```

任何一环都可用 Day10 指标验证，回归保护。

## 五、上线与运维要点（复盘）

- **依赖锁版本**：用 `requirements.txt`/`pyproject.toml` 锁定。
- **配置外置**：模型、切块、权重、缓存 TTL 放 config，不硬编码。
- **CI 评估**：每次改动跑评估集，指标不降才合入（Day10）。
- **可观测告警**：P95 延迟、错误率、成本、faithfulness 设阈值。
- **数据治理**：文档版本、权限、脱敏、审计日志。
- **蓝绿发布**：新索引构建好并验证后再切换，避免线上变更。

## 六、进阶方向（走出 RAG 之后）

| 方向 | 说明 | 何时升级 |
|------|------|---------|
| **Agentic RAG** | 用 Agent 自动规划检索/多工具/迭代反思 | 需要复杂多步推理的工具化 |
| **Graph RAG** | 用知识图谱增强实体关系检索 | 重实体/关系的场景（如医疗、法务） |
| **Multimodal RAG** | 图、表、音视频多模态检索 | 文档含大量图表/媒体 |
| **Fine-tuning + RAG** | 微调提升指令遵循，再叠加 RAG | 领域风格/专业术语 |
| **长上下文 + RAG** | 用超长上下文承载更多检索结果 | 上下文窗口富余、可容忍成本 |

> 这些将在后续独立板块（Agent 等）逐一展开。

## 关键知识点总结

1. **模块化分层**：数据/检索/生成/评估/api 各自解耦。

5. **进阶路线**：Agentic / Graph / 多模态 RAG。
