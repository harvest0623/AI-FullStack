# Day04 - 嵌入 Embedding 与向量化

> 切好块之后，要让计算机理解文本"像不像"，需要把文本转成**向量（Embedding）**。嵌入质量直接决定检索的语义准确性。今天我们吃透嵌入原理、模型选型与质量检验，并把它和「切块 + 向量库」串起来。

## 一、什么是嵌入（Embedding）

**嵌入 = 把一段文本映射成一个固定长度的数值向量**，使得**语义相近的文本在向量空间中距离更近**。

```
"报销住宿标准"      → [0.12, -0.33, 0.87, ...]  （512 维）
"年假可以累加吗"   → [-0.40, 0.21, 0.05, ...]
"出差住宿报销限额"  → [0.11, -0.30, 0.85, ...]  （与第一条更近）
```

检索即：把查询也转成向量，找库里与之"最近"的那些块。

---

## 二、相似度计算：余弦相似度

衡量两个向量"方向是否一致"最常用**余弦相似度**：

```
cos(A, B) = (A·B) / (||A|| × ||B||)
```

- 范围 [-1, 1]，越接近 1 越相似。
- 对**归一化向量**，余弦相似度直接用**向量点积**即可。
- 另有两种距离：欧氏距离、曼哈顿距离；向量库默认多为余弦或点积。

> 注意：不同嵌入模型的向量**不能互用**（A 模型向量与 B 模型向量不可比）。

## 三、嵌入模型选型

### 3.1 主流模型

| 模型 | 维度 | 多语言 | 成本 | 说明 |
|------|------|--------|------|------|
| `text-embedding-3-small` | 1536 | 好 | 低 | OpenAI 默认、性价比高 |
| `text-embedding-3-large` | 3072 | 好 | 中 | 精度更高 |
| `bge-m3` | 1024 | 优（中英） | 免费/本地 | 国产优秀开源 |
| `Cohere embed-v3` | 1024 | 中 | 中 | 带检索专用模式 |
| `mxbai-embed-large` | 1024 | 中 | 免费/本地 | 稀疏+稠密混合 |

### 3.2 选型要点

1. **语言**：中文场景选多语言模型（bge 系列 / OpenAI / text-embed-3）。
2. **维度与成本**：维度越高精度越高但存储、计算成本也越高。
3. **本地 vs API**：数据敏感选本地开源模型；追求便捷用 API。
4. **检索任务匹配**：用专为检索（Retrieval）训练的嵌入模型。

> 原则：**选一个"经 MTEB/中文基准 验证过检索能力"的模型**，比盲目加大维度更有意义。

## 四、查询-文档嵌入的一致性

简单检索时：**查询文本和文档块都用同一嵌入模型**，各自转向量后比较。

但实践中存在"查询场景 vs 文档场景"措辞差异（口语提问 vs 书面文档），可考虑：
- **Query Prompt 前缀**：很多检索嵌入模型为查询侧加了特定指令前缀（如 `bge` 的 `为这个句子生成表示以用于检索相关文章`）。
- **HyDE**：先让 LLM 生成一个"假设答案"再用其嵌入检索（Day07 详述）。

> 关键：**查询侧与文档侧用同一个模型**，且按模型规范处理 query/document 区分。

---

## 五、批量嵌入与缓存

生产中对大量文档嵌入时：
- **批量嵌入**（Batch Embedding）：一次请求塞多条文本，节省 API 往返、控制 token 上限。
- **嵌入缓存**：相同文本不重复计算，存到磁盘/内存，节省成本与时间（Day11 展开）。

```python
# LangChain 批量（内部自动分批）
from langchain_openai import OpenAIEmbeddings
emb = OpenAIEmbeddings(model="text-embedding-3-small")
vecs = emb.embed_documents(["文本1", "文本2", ...])   # 批量文档
qvec = emb.embed_query("我的问题")                     # 单一查询
```

> 注意 `embed_documents`（批量、可并行）与 `embed_query`（查询、可能带前缀）是**两套方法**，务必区分。

## 六、如何检验嵌入质量

没有量化的"好"都是感觉。用**相似问句对 / 不相关问句对**做简单 sanity check：

```
应相似（高相似度）：              应不相关（低相似度）：
"报销住宿上限" ↔ "出差住宿能报多少"   "报销住宿上限" ↔ "年假怎么申请"
```

- 如果"应相似"的相似度低 → 模型语义能力不足/语言不匹配。
- 换模型、换维度、加查询前缀后重测，看是否提升。

更严谨的用检索指标（Recall/MRR）在评估集上验证（Day10）。

## 关键知识点总结

1. **嵌入 = 语义→向量**，相近语义向量更近。
2. **余弦相似度**衡量两向量"方向一致性"，是检索打分基础。
3. **模型选型**看多语言 / 维度 / 成本 / 检索能力。
4. **查询与文档用同一模型**，注意 query/document 方法区分。
5. **质量要量化**：用相似对/指标检验，而非拍脑袋。
