# Day09 - 多文档与知识库架构设计

> 真实企业的 RAG 面对的是**多部门、多类型、海量文档**：财务制度、产品手册、合同、FAQ……简单地把所有文档塞进一个索引往往"又大又糊"。今天解决**多文档知识库的架构设计**：分索引、元数据路由、先摘要再检索、Agentic RAG 前瞻。

## 学习目标

完成本章后，你将能够：

- 在多文档场景下设计索引隔离与组织策略
- 用元数据过滤实现按文档/部门/类型检索
- 实现"先摘要、再检索"的 Agentic RAG 模式
- 理解多库路由与多工具 Router 的区别
- 处理多文档间的引用与冲突

---

## 一、多文档 RAG 的挑战

| 挑战 | 表现 |
|------|------|
| 检索量巨大 | 单个索引大而杂，相似度被稀释 |
| 主题混杂 | 一个查询可能命中多个无关主题 |
| 格式多样 | 制度/手册/表格/FAQ 结构差异大 |
| 权限隔离 | 不同部门/密级需隔离 |
| 内容冲突 | 多份文档说法不一致 |

**核心思路**：把"一个大而糊的索引"拆成"多个小而准的索引 + 路由"。

---

## 二、索引组织策略对比

| 策略 | 做法 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| 单一大索引 | 全部文档一个向量库 | 简单 | 大而稠、易串主题 | 小型/统一主题 |
| **按文档类型分索引** | 制度库/产品库/FAQ库 各自独立 | 检索聚焦、权限好隔离 | 需路由 | 中型、多类型 |
| **按租户/部门分索引** | 财务/人事/技术 各自独立 | 天然权限隔离 | 库多、管理成本 | 多部门/多租户 |
| 元数据单索引 | 一个大库 + metadata 过滤 | 简化运维、可精细化过滤 | 依赖 metadata 规范 | 需跨类型检索 |

> 实践常**组合**：单一大库 + 强元数据过滤（精度、性能、权限兼顾）+ 必要时物理分索引。

---

## 三、元数据路由（Metadata-based Routing）

即使不做物理隔离，也可用元数据精确指定检索范围：

```python
hits = vectorstore.similarity_search(q, k=3, filter={"doc_type": "制度", "dept": "财务部"})
```

优点：无需维护多个库；缺点是跨类型检索不方便。做得好坏取决于**入库时的元数据是否规范**（Day03 已强调）。

---

## 四、Agentic RAG：先摘要、再检索

是处理"大文档/跨文档问题"的经典模式，先定位"哪篇文档"再深入"哪一段"：

```
用户问题
  │
  ▼
① 文档索引检索：找最相关的几篇"文档摘要/向量"
  │
  ▼
② 仅就选中的文档，细化到块级检索
  │
  ▼
③ 生成
```

好处：先缩小范围（文档级）再精读（块级），避免大海捞针、降低成本。

---

## 五、多库 / 多工具路由（Router）

面对"物理分索引 + 可能的外部工具"，需一个 Router 统一调度：

```
             ┌─ 财务索引
问题 ──路由──┼─ 人事索引
             ├─ 产品手册
             └─ (外部) 计算器/天气等工具
```

两种实现（Day07 已讲）：
- **LLM Router**：让 LLM 判断该用哪个工具。
- **相似度 Router**：查询向量匹配各工具描述。

Router 是 RAG 走向 **Agent/工具化** 的桥梁，也是 Agentic RAG 的基础。

## 六、处理多文档冲突与引用

| 问题 | 对策 |
|------|------|
| 多文档都命中、内容矛盾 | 聚合时让 LLM 指出差异 + 依据来源；按"版本/密级/时效"偏好 |
| 引用混乱 | 保留 metadata（file_name/page）让回答可溯源 |
| 检索跨文档时上下文跳变 | 用父子切块 / 来源分组，保证同一文档的上下文连续 |

> 关键：让 LLM **看到"来源"** 并依此权衡，而非拉萨无从判断的矛盾上下文。

---

## 场景：DataIQ 的多文档架构

- **大库 + 强元数据**：单 Chroma 库，每块带 `doc_type/dept/level`。
- **Filter Router**：根据问题关键词/路由结果，加 `filter` 限定范围。
- **先摘要再检索**：对超长制度先建摘要索引，命中摘要后再读正文。
- **权限**：按 `level` + 用户角色过滤（公开/内部/保密）。

## 关键知识点总结

1. **多文档要"分而治之"**：分索引 或 强元数据过滤。
2. **元数据路由**：入库规范 + filter 是精度与权限的根基。
3. **先摘要再检索**：Agentic RAG 经典两步，省成本提精度。
4. **Router 调度**：多库/多工具统一入口，是 Agent 的跳板。
5. **冲突与引用**：保留来源 metadata，让 LLM 能权衡。
