# Day07 - 查询优化与查询路由

> 检索质量不只看"库端"，也看"查询端"：用户的口语化问题往往与文档书面语差距很大。**查询优化**在发检索前改造问题（改写、多查询、分解、HyDE），**查询路由**则把不同类型的问题分发到正确的数据源。今天打通"查询端"的所有关键技巧。

## 学习目标

完成本章后，你将能够：

- 理解查询质量为何影响检索质量
- 用查询改写缩小查询与文档的语义鸿沟
- 用多查询（Multi-Query）展开问题多角度召回
- 用查询分解拆解复杂问题
- 掌握 HyDE 的原理与落地
- 用查询路由把问题分发到正确的索引/工具

---

## 一、查询质量 → 检索质量

检索 = 查询向量 与 文档向量的比较。**查询越接近文档的表达方式，越容易命中。**

```
用户：伙计，出差回来咋报销捏？       ← 口语化，难以命中
改写：DATA告报销流程是怎样的         ← 书面化，易于命中
```

因此"查询端"是一大优化空间，目标是让查询更接近文档的"自然语言 + 信息结构"。

---

## 二、查询改写（Query Rewriting）

**思路**：用 LLM 把用户输入"翻译"成更适合检索的形式。

```python
def rewrite(query: str) -> str:
    prompt = f"把下面的问题改写成适合在金融企业制度库中检索的正式文献查询，输出改写后的查询：\n{query}"
    return llm(prompt)
```

适用：口语化、含糊、含人称代词的查询。

---

## 三、多查询（Multi-Query）

**思路**：一个问题的不同说法召回不同的块，**生成 N 个 POD 视角的查询分别检索，再合并去重**。

```python
def multi_query(query: str, n=3) -> list[str]:
    prompt = f"请从多个不同角度，为下面的问题生成{n}个检索子查询，每行一个：\n{query}"
    queries = llm(prompt).strip().splitlines()
    # 对每个子查询检索，合并候选，再交给重排
```

- 好处：覆盖更多相关表达，提升召回。
- 成本：检索次数 ×N，需与收益对齐。

---

## 四、查询分解（Query Decomposition）

**思路**：把"复合问题"拆成多个子问题，分别检索再汇总。

> 例："年假能转给下一年化吗？和病假冲突吗？"

应拆成：① 年假能否结转；② 年假与病假是否冲突。分别检索、分别回答、汇总。

```python
def decompose(query: str) -> list[str]:
    prompt = "把下面的复合问题拆成若干个独立的子问题，每行一个，都尽量是能被单独检索的：\n" + query
    return llm(prompt).strip().splitlines()
```

适用：含"和/并且/同时"等多主题查询。

---

## 五、HyDE（Hypothetical Document Embedding）

**核心洞察**：查询向量与文档向量常不在同一"分布"。**HyDE 先让 LLM 根据问题"写一个假设答案"（更接近文档的形态），再用这个假设答案的向量去检索**。

```python
hypo = llm(f"为下面问题写一个假设性的简洁作答，尽量使用原文术语：\n{query}")
hits = vectorstore.similarity_search(hypo)   # 用假设答案检索，而非原始问题
```

- 优点：解决"查询/文档语义鸿沟"，常显著提升零样本检索。
- 代价：一次额外 LLM 调用。

---

## 六、查询路由（Query Routing）

**思路**：面对多库/多工具，先判断"这个问题该去哪个数据源"，再定向检索。

两类路由方式：

| 方式 | 原理 | 例子 |
|------|------|------|
| **LLM 路由** | 让 LLM 选工具 | "问报销→财务库；问年假→HR 库" |
| **相似度路由** | 用查询向量匹配各库代表 prompt | 预置各库描述向量，选最贴近的 |

```python
# LLM 路由示意
tools_desc = {"财务库": "报销、发票、预算...", "HR库": "年假、请假、绩效..."}
prompt = f"根据下面的问题，选最合适的库({list(tools_desc)})，只输出库名：\n{query}"
chosen = llm(prompt)
result = retrieval_from_index(query, chosen_index)
```

> 路由让每个子库更"小而准"，也天然支撑多租户/分离。

## 七、优化组合策略

实际中常组合使用：

```
用户查询
  │
  ├── ① 改写/多查询/分解  （查询端增强）
  │
  ▼
  ├── ② 路由到正确索引  （数据源编排）
  │
  ▼
  ├── ③ 检索（Day05）+ 重排（Day06）
  │
  ▼
  └── ④ 生成
```

**原则**：先从"最影响问题的那个环节"入手，用评估（Day10）确认收益，再叠加。

## 场景：DataIQ 的查询端优化

DataIQ 员工问题口语化、且涉及多个子库。方案：
- 先做**LLM 路由**：区分"查制度 / 查产品 / 查个人"；
- 对含糊问题做**查询改写**；
- 对事实型精确问题考虑 **HyDE**；
- 对复合问题做**分解**。

配合 Day10 指标，保留"有量化提升"的优化，砍掉"无收益只加成本"的。

## 关键知识点总结

1. **查询端与文档端越像，越容易检索命中**。
2. **改写**：把口语化问题"翻译"成文档书面语。
3. **多查询**：多角度展开，增加召回、合并去重。
4. **分解**：拆解复合问题，分而检索。
5. **HyDE**：用"假设答案"而非原问题检索，缓解语义鸿沟。
6. **路由**：按意图分发到正确的库/工具。
