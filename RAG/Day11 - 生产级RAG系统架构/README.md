## 一、生产 RAG 架构全景

```
┌────────────── 离线（索引管道）─────────────┐     ┌────────── 在线（检索服务）──────────┐
│ 数据源 → 清洗 → 切块 → 嵌入 → 写入向量库    │     │ 请求 → 路由 → 检索 → 重排 → 生成      │
│              （可异步/批量）               │     │        （低延迟、高并发）             │
└────────────────────────────────────────────┘     └──────────────────────────────────────┘
```

核心原则：**索引与检索解耦**。离线管道负责数据进库（可慢可批量），在线服务只做查询（要快）。

---

## 二、索引管道与检索服务解耦

| 层 | 职责 | 特点 |
|----|------|------|
| 离线管道 (Ingest) | 抓取/解析/切块/嵌入/入库 | 慢、批量、可重跑、失败可重试 |
| 在线服务 (Serve) | 查询→检索→重排→生成 | 快、并发、有 SLA |

好处：
- 数据准备不影响查询体验；
- 管道出错可重放，不影响线上；
- 各自独立扩缩容。

---

## 三、缓存策略（降本增效）

RAG 每查询都调用嵌入 + LLM，成本高。缓存是性价比最高的优化：

| 缓存 | 缓存什么 | 命中场景 |
|------|---------|---------|
| **检索缓存** | 查询→检索结果 | 同一问题反复问 |
| **生成缓存** | 查询→最终回答 | 完全相同的请求 |
| **嵌入缓存** | 文本→向量 | 文档重复出现 |

```python
# 简单生成缓存（生产用 Redis/内存带 TTL）
CACHE = {}
def cached_answer(q):
    if q in CACHE: return CACHE[q]
    ans = rag_pipeline(q)
    CACHE[q] = ans
    return ans
```

> 注意：缓存要考虑更新失效（文档变了要清缓存）。

## 四、增量更新与数据同步

知识库会变化，需同步索引：

- **新增**：新文档切块嵌入后 `add` 进库。
- **删除**：按 `source_id`/`doc_id` 删除对应向量。
- **修改**：删旧 + 加新，或按版本号替换。
- **触发**：接口触发、定时轮询、事件监听（如文档上传成功）。

```python
# Chroma 按源删除（示意）
collection.delete(where={"source_id": doc_id})
# 再插入新版本块
```

## 五、权限与数据安全

RAG 上生产必须先解决"谁可以看什么"：

| 手段 | 说明 |
|------|------|
| **元数据过滤** | 按 `dept/level` 在前置过滤，用户只能检到自己有权限的 |
| **多租户隔离** | 每租户独立 collection/namespace |
| **Prompt 注入防护** | 约束 Prompt "只回答知识库内容"，防止被引导泄露 |
| **敏感数据治理** | 敏感字段脱敏、审计日志 |
| **限流与鉴权** | API Key/JWT + 调用限额 |

> 权限要在**检索层就过滤**（拿不到的压根不进上下文），而非只在生成层嘴上约束。

## 六、可观测性与监控

不知道线上好不好 = 没有线上。接入可观测：

| 工具 | 作用 |
|------|------|
| **LangSmith** | LangChain 应用追踪、评估 |
| **Langfuse** | 追踪 + 人工反馈 + 成本分析 |
| **Arize Phoenix** | 开源 trace + 评估 |
| **OpenTelemetry** | 通用链路追踪 |

需监控的指标：
- **质量**：retrieval recall、faithfulness（Day10）
- **性能**：端到端延迟 P50/P95、检索延迟
- **成本**：每查询 token、LLM/嵌入费用
- **容量**：并发、错误率、缓存命中率

---

## 七、错误处理与降级

- LLM/向量库调用失败 → 重试（指数退避）+ 优雅降级。
- 检索无结果 → 明确告知"知识库暂无相关内容"，而非编造。
- 超时保护 → 设置整体超时，避免拖垮服务。

---

## 八、FastAPI 封装生产服务

```
GET  /health        健康检查
POST /query         单轮问答 {"question":...}
POST /chat          多轮 {"messages":[...]}
POST /ingest        触发文档入库（后台任务）
```

启动时预加载索引，请求时复用（避免每个请求重建）。

## 场景：DataIQ 生产化

- **解耦**：`ingest` 管道脚本 + `api` FastAPI 服务。
- **缓存**：检索+生成缓存（Redis-like）。
- **数据同步**：文档上传接口触发增量入库。
- **权限**：每用户按 `dept/level` 过滤检索。
- **观测**：接入 Langfuse，记录每次 query 的检索块、score、token、延迟。
- **监控**：P95 延迟、召回率、成本告警。

## 关键知识点总结

1. **索引与检索解耦**，各自扩缩容。
2. **缓存**（检索/生成/嵌入）是降本第一手段。
