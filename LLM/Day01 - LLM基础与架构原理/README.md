# Day01 - LLM 基础与架构原理

LLM（大语言模型）是当前 AI 浪潮的技术基石。从 ChatGPT 引爆全球到各类 Agent 应用层出不穷，背后都离不开一个核心：基于 Transformer 架构的大规模语言模型。要用好 LLM、做出稳定的 AI 应用，仅仅会调 API 是不够的——你必须理解它的架构原理、训练方式与能力边界。本章带你从 NLP 发展史出发，深入 Transformer 架构，理清 GPT/BERT 的差异，掌握 LLM 训练三阶段，建立对大模型原理的系统性认知，为后续 API 调用、Token 管理、Embedding 等工程实践打下理论基础。

## 一、LLM 定义

**LLM（Large Language Model，大语言模型）** 是基于海量文本数据训练的大规模神经网络模型，通过预测「下一个 Token」的方式学习语言的统计规律与世界知识，从而具备对话、推理、写作、代码生成等多种能力。

LLM 的三个「大」：
- **数据大**：训练语料达万亿级 Token（书籍、网页、代码、论文）
- **参数大**：从几十亿到数千亿参数（7B / 70B / 405B / 671B）
- **算力大**：训练消耗数千张 GPU、数月时间

代表性模型：GPT-4o、Claude 3.5、Gemini、Llama 3.1、Qwen 2.5、DeepSeek-V3。

---

## 二、NLP 发展史

理解 LLM 的最好方式，是看自然语言处理（NLP）是如何一步步走到今天的：

| 阶段 | 时期 | 代表技术 | 特点与局限 |
| --- | --- | --- | --- |
| 规则系统 | 1950s-1980s | 专家系统、正则匹配 | 人工编写规则，覆盖面窄，无法泛化 |
| 统计学习 | 1990s-2000s | N-gram、HMM、CRF、TF-IDF | 基于概率统计，特征工程繁重 |
| 深度学习 | 2010s | Word2Vec、RNN、LSTM、CNN | 自动学习表示，但 RNN 串行计算慢、长依赖弱 |
| Transformer | 2017 | Self-Attention | 并行计算、长距离依赖强，开启新范式 |
| 大模型 | 2020s 至今 | GPT-4 / Claude / Llama | 涌现推理、少样本学习能力，通用能力强 |

**关键转折点**：2017 年 Google 发表《Attention Is All You Need》，提出 Transformer 架构，完全抛弃 RNN 的串行结构，用 Self-Attention 并行建模序列关系。这是 LLM 时代的真正起点。

## 三、Transformer 架构详解（重点）

Transformer 是 LLM 的「引擎」，几乎所有现代大模型都基于它。下面逐个拆解其核心组件。

### 架构总览

```
输入嵌入 + 位置编码
      │
      ▼
┌─────────────────────────┐
│  多头注意力 Multi-Head   │ ◄── 残差连接 + LayerNorm
├─────────────────────────┤
│  前馈网络 FFN            │ ◄── 残差连接 + LayerNorm
└─────────────────────────┘
      │  (重复 N 层)
      ▼
   线性层 + Softmax → 输出概率
```

每个 Encoder/Decoder Block 由「注意力子层 + FFN 子层」组成，每个子层都包裹 **残差连接（Residual）+ 层归一化（LayerNorm）**。

### 3.1 自注意力机制 Self-Attention

Self-Attention 让序列中每个词都能「看到」其他所有词，并决定关注谁。这是 Transformer 的灵魂。

**核心三矩阵：**
- **Q（Query 查询）**：当前位置在「寻找」什么信息
- **K（Key 键）**：其他位置能「提供」什么信息
- **V（Value 值）**：其他位置实际携带的内容

计算公式：

```
Attention(Q, K, V) = softmax(QK^T / √d_k) V
```

**步骤拆解：**
1. 输入 X 分别乘以三个权重矩阵 `W_Q / W_K / W_V`，得到 Q / K / V
2. `QK^T` 计算每两个词的点积相似度（注意力分数）
3. 除以 `√d_k` 缩放，防止点积过大导致 softmax 梯度消失
4. softmax 归一化为权重（每行加和为 1）
5. 权重对 V 加权求和，得到融合了上下文的输出

**为什么除以 √d_k？** 当维度 d_k 较大时，点积结果方差大，softmax 会进入饱和区（梯度趋近 0）。缩放后使分布更平滑，训练更稳定。

### 3.2 多头注意力 Multi-Head Attention

一组 Q/K/V 只能学到一种关注模式。多头注意力将向量拆成 `h` 个子空间，每个头独立做 Self-Attention，最后拼接 + 线性变换：

```
MultiHead(Q,K,V) = Concat(head_1, ..., head_h) W_O
head_i = Attention(Q W_Q^i, K W_K^i, V W_V^i)
```

**意义**：不同头可以专注不同关系——有的捕捉语法（主谓）、有的捕捉指代（"他"指代谁）、有的捕捉长距离依赖。就像多个「视角」并行观察同一句话。

### 3.3 位置编码 Positional Encoding

Self-Attention 本身是「置换不变」的——打乱输入顺序结果不变。为了让模型感知 Token 顺序，需要注入位置信息。

**正弦/余弦编码（原论文）：**
```
PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
```
位置编码与词向量相加。不同位置拥有不同编码模式，且相对位置可由线性函数表达。

**RoPE 旋转位置编码（现代主流）：** Llama、Qwen 等模型采用 RoPE，通过对 Q/K 做位置相关的旋转变换，使注意力分数只依赖相对位置，外推性更好（支持长上下文扩展）。

### 3.4 前馈网络 FFN

每个位置独立经过一个两层全连接网络：

```
FFN(x) = max(0, x W_1 + b_1) W_2 + b_2
```

- 第一层升维（通常 4×d_model），第二层降回 d_model
- 中间用激活函数（ReLU / GELU / SwiGLU）
- **作用**：注意力负责「信息聚合」，FFN 负责「信息变换/记忆」。LLM 的大部分参数集中在 FFN

> 现代 LLM（如 Llama）多采用 **SwiGLU** 激活，比 ReLU 效果更好但参数略多。

### 3.5 Layer Normalization 层归一化

对每个样本的特征维度做归一化（均值为 0、方差为 1），再缩放平移：

```
LayerNorm(x) = γ · (x - μ) / √(σ² + ε) + β
```

**作用**：稳定每层输入分布，加速训练收敛，缓解梯度问题。现代 LLM 多用 **RMSNorm**（LayerNorm 的简化版，去掉均值中心化，更快）。

### 3.6 残差连接 Residual Connection

每个子层的输出为 `LayerNorm(x + Sublayer(x))`，即把输入直接加到子层输出上。

**作用**：
- 解决深层网络的梯度消失问题（梯度可经捷径直接回传）
- 允许堆叠更多层（GPT-3 达 96 层）
- 让网络「至少不比浅层差」

### 三种归一化位置对比

| 方式 | 公式 | 特点 |
| --- | --- | --- |
| Post-LN（原论文） | `LN(x + Sublayer(x))` | 训练不稳，需 warmup |
| Pre-LN（主流） | `x + LN(Sublayer(x))` | 训练稳定，主流选择 |
| Sandwich-LN | `LN(x + LN(Sublayer(x)))` | 部分新模型采用 |

## 四、GPT vs BERT 架构对比

Transformer 最初是 Encoder-Decoder 结构，后续衍生出三大流派：

| 维度 | GPT（Decoder-Only） | BERT（Encoder-Only） | T5（Encoder-Decoder） |
| --- | --- | --- | --- |
| 架构 | 仅解码器 | 仅编码器 | 编码器 + 解码器 |
| 注意力 | 单向（因果掩码） | 双向 | 编码双向/解码单向 |
| 训练目标 | 预测下一个 Token | 随机 Mask 预测 | Seq2Seq 文本到文本 |
| 输入方向 | 从左到右 | 看到全部上下文 | 编码端看全部 |
| 擅长任务 | 生成（对话/写作/代码） | 理解（分类/抽取/检索） | 翻译/摘要等 seq2seq |
| 代表模型 | GPT 系列、Llama、Qwen | BERT、RoBERTa | T5、BART |
| 工程生态 | 当前 LLM 主流（生成+理解通吃） | 多用于 Embedding/分类 | 逐渐被 Decoder-Only 取代 |

**关键结论**：今天的「大模型」几乎都是 **Decoder-Only**（GPT 路线）。原因是：自回归生成天然统一了所有任务（一切皆「预测下一个 Token」），且在足够规模下，Decoder-Only 的理解能力也能追平甚至超越 BERT。

## 五、LLM 训练三阶段

一个对话型 LLM 的诞生要经历三个阶段，从「会说话」到「听指令」再到「懂人意」：

### 阶段一：预训练 Pre-training

- **数据**：万亿级无标注文本（网页、书籍、代码）
- **目标**：自回归预测下一个 Token
- **结果**：学会语言规律与世界知识，但不会遵循指令（你问它问题，它可能继续续写问题）
- **成本**：占总成本 90%+，需数千 GPU 跑数月

```
输入: "中国的首都是"
目标: "北京"
```

### 阶段二：指令微调 SFT（Supervised Fine-Tuning）

- **数据**：人工编写的「指令-回答」对（数万到数十万条）
- **目标**：让模型学会「按指令回答」
- **结果**：从「续写机器」变成「对话助手」

```
指令: "请用一句话解释什么是黑洞。"
回答: "黑洞是引力极强、连光都无法逃脱的天体。"
```

### 阶段三：对齐人类偏好（RLHF / DPO）

SFT 后模型会回答了，但回答质量参差、可能有偏见或有害。需要进一步对齐人类偏好。

**RLHF（Reinforcement Learning from Human Feedback）：**
1. 训练奖励模型（Reward Model）：用人类标注的「回答 A 好于 B」数据训练一个打分模型
2. 用 PPO 等强化学习算法优化 LLM，使其输出奖励模型高分回答
3. 缺点：流程复杂、训练不稳定、工程难度高

**DPO（Direct Preference Optimization，直接偏好优化）：**
- 直接用偏好数据（A 好于 B）优化 LLM，省去显式奖励模型
- 流程更简单、训练更稳定，逐渐成为主流

```
偏好数据:
  提示: "如何学习编程？"
  回答A(偏好): "建议从 Python 入门，边学边做项目..."
  回答B(拒绝): "自己随便看看就行。"
```

### 三阶段速查

| 阶段 | 数据 | 目标 | 产出 |
| --- | --- | --- | --- |
| 预训练 | 海量无标注文本 | 预测下一 Token | 基座模型（Base） |
| SFT | 指令-回答对 | 遵循指令 | 对话模型（Chat） |
| RLHF/DPO | 人类偏好数据 | 对齐人类价值观 | 安全有用的助手 |

## 六、模型参数与能力关系

LLM 的能力受三大因素影响：

| 因素 | 说明 | 量级 |
| --- | --- | --- |
| 参数量 | 模型可学习的权重数量 | 7B / 13B / 70B / 405B / 671B |
| 训练数据量 | 训练语料的 Token 数 | 1T - 15T Tokens |
| 计算量（FLOPs） | 训练消耗的浮点运算量 | 10^22 - 10^26 FLOPs |

**经验规律**：参数量↑、数据量↑、算力↑，模型能力↑。但三者需匹配，单纯加大参数而数据不足会过拟合。

---

## 七、Scaling Laws

OpenAI 提出的缩放定律揭示了 LLM 的一个惊人规律：**损失（Loss）与模型大小、数据量、计算量呈幂律关系**。

```
L(N) = (N_c / N)^α        # 损失随参数量 N 下降
L(D) = (D_c / D)^β        # 损失随数据量 D 下降
L(C) = (C_c / C)^γ        # 损失随计算量 C 下降
```

**核心结论**：
- 模型性能可被「参数×数据×算力」三者预测
- 投入更多资源，损失可预测地下降（在当前范式下未饱和）
- 这一定律直接推动了「越做越大」的军备竞赛

> DeepMind 的 Chinchilla 定律进一步指出：在固定算力下，**数据量与参数量应按比例增长**（约 20 Tokens / 参数）。过去很多模型「参数大、数据不足」是次优的。

## 八、涌现能力 Emergent Abilities

当模型规模超过某个阈值后，会**突然出现**小模型没有的能力，称为「涌现能力」。

典型涌现能力：
- **少样本学习（In-context Learning）**：给几个示例就能学会新任务
- **思维链推理（Chain-of-Thought）**：分步推理解决复杂问题
- **代码生成与执行**：写代码、调试、跨文件理解
- **指令遵循**：理解复杂多步指令

**争议**：部分研究认为「涌现」可能是评估指标的非线性造成的假象（用连续指标测量时能力是平滑增长的）。但无论如何，大模型在复杂任务上的表现远超小模型是不争的事实。

## 九、上下文窗口 Context Window

**上下文窗口** 是模型一次能处理的最大 Token 数，决定了「记忆容量」。

| 模型 | 上下文窗口 |
| --- | --- |
| 早期 GPT-3 | 2K |
| GPT-4 Turbo | 128K |
| Claude 3.5 | 200K |
| Gemini 1.5 Pro | 1M-2M |
| Llama 3.1 | 128K |

**注意**：上下文越长 → 越贵（Token 多）→ 越慢（注意力 O(n²)）→ 且存在「Lost in the Middle」问题（中间信息易被忽略）。所以「能用短上下文就别用长上下文」是工程原则。

## 十、主流开源模型生态

闭源模型（GPT-4/Claude/Gemini）能力领先，但开源模型生态在快速追赶，且可本地部署、可微调、数据可控。

| 模型系列 | 出品方 | 架构 | 特点 | 适用场景 |
| --- | --- | --- | --- | --- |
| **Llama 3 / 3.1** | Meta | Dense | 最流行开源系列，生态最丰富 | 通用基座，可微调 |
| **Qwen 2 / 2.5** | 阿里 | Dense | 中文能力最强之一 | 中文应用、多模态 |
| **Mistral / Mixtral** | Mistral AI（欧洲） | Dense / MoE | MoE 架构性价比高 | 欧洲合规、高效部署 |
| **DeepSeek-V3 / R1** | 深度求索 | MoE | 推理能力强、价格极低 | 推理任务、成本敏感 |
| **GLM-4** | 智谱 | Dense | 中文友好，Agent 能力 | 智能体应用 |
| **Phi-3** | 微软 | Dense | 小而精，3.8B 性能强 | 端侧/移动部署 |

**MoE（Mixture of Experts）**：将 FFN 拆成多个「专家」，每次只激活其中几个。如 Mixtral 8x7B 总参数 46.7B 但每次只激活 13B，兼顾大容量与低推理成本。DeepSeek-V3、GPT-4 据传均采用 MoE。

## 关键知识点总结

### 1. Transformer 架构速查

| 组件 | 公式/作用 | 一句话记忆 |
| --- | --- | --- |
| Self-Attention | `softmax(QK^T/√d_k)V` | 每个词看其他所有词 |
| Multi-Head | 多头并行 + 拼接 | 多视角观察 |
| 位置编码 | sin/cos 或 RoPE | 给注意力加顺序感 |
| FFN | 两层线性 + 激活 | 信息变换与记忆 |
| LayerNorm | 特征维归一化 | 稳定训练 |
| 残差连接 | `x + Sublayer(x)` | 抗梯度消失 |

| 维度 | GPT | BERT |

| 架构 | Decoder-Only | Encoder-Only |

| 训练目标 | 预测下一 Token | Mask 预测 |
| 擅长 | 生成 | 理解 |
| 现状 | LLM 主流 | 多用于 Embedding/分类 |

### 3. 训练三阶段速查

| 阶段 | 数据 | 目标 |
| --- | --- | --- |
| 预训练 | 无标注海量文本 | 学语言+知识 |
| SFT | 指令-回答对 | 学会遵循指令 |

### 练习 1：手算注意力权重

给定两个 2 维向量 `Q1 = [1, 0]`、`K1 = [1, 0]`、`K2 = [0, 1]`，`√d_k = √2`，手算 `softmax(Q1·K1/√2, Q1·K2/√2)` 的结果，验证 Q1 对 K1 的注意力更高。然后在 `01_transformer_concepts.py` 中修改输入验证你的计算。

1. 总字符数与总 Token 数
2. 中文部分与英文部分的 Token/字符比
