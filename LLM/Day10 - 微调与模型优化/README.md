# Day10 - 微调与模型优化

微调（Fine-tuning）让 LLM 在预训练能力之上，进一步适配特定领域、风格和任务，是超越通用 Prompt 工程的高级优化手段。当 Prompt 调优和 RAG 已无法满足定制化需求时，微调能让模型"内化"领域知识与行为规范。本章系统讲解微调方法分类、LoRA 原理、数据准备、训练流程与效果评估，并结合 LLaMA-Factory 等工具完成 AISearch 智能问答服务的领域适配。

## 学习目标

- 理解微调的动机，以及与 Prompt Engineering、RAG 的选型差异
- 掌握全量微调与 PEFT（LoRA/QLoRA）的区别与适用场景
- 深入理解 LoRA 低秩分解原理
- 掌握微调数据准备规范（指令格式/对话格式/质量标准）
- 熟悉完整微调流程：数据准备 → 训练 → 评估 → 部署
- 了解 LLaMA-Factory、Unsloth、Axolotl 等主流微调工具
- 能够评估微调效果并检测灾难性遗忘

## 理论知识讲解

### 一、微调概念与动机

**什么是微调：** 在已预训练好的大模型基础上，用特定领域或任务的数据继续训练，使模型在该方向上表现更好。

**为什么微调：**

| 动机 | 说明 | 举例 |
| --- | --- | --- |
| 领域适配 | 让通用模型掌握领域术语与知识 | 医疗诊断、法律条文解读 |
| 风格定制 | 让模型输出符合品牌语气 | 客服话术、品牌文案 |
| 能力增强 | 在特定任务上达到更高精度 | 代码生成、表格抽取 |
| 成本优化 | 微调小模型替代调用大模型 | 7B 微调替代 GPT-4 |

**微调 vs Prompt Engineering vs RAG 对比：**

| 维度 | Prompt Engineering | RAG | 微调 |
| --- | --- | --- | --- |
| 实现成本 | 极低 | 中 | 高 |
| 数据需求 | 无 | 文档库 | 标注数据 500-5000 条 |
| 更新频率 | 随时 | 随时更新文档 | 训练周期长 |
| 知识更新 | 依赖模型自身 | 实时 | 需重新训练 |
| 风格定制 | 弱 | 弱 | 强 |
| 适用场景 | 快速验证 | 知识密集型 | 固定任务/风格 |

### 二、微调方法分类

**1. 全量微调 Full Fine-tuning：**

- 更新模型所有参数
- 效果最好，但显存需求极大（需存梯度与优化器状态）
- 7B 模型全量微调约需 80GB+ 显存

**2. 参数高效微调 PEFT（Parameter-Efficient Fine-Tuning）：**

只更新少量参数，大幅降低显存与计算成本。

| 方法 | 原理 | 显存（7B） | 效果 |
| --- | --- | --- | --- |
| LoRA | 注入低秩矩阵 B、A，只训练它们 | ~16 GB | 接近全量 |
| QLoRA | 量化基座 + LoRA，4bit 基座 | ~6 GB | 接近 LoRA |
| Prefix Tuning | 在输入前加可训练前缀向量 | ~8 GB | 略低于 LoRA |
| P-Tuning | 类似 Prefix Tuning，优化 prompt embedding | ~8 GB | 略低于 LoRA |

**全量 vs PEFT 对比：**

| 维度 | 全量微调 | PEFT (LoRA) |
| --- | --- | --- |
| 可训练参数量 | 100% | <1% |
| 显存需求 | 极高 | 低 |
| 训练速度 | 慢 | 快 |
| 效果 | 最优 | 接近全量（差距 <2%） |
| 适用场景 | 资源充足、追求极致 | 消费级 GPU、快速迭代 |

### 三、LoRA 原理详解

LoRA（Low-Rank Adaptation）的核心思想：模型权重的更新矩阵是低秩的，可以用两个小矩阵的乘积近似。

**数学表达：**

```
原始权重：W₀ ∈ R^(d×k)    （冻结，不训练）
更新量：  ΔW = B × A
其中：    B ∈ R^(d×r), A ∈ R^(r×k), r << min(d, k)
最终：    W = W₀ + B × A
```

**关键点：**

- 只训练 B 和 A，原始 W₀ 完全冻结
- rank r 通常取 8-64，r 越大表达能力越强但参数越多
- 推理时可将 B×A 合并回 W₀，无额外推理开销

**优势：**

- 参数量减少 99%+
- 效果接近全量微调
- 可为同一基座训练多个 LoRA 适配器，按需切换

```
LoRA 参数量示例（7B 模型，r=8）：
全量参数：7,000,000,000
LoRA 参数：约 10,000,000（0.14%）
```

### 四、微调数据准备

**指令格式（Alpaca 风格）：**

```json
{
  "instruction": "将以下句子翻译成英文",
  "input": "今天天气真好",
  "output": "The weather is really nice today."
}
```

**对话格式（ShareGPT 风格）：**

```json
{
  "messages": [
    {"role": "system", "content": "你是一个翻译助手"},
    {"role": "user", "content": "今天天气真好"},
    {"role": "assistant", "content": "The weather is really nice today."}
  ]
}
```

**数据质量原则：**

- **数据质量 > 数据数量**：1000 条高质量数据 > 10000 条低质量数据
- **数据量建议**：500-5000 条（取决于任务复杂度）
- **数据多样性**：覆盖不同场景、风格、难度
- **数据清洗**：去重、去噪、格式统一、去除有害内容

**数据量与任务复杂度参考：**

| 任务类型 | 建议数据量 | 备注 |
| --- | --- | --- |
| 简单分类/格式化 | 500-1000 | 任务单一 |
| 领域问答 | 2000-5000 | 需覆盖领域知识 |
| 风格定制 | 1000-2000 | 强调一致性 |
| 复杂推理 | 5000+ | 需要更多示例 |

### 五、微调流程

```
1. 数据准备    收集 → 清洗 → 格式化
      ↓
2. 格式转换    转为训练框架要求的格式（JSONL/ShareGPT）
      ↓
3. 训练配置    学习率 / epochs / batch_size / LoRA rank
      ↓
4. 训练        GPU 训练（监控 loss 与显存）
      ↓
5. 评估        在测试集上评估效果 + 检测灾难性遗忘
      ↓
6. 部署        合并 LoRA 权重 / 导出 GGUF / Ollama 部署
```

**关键训练参数：**

| 参数 | 推荐值 | 说明 |
| --- | --- | --- |
| learning_rate | 1e-4 ~ 3e-4 | LoRA 学习率，比全量大 |
| epochs | 2-5 | 过多易过拟合 |
| batch_size | 4-16 | 受显存限制 |
| LoRA rank (r) | 8-64 | 8 通用，32 较强 |
| LoRA alpha | 2×rank | 缩放系数，通常为 rank 的 2 倍 |
| LoRA dropout | 0.05-0.1 | 防过拟合 |

### 七、微调效果评估

| 评估方法 | 说明 |
| --- | --- |
| 保留集评估 | 训练时留出 10-20% 数据作测试集 |
| 对比评估 | 微调前 vs 微调后，同一测试集对比 |
| 人工评估 | 领域专家判断输出质量 |
| 灾难性遗忘检测 | 用通用能力测试集（如 MMLU 子集）验证通用能力是否下降 |

### 八、微调 vs Few-Shot vs RAG 选型

| 场景 | 推荐方案 |
| --- | --- |
| 快速验证、少量数据、任务变化频繁 | Few-Shot |
| 知识频繁更新、大量文档检索 | RAG |
| 固定任务、风格定制、追求极致性能 | 微调 |
| 需要特定领域知识 + 实时更新 | RAG + 微调（组合） |

### 九、微调的坑与注意事项

- **数据质量是关键**：垃圾进垃圾出，低质量数据会"教坏"模型
- **过拟合**：epochs 过多导致模型只记住训练数据，泛化能力下降
- **灾难性遗忘**：微调后通用能力下降，需用通用测试集检测
- **学习率选择**：太大学坏模型，太小学不动；LoRA 建议 1e-4 ~ 3e-4
- **评估要全面**：不只看任务指标，还要看通用能力是否受损

### 2. LoRA 原理图解

```
         冻结 W₀ (d×k)
         ┌─────────────┐
输入 x ─→│     W₀      │─→ W₀x
         └─────────────┘
                +        ─→ W₀x + BAx = (W₀+BA)x
         ┌───┐   ┌───┐
         │ B │ × │ A │   (只训练 B 和 A，r << d,k)
         │d×r│   │r×k│
         └───┘   └───┘
```
