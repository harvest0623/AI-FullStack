# Day11 - LLM 评估与监控

没有评估就没有优化，没有监控就没有稳定。LLM 输出的开放性与主观性，使得传统软件的评估方法难以直接套用。系统化的评估与监控体系，是 LLM 应用从"能跑"到"持续好用"的关键保障。本章讲解 LLM 评估指标体系、评估基准、LLM-as-a-Judge 方法论、自动化评估管道，以及生产环境的延迟/成本/质量/安全监控，为 AISearch 智能问答服务构建可持续运营的评估监控能力。

## 学习目标

- 理解 LLM 评估的独特挑战与应对策略
- 掌握准确性/相关性/流畅性/安全性/忠实性等多维评估指标
- 了解 MMLU、HumanEval、GSM8K 等主流评估基准
- 掌握 LLM-as-a-Judge 方法的原理、Prompt 设计与局限
- 能够构建评估数据集并搭建自动化评估管道
- 掌握生产环境监控指标体系与告警规则设计
- 理解概念漂移/数据漂移/模型漂移的检测方法

## 理论知识讲解

### 一、LLM 评估的挑战

| 挑战 | 说明 |
| --- | --- |
| 开放性 | LLM 输出没有唯一正确答案，同一问题可有多种合理回答 |
| 主观性 | 不同人对同一输出评价不同，标注一致性难保证 |
| 多维度 | 需同时考量准确性、相关性、安全性、风格、格式等 |
| 成本 | 人工评估贵且慢，难以高频执行 |

### 二、评估指标体系

| 指标 | 定义 | 适用场景 |
| --- | --- | --- |
| 准确性 Accuracy | 输出是否事实正确 | 知识问答、事实核查 |
| 相关性 Relevance | 是否切题回答了用户问题 | 所有问答场景 |
| 流畅性 Fluency | 语言是否通顺自然 | 文本生成 |
| 安全性 Safety | 是否遵守安全约束 | 所有生产场景 |
| 忠实性 Faithfulness | 是否忠于给定上下文（不编造） | RAG 场景 |
| 格式合规 Format Compliance | 是否符合输出格式要求 | 结构化输出 |
| 延迟 Latency | 响应时间 | 在线服务 |

### 三、评估基准

| 基准 | 评估能力 | 规模 | 评估方式 |
| --- | --- | --- | --- |
| MMLU | 57 学科多选问答 | 14万题 | 客观匹配 |
| HumanEval | 代码生成 | 164 题 | 单元测试 |
| GSM8K | 小学数学推理 | 8.5K 题 | 精确匹配 |
| MT-Bench | 多轮对话能力 | 80 题 | GPT-4 评分 |
| AlpacaEval | 指令遵循 | 805 题 | GPT-4 评分 |
| Chatbot Arena | 综合能力 | 持续累积 | 人类盲评 Elo |

### 四、LLM-as-a-Judge

**原理：** 用强 LLM（如 GPT-4）作为裁判，评估其他 LLM 的输出质量。

**优势：**

- 自动化、可规模化
- 成本远低于人工评估
- 可持续运行

**评估 Prompt 设计：**

```
你是一个专业的评估专家。请根据以下标准评估回答质量。

【评估标准】
- 准确性（1-5分）：回答是否事实正确
- 相关性（1-5分）：是否切题
- 流畅性（1-5分）：语言是否通顺

【用户问题】{question}
【模型回答】{answer}
【参考答案】{reference}

请输出 JSON：{"accuracy": 分数, "relevance": 分数, "fluency": 分数, "reason": "评语"}
```

**局限：**

- **偏见**：评估模型自身存在偏见
- **位置偏见**：倾向选择第一个或最后一个答案
- **长度偏见**：倾向选择更长的回答
- **自我偏好**：倾向偏好与自身风格相似的输出

**应对策略：** 多评估模型交叉验证、随机打乱顺序、控制输出长度。

### 五、人工评估方法论

| 方法 | 说明 |
| --- | --- |
| 盲评 | 标注者不知道输出来自哪个模型 |
| 多标注者 | 多人标注同一项，减少主观偏差 |
| 评分量表 | 1-5 分制，每个分值有明确描述 |
| 一致性检查 | 同一标注者重复标注，计算 IAA |

**Inter-annotator Agreement (IAA)：** 衡量不同标注者的一致性，常用 Cohen's Kappa，>0.6 为可接受。

### 六、评估数据集构建

| 要素 | 建议 |
| --- | --- |
| 来源 | 真实用户对话 / 人工构造 / 合成数据 |
| 标注 | 人工标注期望输出 |
| 分层 | 简单/中等/困难/边缘案例 |
| 维护 | 持续更新、记录失败案例 |
| 规模 | 50-200 条即可有效评估 |

### 七、自动化评估管道

```
输入测试集 → 批量调用被评估模型 → 收集输出
      ↓
LLM-as-Judge 评分 → 生成评估报告 → 趋势追踪
```

- **定时执行**：每日/每周自动运行
- **结果可视化**：趋势图、对比图、失败案例列表

### 八、生产环境监控

| 监控维度 | 关键指标 |
| --- | --- |
| 延迟 | P50 / P95 / P99 响应时间 |
| 成本 | 日/周/月 Token 消耗与费用 |
| 质量 | 用户反馈、LLM-as-Judge 抽检 |
| 安全 | 有害内容检测、Prompt 注入检测 |
| 可用性 | API 错误率、服务状态 |

**告警规则示例：**

| 告警 | 条件 | 级别 |
| --- | --- | --- |
| 延迟突增 | P95 > 5s 持续 5 分钟 | 警告 |
| 成本异常 | 日消耗 > 预算 120% | 严重 |
| 质量下降 | 抽检得分 < 3.5 持续 1 天 | 警告 |
| 安全事件 | 检测到有害内容 | 严重 |
| 服务不可用 | 错误率 > 10% 持续 2 分钟 | 严重 |

### 九、用户反馈收集

| 类型 | 信号 |
| --- | --- |
| 显式反馈 | 点赞/点踩、评分、文字反馈 |
| 隐式反馈 | 重试率、复制率、对话长度、跳出率 |

### 十、漂移检测

| 漂移类型 | 定义 | 检测方法 |
| --- | --- | --- |
| 概念漂移 Concept Drift | 用户意图分布变化 | 意图分类分布统计检验 |
| 数据漂移 Data Drift | 输入特征分布变化 | 输入长度/主题分布对比 |
| 模型漂移 Model Drift | 模型更新导致行为变化 | 更新前后行为对比 |

## 关键知识点总结

### 1. 评估指标速查

| 指标 | 计算方式 | 适用 |
| --- | --- | --- |
| 精确匹配 | answer == expected | 事实问答 |
| 包含匹配 | expected in answer | 开放问答 |
| BLEU | n-gram 重叠 | 翻译/生成 |
| ROUGE | 召回率 | 摘要 |
| 格式合规 | 正则/Schema | 结构化输出 |

### 2. 评估基准对比

| 基准 | 类型 | 自动化 | 适用模型 |
| --- | --- | --- | --- |
| MMLU | 客观 | 全自动 | 通用模型 |
| HumanEval | 代码 | 全自动 | 代码模型 |
| MT-Bench | 主观 | GPT-4 | 对话模型 |
| Chatbot Arena | 主观 | 人工 | 对话模型 |

### 3. LLM-as-Judge 优缺点

| 优点 | 缺点 |
| --- | --- |
| 自动化、低成本 | 存在偏见 |
| 可规模化 | 长度/位置偏见 |
| 多维度评分 | 自我偏好 |
| 可持续运行 | 强模型依赖 |

### 4. 监控指标速查

| 维度 | P50 | P95 | P99 |
| --- | --- | --- | --- |
| 延迟 | <2s | <5s | <10s |
| 成本 | 日预算 | 周预算 | 月预算 |

### 5. 告警规则示例

| 规则 | 阈值 | 动作 |
| --- | --- | --- |
| 延迟突增 | P95 > 5s @5min | 通知运维 |
| 成本超限 | 日消耗 > 120% 预算 | 限流 |
| 质量下降 | 抽检 < 3.5 @1d | 通知算法 |
| 安全事件 | 有害内容 | 立即处置 |

### 6. 漂移检测方法

| 漂移 | 检测方法 | 频率 |
| --- | --- | --- |
| 概念漂移 | 意图分布卡方检验 | 每周 |
| 数据漂移 | 输入长度/主题分布 | 每日 |
| 模型漂移 | 更新前后对比 | 每次更新 |

## 实战练习

### 练习一：构建 AISearch 评估数据集

为 AISearch 智能问答服务构建 100 条评估数据集，按难度分层（简单 40 / 中等 40 / 困难 20），人工标注期望输出，使用 `EvalMetrics` 计算准确率与格式合规率。

### 练习二：搭建 LLM-as-Judge 评估管道

使用 `LLMJudge` 与 `EvalPipeline`，对 AISearch 服务的输出进行自动化评估，对比 GPT-4o-mini 与本地 7B 模型在准确性、相关性、流畅性上的得分，生成评估报告。

### 练习三：设计生产监控仪表盘

使用 `LLMMonitor` 采集一周的生产数据，配置告警规则（延迟/成本/质量/安全），生成监控报告，识别需要优化的指标。
