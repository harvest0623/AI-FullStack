# Day09 - 综合实战与最佳实践

> 收官实战：组装一个"能查天气 + 算数 + 记账"的多工具 Agent，并整理工具描述规范、参数校验与安全、失败降级、上线自检清单。

---

## 1. 综合案例：一个"一个会外务的小助手"

目标：用户输入自然语言，Agent 自主决定用天气 / 计算 / 记账三类工具完成。

```
工具集：
  get_weather(city)          → 查天气
  calculate(expr)            → 计算表达式
  add_expense(item, amount)  → 记一笔账（带数据）
```

一个有代表性的流程：

```
用户："查下北京天气，顺便记一笔咖啡30元的账"
① calculate? 不需要；调用 get_weather(北京)
② 调用 add_expense(coffee, 30)
③ 都完成 → 汇总作答
```

多处依赖 Day06 的循环 + Day08 的 ToolRegistry + Day04 的安全执行。

---

## 2. 工具描述写作规范

| 要点 | 建议 |
|------|------|
| 名称 | 稳定、语义化，动词开头（get/add/update…） |
| description | 写清"目的、参数含义、何时用"，给取值示例 |
| 参数 schema | 类型准确、必填明确、用 enum 限定取值范围 |
| 职责单一 | 一个工具只做一件事，避免大而杂 |
| 副作用 | 有副作用的工具描述里点明（如"会写入/改变xxx"） |

---

## 3. 参数校验与安全

- 执行前：必填字段、类型校验（Day04-03 的 validate）
- 执行中：异常统一转错误结果（Day06-02）
- 权限：危险操作（改库/转账）→ 需用户确认或 done 控制
- 不要信任模型给的参数 100%——始终在应用侧二次校验

---

## 4. 失败降级

- 工具失败 → 回填错误 → 模型可重试或换方案
- 无输入参数时可选默认（如城市默认北京），但要明确
- 超时/无响应 → 终止本轮，给用户兜底话术

---

## 5. 上线自检清单

- [ ] 每个工具：name 稳定 + description 写清目的/参数/何时用
- [ ] 参数类型与必填都用 JSON Schema 明确约束
- [ ] 执行前有参数校验；执行有异常兜底
- [ ] 危险工具（有副作用）已控制权限/需确认
- [ ] 循环有最大迭代保护，避免死循环
- [ ] 大结果已截断/摘要，控制上下文
- [ ] 流式场景正确按 index 拼接 tool_calls
- [ ] 在真实模型端点跑通闭环，换 key 也能用（无硬编码）
- [ ] 有日志，便于排查是哪一次调用失败

---

## 6. 本节小结

- 综合案例：多工具 + 循环 + 注册中心，组成能干活的小助手
- 规范了工具描述、参数校验、安全与降级
- 一张可落地的上线自检清单
- ToolCalling 是 Agent / MCP 的能力底座，掌握它就掌握了"模型动手"的关键
