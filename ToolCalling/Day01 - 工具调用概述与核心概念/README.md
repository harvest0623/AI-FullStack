# Day01 - 工具调用概述与核心概念

> 认识工具调用的本质：模型"只提议、不执行"，执行由应用完成。掌握一次工具调用的生命周期与典型场景，为后续所有章节打地基。

---

## 1. 工具调用是什么

**工具调用（Tool / Function Calling）** 是大语言模型的能力之一：模型在生成时，可以**识别出"这里应该调用某个外部函数"**，并**结构化地输出调用指令**（调用哪个工具、传什么参数）。

关键：**模型不会真正执行**它。它只是"提议"，真正的执行永远是应用代码。

```
对话："北京天气如何？"

模型内部："需要调用 get_weather(city='北京')"
         ↓ 结构化输出
模型返回：
  tool_calls → [{ name: "get_weather", arguments: { city: "北京" } }]

应用拿到后，自己调用 get_weather，再把结果回填给模型。
```

---

## 2. "只提议不执行"：为什么这么设计

- **安全**：执行权在应用手里，应用可校验、可授权、可审计
- **灵活**：同一工具可被不同模型/应用复用
- **解耦**：模型（决策）+ 执行器（动作）清晰分离
- **可控**：结果回填后可让模型基于真实结果继续作答

> 记忆：**模型是"总指挥"，应用是"执行大队"，工具的后果由应用负责。**

---

## 3. 一次工具调用的生命周期

完整一次调用通常分 4 步：

```
 ① 定义并传入工具
    应用把工具描述成 JSON（tools）
 ② 模型决策
    模型判断需要调用 → 返回 tool_calls
 ③ 应用执行
    应用解析参数 → 执行对应函数 → 拿到结果
 ④ 回填与作答
    结果以"角色=工具"消息发回 → 模型基于结果生成最终答复
```

> 当一次不能满足时，会反复 ②→③→④，形成"工具调用循环"（Day06 详讲）。

---

## 4. 与普通文本补全的区别

| 维度 | 普通补全 | 工具调用 |
|------|---------|---------|
| 输出 | 纯文本 | 可能含结构化 tool_calls |
| 触发 | 无条件 | 模型判断"需要外部能力"时 |
| 目的 | 生成内容 | 请求外部动作 + 获取真实数据 |
| 后续 | 结束 | 应用执行并回填，还可继续 |

---

## 5. 典型场景

- **实时查询**：天气、新闻、股票、数据库
- **执行操作**：发消息、写文件、下单、改配置
- **获取上下文**：读文档、查日志、搜百科
- **多步任务**：订机票（查→选→订）、研究（搜多轮）
- **工具编排**：作为 Agent 的能力底座

---

## 6. 本节小结

- 工具调用的本质：**模型提议、应用执行、结果回填**
- 生命周期四步：**定义工具 → 模型决策 → 应用执行 → 回填作答**
- 与文本补全不同：可能输出结构化 tool_calls，并引向外部执行
- 是 Agent、RAG 扩能力、多步任务的基础
