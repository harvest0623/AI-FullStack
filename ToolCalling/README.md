## 板块定位

**工具调用（Tool / Function Calling）** 是让大语言模型（LLM）在对话框中**识别出需要调用外部函数/工具**，并**结构化地输出调用参数**的能力。模型本身"不会执行"，但能告诉应用"该调用哪个工具、传入什么参数"；具体执行由应用完成，结果再回传给模型。它是 Agent 能"动手"的基石。

**与 AI-FullStack 其他板块的关系**：
- **LLM** 板块解决"模型的生成与理解"；本板块解决"模型如何决策并发出工具调用指令"
- **MCP** 解决"工具如何以统一协议暴露/接入"（协议层）；本板块聚焦"模型侧的调用机制"（能力层）
- **Agent / LangChain** 解决"如何编排、规划、记忆"（编排层）；本板块是其底层依赖
- 三者层层递进：ToolCalling（会调）→ MCP（被调接入）→ Agent（组织调用）

**学习目标**：完成本板块后，你应能：
- 讲清工具调用的本质：模型输出"工具调用意图"，而非执行
- 理解 Function Calling 的原理与主流 API 形态（tools/ tool_calls）
- 用 JSON Schema 规范、精确地定义工具
- 实现单工具与多工具（并行）调用
- 搭建工具调用循环（Agent 循环的雏形），正确处理错误与重试
- 把工具结果注入模型上下文，处理流式工具调用
- 将工具调用接入 LangChain / 自建 Agent
- 掌握工具调用的最佳实践与常见坑

**设计原则**：
- 知识点梳理为主，每天独立成章，含理论 + 可执行 Python 讲解/演示脚本
- **代码优先兼容离线运行**：用"模拟模型"复现工具调用的决策与循环逻辑，无需真实 API key 也能看懂；对于真实 API 形态给出对照示例
- 紧扣 Tool Calling 本身，逐层深入，最后落到与框架/Agent 结合与生产实践

## 为什么需要 Tool Calling

| 对比项 | 仅文本生成 | 加入工具调用 |
|--------|-----------|-------------|
| 查询实时数据 | 模型不知道、易编造 | 模型决定查实况，返回真实结果 ★ |
| 执行操作 | 只能"描述"不能"做" | 可调用写文件/发请求/操作库 |
| 准确性 | 依赖训练数据，易过时 | 对接外部真实系统 ★ |
| 可控性 | 黑盒生成 | 工具定义约束了能力边界 |
| 可扩展 | 换模型才变 | 增删工具即可扩能力 ★ |

一句话：**工具调用让模型从"会说"走向"会做"，并且把外部真实状态接进对话。**

## 每日内容详表

### Day01 - 工具调用概述与核心概念
- **核心**：工具调用是什么、模型"只提议不执行"的本质、与普通文本补全的区别、生命周期总览（示意→执行→回填）、常见场景
- **代码**：`01_what_is_tool_calling.py`（概念与本质）/`02_lifecycle.py`（一次调用的生命周期）/`03_scenarios.py`（典型场景）/`toolcall_check.py`（环境检测）/`README.md`
- **重点**：本质（提议而非执行）、生命周期

### Day02 - Function Calling 原理与 API 形态
- **核心**：模型如何"感知工具"、输出工具调用意图、主流 API（OpenAI tools/tool_calls、Anthropic、原生 tool calling）、tool_calls 的返回结构、为何要 JSON
- **代码**：`01_how_model_decides.py`（决策原理）/`02_api_shapes.py`（API 返回形态）/`03_tool_calls_struct.py`（tool_calls 结构解析）/`README.md`
- **重点**：tool_calls 结构、不同 API 的形态差异

### Day03 - 工具定义与 JSON Schema
- **核心**：如何把 Python/函数描述成模型能懂的 JSON、JSON Schema（type/properties/required/enum/description）、让模型能准确填参的描述技巧、从函数签名生成 schema
- **代码**：`01_schema_basics.py`（JSON Schema 基础）/`02_description_matters.py`（描述如何影响准确度）/`03_signature_to_schema.py`（从函数生成 schema）/`README.md`
- **重点**：JSON Schema、description 的作用

### Day04 - 单工具调用实现
- **核心**：完整实现一个工具调用：定义工具→发请求带 tools→模型返回 tool_calls→应用执行→回填→模型作答。用模拟模型跑通闭环
- **代码**：`01_single_call.py`（离线演示闭环）/`02_real_shape.py`（真实 API 形态）/`03_parse_arguments.py`（安全解析参数）/`README.md`
- **重点**：完整闭环、参数解析与校验

### Day05 - 多工具调用与并行
- **核心**：一个请求触发多个工具调用、并行工具调用（parallel_tool_calls）、分别执行并回填多个结果、处理依赖与顺序
- **代码**：`01_multi_tool.py`（多工具循环）/`02_parallel.py`（并行调用）/`03_dependencies.py`（有依赖的顺序处理）/`README.md`
- **重点**：多结果回填、并行与依赖

### Day06 - 工具调用循环与错误处理
- **核心**：把工具调用放进循环（Agent 雏形）、终止条件、错误处理（非法参数/执行失败/超时）、重试与兜底、防止死循环（最大迭代数）
- **代码**：`01_tool_loop.py`（工具调用循环）/`02_error_handling.py`（错误场景）/`03_max_iterations.py`（防死循环）/`README.md`
- **重点**：循环控制、错误处理、防死循环

### Day07 - 结果注入与流式调用
- **核心**：把工具返回结果注入上下文（content/工具角色）、大体积结果怎么塞、流式输出时的工具调用（stream tool_calls增量）、首 token 决策
- **代码**：`01_result_injection.py`（结果注入）/`02_stream_partial.py`（流式增量解析）/`03_truncation.py`（结果截断与策略）/`README.md`
- **重点**：结果注入、流式工具调用

### Day08 - 与 LangChain / Agent 的结合
- **核心**：LangChain 的 bind_tools / ToolNode 概念、把工具调用桥接到 Agent 循环、自建最小 Agent 复用 Day06 思路、封装 tools 的统一抽象
- **代码**：`01_langchain_bridge.py`（LangChain 思路）/`02_mini_agent.py`（自建 Agent）/`03_tool_abstraction.py`（统一工具抽象）/`README.md`
- **重点**：接入框架、自建 Agent

### Day09 - 综合实战与最佳实践
- **核心**：组装一个"能查天气+算数+记账"的多工具应用、工具描述的写作规范、参数校验与安全、失败降级、上线自检清单、总结与后续路径
- **代码**：`app.dart`（综合应用讲解）/`01_best_practice.py`（最佳实践）/`02_production_check.py`（上线清单）/`README.md`
- **重点**：综合实战、最佳实践

## 知识点速查

### 核心概念速查

| 概念 | 说明 |
|------|------|
| Tool / Function | 模型可感知并决定调用的外部能力 |
| Tool Calling | 模型输出"调用哪个工具+参数"的机制 |
| tool_calls | 模型返回的结构化调用请求 |
| tools 参数 | 请求里传给模型的工具清单 |
| JSON Schema | 描述工具参数结构的标准格式 |
| 工具角色 | 回填工具结果的 message.role（tool） |

### 调用流程速查

| 步骤 | 参与方 | 说明 |
|------|--------|------|
| 定义工具 | 应用 | 转成 JSON Schema 并写入 tools |
| 模型决策 | 模型 | 输出 tool_calls（带 id/name/arguments） |
| 执行工具 | 应用 | 按参数执行，拿到结果 |
| 回填结果 | 应用 | 以 tool 角色消息发回模型 |
| 生成答复 | 模型 | 基于结果产出最终回答 |

### 关键机制速查

| 项 | 说明 |
|----|------|
| 并行调用 | 一次请求多 tool_calls，独立执行 |
| 工具循环 | 反复"决策→执行→回填"直至无工具调用 |
| 防死循环 | 设最大迭代数，达到即停止 |
| 流式工具调用 | 增量拼接 tool_calls，最后统一执行 |
| 结果截断 | 超大结果压缩后再回填上下文 |
