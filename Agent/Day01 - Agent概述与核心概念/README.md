## 二、什么是 Agent

### 2.1 定义

> **Agent = 以 LLM 为决策核心，通过感知环境、调用工具、管理记忆、自主规划，循环执行直到达成目标的系统。**

三个关键词：

1. **决策核心是 LLM**：不是硬编码的 if-else，而是模型在每一步"决定下一步做什么"
2. **能行动**：不止会说，还能调工具（查询、计算、写文件、发请求）
3. **有目标**：给的是一个任务/目标，而非一个单轮问题

### 2.2 直观对比

| 输入 | Chatbot | Agent |
|------|---------|-------|
| "上周销量多少？" | 直接回答（可能靠训练记忆，易过时/幻觉） | 调用数据库工具查真实数据再回答 |
| "帮我分析上周销量并写份周报" | "好的，请提供数据……" | 查库 → 计算 → 生成报告 → 存文件 → 回复路径 |
| "查不到怎么办？" | 报错/道歉 | 换个查询条件重试，或向用户澄清 |

**本质差异**：Chatbot 的输出是**文本**；Agent 的输出可以是**世界上真实发生的变化**（一次查询、一封邮件、一份文件）。

### 2.3 Agent vs Workflow

这是最容易混淆的一对：

| 维度 | Workflow | Agent |
|------|----------|-------|
| 谁决定流程 | **开发者**预先编排好节点与顺序 | **LLM** 在运行时动态决定下一步 |
| 路径 | 固定（A→B→C） | 动态（A→?→?，视中间结果而定） |
| 可预测性 | 高，易测试 | 低，需要护栏与评估 |
| 适用 | 步骤确定的任务（报销审批流） | 路径开放的任务（"把这个问题调查清楚"） |

> **经验法则**：能用 Workflow 解决就别上 Agent——确定性优先。Agent 是为了**无法预先穷举路径**的任务而生的。

## 三、Agent 四大组成

```
              ┌────────────────────┐
              │      LLM 大脑       │
              │  （推理与决策）      │
              └────────┬───────────┘
        ┌──────────┬──┴───────┬──────────┐
        ▼          ▼          ▼          ▼
   ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
   │ 工具    │ │ 记忆    │ │ 规划    │ │ 护栏    │
   │ Tools  │ │ Memory │ │ Plan   │ │ Guard  │
   └────────┘ └────────┘ └────────┘ └────────┘
```

| 组件 | 职责 | 关键问题 |
|------|------|---------|
| **LLM 大脑** | 每步的推理与决策 | 用什么模型？怎么给指令？ |
| **工具 Tools** | 行动能力（感知+改变世界） | 有哪些工具？怎么描述才能被正确选用？ |
| **记忆 Memory** | 跨步骤、跨会话的状态 | 记什么？怎么裁剪？怎么检索？ |
| **规划 Planning** | 目标分解与路径设计 | 先规划还是边走边看？ |

- **工具**：没有工具的 Agent 只是 Chatbot。工具质量决定能力上限。
- **记忆**：上下文窗口有限，长任务必须依赖外部记忆。
- **规划**：区分"反应式"（走一步看一步）与"规划式"（先出计划再执行）。
- **护栏**：生产必需（Day09 详讲），先埋个概念。

## 四、Agent 核心循环（预览）

所有 Agent 都收敛于同一个循环（Day02 徒手实现）：

```
        ┌─────────────────────────┐
        │ 1. 感知：收集输入与观察    │
        └───────────┬─────────────┘
                    ▼
        ┌─────────────────────────┐
        │ 2. 思考：LLM 推理下一步    │
        └───────────┬─────────────┘
                    ▼
        ┌─────────────────────────┐
        │ 3. 行动：执行工具调用      │
        └───────────┬─────────────┘
                    ▼
        ┌─────────────────────────┐
        │ 4. 观察：拿到结果         │
        └───────────┬─────────────┘
                    ▼
            达成目标？───否──→ 回到 1
                    │是
                    ▼
                输出最终答案
```

**轨迹（Trajectory）**：一次运行中所有 (思考, 行动, 观察) 的序列。它是调试、评估、回放 Agent 的核心数据结构。

## 五、自主性等级（L0-L4）

给业务引入 Agent 前先定级——自主性越高，效率越高，风险也越大：

| 等级 | 名称 | 特征 | 例子 |
|------|------|------|------|
| L0 | 反射式 | 规则触发，无推理 | 关键词自动回复 |
| L1 | 辅助式 | Agent 建议，人执行 | 周报草稿人审后发 |
| L2 | 半自治 | 低风险自动执行，高风险需审批 | 内部查询自动，删数据要审批 |
| L3 | 受限自治 | 目标内全自主，边界明确 | 限定数据源的研究任务 |
| L4 | 全自治 | 长期目标，自我纠偏 | 长期运行的运维值守 Agent |

> **工程建议**：从 L1/L2 起步，靠评估与护栏逐步升到 L3；L4 需要极强的观测与回滚能力。

## 六、主流设计范式概览

| 范式 | 核心思想 | 何时用 |
|------|---------|--------|
| **ReAct** | 边思考边行动，走一步看一步 | 路径不确定、需快速反馈 |
| **Plan-and-Execute** | 先出完整计划，再逐步执行 | 任务可分解、步骤较多 |
| **Reflection** | 执行后自我复盘，修正再试 | 质量敏感（写作/代码） |
| **Multi-Agent** | 多角色分工协作 | 单上下文装不下 / 需专业分工 |

本板块主线：**先吃透 ReAct（Day02-03），再加记忆规划（Day04-06），最后上多 Agent（Day08）**。

## 十、小结

**Agent = LLM + 工具 + 记忆 + 规划，在循环中自主走向目标。**

- 它与 Chatbot 的本质差异：**能改变世界，而不只是生成文本**
- 它与 Workflow 的本质差异：**路径由模型在运行时决定**
- 引入前先定级：**自主性与风险成正比**

**今日金句**：Agent 不是更强的 Chatbot，而是会做事的系统；工具给它双手，记忆给它经验，规划给它路线，护栏给它缰绳。
