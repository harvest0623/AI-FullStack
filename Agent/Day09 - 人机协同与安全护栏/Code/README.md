# Day09 代码说明

所有脚本均**离线可运行**（无需 LLM API Key），智能判断用规则模拟。

## 运行方式

```bash
cd "Agent/Day09 - 人机协同与安全护栏/Code"

python 01_approval_gate.py     # 审批门
python 02_interrupt_resume.py  # 中断与恢复
python 03_clarify.py           # 澄清
python 04_guardrails.py        # 三层安全护栏
```

## 文件说明

| 文件 | 内容 | 关键概念 |
|------|------|---------|
| `01_approval_gate.py` | 工具风险分级、审批请求卡片、批准/拒绝/修改三种响应、拒绝后切换替代方案 | HITL、风险评估 |
| `02_interrupt_resume.py` | 状态持久化、WAITING_HUMAN 中断、断点续跑（不重跑已完成步骤）、超时降级策略 | 状态管理、Interrupt/Resume |
| `03_clarify.py` | 关键参数缺失检测、打包提问给选项和默认值、澄清结果写入记忆避免重复提问 | 交互设计、澄清记忆化 |
| `04_guardrails.py` | 输入护栏（注入检测）、行为护栏（白名单/路径校验/频率/预算熔断）、输出护栏（脱敏/权限过滤）、误拦率与漏拦率评估 | 三层防护、指标权衡 |

## 观察要点

**01_approval_gate.py**
- `read_file` 低风险免审直接执行；`send_email` 中风险、`delete_file`/`transfer_money` 高风险必须审批
- 转账被"修改后批准"：10000 元改为先转 100 元验证
- 删除被拒后自动切换为"归档"替代方案

**02_interrupt_resume.py**
- 第一轮在第 3 步（下单）中断，前 2 步的结果已持久化
- 恢复后从第 3 步继续，`搜索供应商`只执行 1 次（验证断点续跑）
- `check_timeout` 演示超时后的降级策略

**03_clarify.py**
- 第一次请求缺日期和姓名 → 打包提问（一条消息问全）
- 舱位/时间段有默认值 → 不问，只声明
- 第二次请求 → 姓名从记忆读取，不再追问

**04_guardrails.py**
- 注入攻击（"忽略之前的指令..."）被输入护栏拦截
- `/etc/passwd` 路径越界、金额超限被行为护栏拦截
- 输出中手机号/身份证/卡号自动脱敏
- 游客/用户/管理员看到不同字段（权限过滤）
- 评估脚本统计误拦率与漏拦率，体会护栏松紧权衡
